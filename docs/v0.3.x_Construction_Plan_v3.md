# FCEUX11 v0.3.x 构建方案

> **适用基线**：v0.2.30 架构冻结点（Rust 试验性重构结束，进入 C/C++ 优化期）
> **目标平台**：Windows 11 22H2+（独占）
> **工具链**：MSVC 2022 19.36 (VS 17.6) + vcpkg + Qt 6.8 LTS
> **发布日期**：2026-06-08
> **文档定位**：可直接交付给构建 AI Agent 的实施方案

## 1. 总览

### 1.1 核心目标

在 **保持模拟精度 100% 字节级一致** 的前提下，让 C/C++ 主体达到：

1. **API 现代化** — `FCEUI_*` 收敛、`<cstdint>` 化、enum class 化、头文件去循环依赖
2. **Win11 独占优化** — PerMonitorV2、OpenGL 核心模式、暗色模式感知、Snap Layouts 集成
3. **MSVC 独占硬化** — Control Flow Guard、ASan/UBSan、警告分级处理
4. **性能** — PPU/CPU 热路径缓存优化、分支提示、PGO 可选
5. **可持续** — 删除宏残留、DeSmuME 死代码、`types-des.h` 污染；与 Rust FFI 边界清晰

### 1.2 非目标（明确不进入 v0.3.x）

- ❌ 继续 Rust 重构
- ❌ 跨平台回归（Windows 独占不变）
- ❌ 行为级优化（不允许改变时序，**所有 savestate 必须字节级一致**）
- ❌ UI 大改版（Qt 控件替换另立 v0.4.x 议程）
- ❌ 引入 DirectX 视频后端（**OpenGL 核心模式是行业标准**——见 §3.2）
- ❌ 强制 namespace 全量迁移（v0.3.x 内仅分阶段引入，全量迁移推迟到 v0.4.0）
- ❌ 大规模 mapper 概念化改造（mapinc.h 概念化在实测后被取消——见 §2.1）
- ❌ 引入非 MSVC 工具链（v0.3.6.6 起明文；clang-cl / gcc / MinGW / MSYS2 一律拒绝，理由：ABI / 字节级 savestate 一致性——见 §1.3 铁律 9）
- ❌ 创建任何非 `main` 的 Git 分支（v0.3.6.6 起明文；特性/整合/热修分支一律禁止——见 §1.3 铁律 10）

### 1.3 8 条铁律

1. **可字节级回退**：每个子版本 commit 后能 `git checkout` 切回，且 savestate 哈希一致
2. **CI 必过**：`cargo test` 全绿 + `ctest` 全绿 + `nestest.nes` 跑到 `$C66E` 通过
3. **API 冻结与 RFC**：API 增减必须走 RFC 流程
4. **子版本独立性**：每个子版本可独立 cherry-pick / revert
5. **审查门控**：每合一个子版本必须有审查报告
6. **文档同步**：`docs/tech/` 增量更新；CHANGELOG 用 Keep a Changelog 格式
7. **不得静默改 API**：`#include` 顺序、宏定义、可见符号集合改变必须在 commit message 标注
8. **工具链锁定**：MSVC 19.36 + Qt 6.8 LTS 在 v0.3.16 之前不升级
9. **工具链排斥（v0.3.6.6 增）**：项目**只接受 MSVC**。`CMakeLists.txt:28-34` 强制 FATAL_ERROR，
   拒绝 clang-cl / gcc / MinGW / MSYS2 / 任何 LLVM 工具链。`clang_rt.*` 字符串是 MSVC
   官方 ASan 运行时文件名（**非** clang 工具链引用），保留。
10. **分支精简（v0.3.6.6 增）**：项目**永远仅保留 `main` 分支**。禁止创建任何特性分支
    （`topic/v0.3.x-*`）或整合分支（`release/v0.3.6.5 / v0.3.12.5 / v0.3.16`），
    所有 v0.3.x 子版本提交直推 `main`。

### 1.4 与上游 FCEUX 2.6.6 的关系

- v0.3.x 期间不主动同步上游（FCEUX 2.7+ 走 SDL3 + Wayland，与本项目路线冲突）
- 跟踪但不合并；如需 bug fix 走"借鉴重写"路线
- 注释中保留"based on FCEUX"版权声明（GPLv2 必需）

### 2.3 关键事实校正

构建 AI Agent **不得**在 v0.3.x 期间假设以下常见误解：

- ❌ `mapinc.h` **不是**宏 DSL 载体——它仅是 12 行纯 include 头。Mapper 宏（`DECLFW`/`SFORMAT`/`setprg8`）分布在 `src/fceu.h`、`src/utils/memory.h`、`src/cart.h` 等多处
- ❌ `ppu.cpp` 中没有大量 `extern` 全局（实测 `ppu.cpp` + `x6502.cpp` 共 2 处）
- ❌ `ines.h` 中无 `FCEUI_*` 引用（实测 0 处）
- ❌ 测试基建不是"已有 nestest.nes"——**完全空缺**，必须在 v0.3.0 前置版本中建立

## 3. 工具链与关键技术决策（权威依据）

> **本节列出的每项决策均经联网核验并附权威来源**。构建 AI Agent 不允许在 v0.3.x 范围内随意推翻这些决策。若发现新证据足以推翻，需走 RFC 流程。

### 3.1 工具链：MSVC 19.36 + Qt 6.8 LTS

| 项 | 决策 | 权威依据 |
|---|------|---------|
| 编译器 | **MSVC 19.36 (VS 17.6)** | 锁定 19.36 是为避免 C++23 preview 行为漂移 |
| C++ 标准 | **C++20**（**不**升 C++23） | [MSVC 一致性表](https://learn.microsoft.com/en-us/cpp/overview/visual-cpp-language-conformance?view=msvc-170)：`std::print`/`std::flat_map`/`<mdspan>` 在 MSVC 19.36 上**未实现**；`std::expected` 仅在 VS 17.3+ 部分支持 |
| Qt | **Qt 6.8 LTS**（**不**用 Qt 6.5 LTS、Qt 6.7.2） | Qt 6.5 LTS 已于 2023-10 进入 [commercial-only 阶段](https://www.163.com/dy/article/IHE12DCC0511B8LM.html)（开源用户失安全补丁）；Qt 6.7.2 非 LTS；[Qt 6.8 LTS](https://blog.csdn.net/aggs1990/article/details/142936031) 2024-10 发布，支持期 ~3 年（至 2027-10） |
| C++23 完整迁移 | **推迟到 v0.4.x**（待 MSVC ≥ 19.38） | 同 MSVC 一致性表 |
| `std::expected` | **使用 `tl::expected` polyfill**（vcpkg `tl-expected`） | 避免 C++23 preview 行为漂移；待 v0.4.x 切换标准库 |

**C++23 特性采用时间表**（待 MSVC 升级后启用）：

| 特性 | 状态 | 启用子版本 |
|------|------|----------|
| `std::span` | ✅ C++20 已有 | v0.3.3 |
| `tl::expected` | ✅ polyfill | v0.3.3 |
| `std::stacktrace` | ✅ VS 17.4+ | v0.4.x |
| `deducing this` | ❌ 需 VS 17.13+ | v0.4.x |
| `std::print` | ❌ 未列入 | v0.4.x |
| `std::flat_map` | ❌ 未列入 | v0.4.x |
| `<mdspan>` | ❌ 未列入 | v0.4.x |
| `contracts` | ❌ 未列入 | v0.4.x |

### 3.2 视频后端：OpenGL 核心模式（**不**引入 DirectX 11/12）

**决策**：
- 主路径：OpenGL 核心模式（`#version 330 core`，弃用 `glBegin/glEnd`）
- 高级后端：SDL、QWidget（保留）
- **不引入** DirectX 11/12

**权威依据**：
- [RetroArch PR #277 (2024-01)](https://github.com/flathub/org.libretro.RetroArch/pull/277)：RetroArch v1.15 (2024-03) 起**默认 video driver 为 `glcore` (OpenGL Core Profile)**，而非 DX11/DX12。RetroArch 是全球最流行的多系统模拟器前端（覆盖 NES/SNES/PS1/N64/PSP）
- [DirectX 12 10 周年回顾文](https://new.qq.com/rain/a/20251220A049DO00)：DX12 主战场是 3A 游戏，对 256×240 NES 渲染（<0.1M 像素/帧）是过度设计
- [DirectX 百科](https://baike.baidu.com/item/DirectX/314119)：DX12 旨在为高性能 3D 游戏提供低开销 GPU 抽象

**未来路径（v0.4.x 议程）**：SDL3 GPU API（跨平台、轻量、API 类似 DX12/Vulkan）。

### 3.3 输入系统：XInput/SDL/WGI 三后端插件化

**决策**：
- 主路径：XInput（`xinput1_4.dll` **动态加载**，`LoadLibrary` 而非静态链接）
- fallback：SDL_GameController
- 可选编译：`FCEUX11_WGI_BACKEND=ON`（默认 OFF）启用 Windows.Gaming.Input
- 引入 `class InputDevice` 抽象类统一后端接口

**权威依据**：
- [Unity InputSystem PR #1512 (2022-03)](https://github.com/Unity-Technologies/InputSystem/pull/1512)：**Unity（全球最流行游戏引擎）将 WGI 作为 opt-in 设置**，而非默认
- [DualSenseX 工具](https://dualsensex.com/)：即便 2026 年，Windows 原生 WGI **仍不完整支持** DualSense 高级特性（自适应扳机、触觉反馈），需第三方工具
- [XInput 介绍](https://xinput.org/)：XInput 1.4 至今仍是 Windows 游戏控制器事实标准

### 3.4 性能优化：缓存优化为主，**不**做 SIMD

**决策**：
- 必做：LUT 对齐（64 字节）、`[[likely]]`/`[[unlikely]]` 分支提示、预取（`__prefetch`/`_mm_prefetch`）
- 可选探针：v0.3.11 Phase 2 评估 SIMD（SSE4.2/AVX2），仅作 v0.4.x 决策依据
- **不**强制 AVX2；**不**做 PPU SIMD 化

**权威依据**：
- 联网核验（2026-06-08）：**未找到任何 NES PPU SIMD 优化的学术论文或主流开源模拟器 commit**
- NES PPU 是**状态机+数据混合**场景（Sprite 0 hit、mid-frame 滚动、灰度模式、左侧 8 像素遮罩），SIMD 表达困难
- CSDN 文章 [NES 硬件逆向工程](https://blog.csdn.net/plant/article/details/151923037) 详述 PPU 机制，**全文未提及 SIMD**

### 3.5 `std::byte` 使用策略

**决策**：
- **Raw memory 操作**（savestate 序列化、EmuFile 内部 buffer、`memcpy` 替代）：用 `std::byte`（仅限**新开发**模块）
- **Small integer 语义**（像素值、采样值、寄存器值、PPU 状态、CPU flag 位）：保留 `uint8_t`（`fceu11::u8`）

**权威依据**：
- [OpenLoco PR #1988](https://github.com/OpenLoco/OpenLoco/pull/1988)：开源项目已用 `std::byte` 替代 raw memory 的 `uint8_t`
- [`std::byte` 介绍](https://blog.csdn.net/mmts_yang/article/details/130773279)："`std::byte` 本质上代表一个字节的值，但**并不能进行数字或字符的操作**"
- [`std::byte` 详细用法](https://blog.csdn.net/whl0071/article/details/126390341)：所有算术操作**禁止**；必须 `std::to_integer<T>(b)` 转回整型
- [知乎 byte 类型讨论](https://www.zhihu.com/question/64653243)："`std::byte` **并不是为了让你来进行算术运算的**"

## 6. 跨子版本主题

### 6.1 命名空间策略（三阶段分步）

- **阶段 1（v0.3.7 ~ v0.3.8）**：仅**新引入符号**入 `fceu11::`；旧符号保留全局
- **阶段 2（v0.3.10）**：新 API 头中 `FCEUI_*` 改 `fceu11::Foo`，通过 `using` 别名保留旧名
- **阶段 3（v0.4.0）**：全量迁移旧符号，删除 `using` 别名
- v0.3.16 兼容 shim **仅标记 deprecated，不删除**

### 6.2 命名空间划分

- `fceu11::` — 公共 API
- `fceu11::v0_2_compat::` — 兼容层（v0.4.0 删除）
- `fceu11::detail::` — 内部实现
- `fceu11::testing::` — 测试辅助

### 6.3 弃用流程

每个子版本对**外部可见**的 API 变更：
1. 在 `CHANGELOG` 标注 `[DEPRECATED] <symbol> → <new symbol> (<commit>)`
2. 编译期 `#pragma message("deprecated: use fceu11::Foo")` 警告
3. v0.3.16 仅标记 deprecated；v0.4.0 前允许 `FCEUX11_NO_DEPRECATION_WARNINGS` 宏抑制
4. 实际删除推迟到 v0.4.0

### 6.4 FFI 边界

- v0.2.30 已冻结 180 FFI 函数，**v0.3.x 不增加 FFI**
- 任何 `fceux11_rust.h` 变更需 RFC
- **Rust crate 版本保持 0.2.x 不变**（与 C++ 侧版本号解耦）
- v0.3.10 的 API 收敛若触及 Rust 调用边界，仅改 C++ 包装层，不动 Rust crate

### 6.5 测试策略

| 测试类型 | 工具 | 触发条件 | 状态 |
|----------|------|---------|------|
| 单元 | CTest + GoogleTest | 每个子版本 | v0.2.30 已有 |
| 回归 ROM | `tests/rom_regression_test.cpp` | 每个子版本 | **v0.3.0 新建** |
| 字节级 savestate | `tests/fixtures/golden_hashes.json` | 每个子版本 | **v0.3.0 新建** |
| 性能基线 | Google Benchmark | v0.3.0 / v0.3.12.5 / v0.3.16 | **v0.3.0 新建** |
| 模糊 | libFuzzer + ASan | v0.3.6 / v0.3.16 | v0.2.30 部分有 |
| GUI 烟雾 | Qt Test | v0.3.15 / v0.3.16 | v0.2.30 已有 |

### 6.6 Lua 维护策略

- `src/lua/` 是完整 Lua 5.1 源码（56 个文件，ANSI C）
- v0.3.x 期间：
  - **优先使用 Rust mlua**（`fceux11-lua` crate）
  - 嵌入 Lua 5.1 作为 fallback，**冻结更新**
  - 若发现 Lua 5.1 安全问题，直接弃用 fallback 路径
- `FCEUX11_LUA_RUST_ENABLED=OFF` 时用嵌入 Lua 5.1
