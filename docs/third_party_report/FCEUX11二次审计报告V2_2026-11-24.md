总体上，**审计范围覆盖**：v2.0.8 发布的源代码（HEAD efedd83）、GitHub Actions CI/CD（成功运行的 code scanning、CI、F11QA jobs）、开发计划文档和 v1 报告背景。CI 显示，F11QA runner、普通 CI 构建、以及 CodeQL 扫描作业均已成功执行。v2.0.8 发行说明表明已发布 Windows 64-bit ZIP 资产，SourceForge 同步托管源码与二进制，且开发方修正了发布渠道错误。

## 未关闭发现  

1. **P1：Rust Crate 单元测试缺失（严重）**  
   **位置/路径：** CI 工作流（.github/workflows/ci.yml 及 f11qa.yml）  
   **问题描述：** 审查发现 CI 配置仅安装 Rust 工具链并构建 F11QA runner（`cargo build -p f11qa`），并未执行诸如 `cargo test` 的步骤。项目拆分为多个 Rust crate（formats、media、debug、utils、lua、f11qa 等），其单元测试和锁测试仅在本地运行，CI 中并未自动执行。导致潜在的代码错误或回归未经自动检测。  
   **影响：** 可能降低测试覆盖率，单元/整合测试未纳入持续集成，未来改动风险增加。  
   **为何 V1 未覆盖：** V1 提及 Rust 子项目测试计划，但未检测到 CI 漏执行该步骤；开发侧回应也未否认此点。  
   **建议整改：** 在 CI 工作流中添加适当的 `cargo test` 命令，仅运行需要的包测试以避免超时（可考虑限制为关键 crates），并确保测试失败时使 Job 失败。可参考 F11QA runner 构建步骤的做法扩展。  
   **验收标准：** CI 成功执行覆盖多 crate 的 `cargo test`，并在测试失败时终止构建（可通过 GitHub Actions 状态验证）。  

2. **P2：崩溃报告多次触发（严重）**  
   **位置/代码：** `src/crash_handler.cpp` 中 SEH/CRT 处理逻辑  
   **触发路径：** 程序异常时触发 SEH 或 std::terminate，具体如下：  
   - SEH 过滤器 `seh_filter()` 会检查 `g_inCrash` 并设置为 true，然后调用 `report()`；  
   - `report()` 函数本身没有设置一次性保护；  
   - `terminate_handler()` 调用 `report("terminate", ...)` 后执行 `abort()`；  
   - `install_crash_handler()` 已将 SIGABRT 注册到 `abort_handler()`，后者再次调用 `report("abort", ...)`；  
   - Windows CRT `abort()` 在已有 abort handler 时会触发 SIGABRT 再终止进程（微软文档可参考）。  
   此外，生成的转储文件名以 **秒级时间戳 + 进程 PID** 为基础，使用 `CREATE_ALWAYS` 打开，若同一进程在同一秒内被触发两次，中间文件名相同会覆盖。Crash 日志摘要（`crash_log.txt`）也会出现相同摘要信息的重复条目。  
   **影响：** 同一次崩溃事件可能产生两次转储输出，前一次可能被覆盖或其存在造成混淆，降低诊断准确性；`g_inCrash` 作为普通 bool 未在所有路径共享，且不具备多线程安全性，无法在多线程环境中保证只触发一次。  
   **为何 V1/整改未覆盖：** V2.0.8 开发计划（C2 项）仅说明已实现本地 Minidump 输出，未描述此二次调用风险；现有 F11QA 测试仅验证手动调用 `write_crash_dump()` 有文件生成，不涵盖实际 `terminate→abort` 路径的行为。  
   **整改建议：** 使用跨所有 handler 路径共享的原子一次性保护（如 `std::atomic` 或 `InterlockedExchange`）替代当前 `bool g_inCrash`，并在 `terminate_handler` 执行 `abort()` 前阻止重复上报。可在 `write_minidump()` 中采用追加或确保唯一文件名（如加入毫秒级时间）以防覆盖。建议在真实 Windows 环境通过集成测试触发异常（例如手动抛出），验证单次崩溃仅生成一份 minidump 文件且 `crash_log.txt` 仅记录一条摘要。  
   **验收标准：** 确保在所有崩溃路径中报告仅触发一次（可通过集成测试确认一个崩溃事件只输出一个转储和一条摘要）。
