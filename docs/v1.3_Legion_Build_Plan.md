# FCEUX11 v1.3 Legion 独立构建方案

> **目标**：在 v1.2 Census 已交付的 `fceu11::State` 门面基础上，完成 **CPU 状态对象化（v1.3 Legion）**，同时修复 `docs/logs_74925299265.zip` 中 CI 日志暴露的 3 类缺陷，确保 v1.3 从第一天起即可在 GitHub Actions `windows-2022` 上绿过。
>
> **基线版本**：v1.2.0（commit `79adeeb`）  
> **工具链**：MSVC 2022 19.36+ / C++20 / Rust 2024 / Qt 6.8 LTS / CMake 4.0+ / Ninja  
> **文档更新**：2026-06-20

---

## 1. 总体策略

v1.3 的核心任务是 **把 X6502 结构体及其周边全局变量封装为 `fceu11::Cpu` 类**。本方案把任务拆成两条并行的前置安全线：

1. **先修 CI（Phase 0）**：日志中的失败会把后续改造的真实回归问题掩盖掉，必须先行清零。
2. **再做对象化（Phase 1~4）**：严格按 roadmap 的渐进式原则，每迁移一个文件就跑一次回归测试。

### 关键原则

- **零中间不可用态**：每个 PR 都必须可编译、可运行、`ctest` 全绿。
- **savestate 二进制兼容**：v1.3 完成后，v1.0 的 golden `.fc0` 仍能加载/保存往返一致。
- **性能不退步**：`bench_cpu_frame` 相对 v1.0 基线退步 < 1%。

## 3. Phase 0：CI 稳定化（必须先完成）

### 3.1 BUG-1：修复 Rust E0133 警告

Rust 2024 中，`unsafe fn` 的函数体默认是 **safe context**，原始指针解引用、调用 `unsafe fn` 必须再包一层 `unsafe { }`。

#### 修改点

1. `src/rust/crates/fceux11-media/src/drawing.rs`
   - `cstr_to_bytes`（约第 380 行）内部对 `*ptr.add(len)` 的解引用与 `std::slice::from_raw_parts` 调用包入 `unsafe { }`。
   - 第 456-498 行的 `unused_assignments`（`mw`、`mh`、`ny`、`last_ny`）一并清理，避免日志噪音。
2. `src/rust/crates/fceux11-media/src/filter.rs`
   - 第 330 行的 `unsafe { fill(...) }` 是不必要的（`extern "C" fn` 指针是 safe call），直接移除 `unsafe` 块。

#### 验证

```powershell
cd src/rust
cargo check --all-targets
cargo clippy --all-targets -- -D warnings
```

> 目标：`fceux11-media` 与 `fceux11-formats` 零 warning。

---

### 3.2 BUG-2：golden_savestate_test MD5 不匹配

#### 根因分析

`golden_index.json` 中的 MD5 是在 commit `017d1bb`（MSVC 14.51）生成的。当前 CI（MSVC 14.44）与实际源码之间出现了 savestate 二进制差异。由于本地旧构建恰好通过，说明差异来自**最近一次源码变更后未重新生成 golden 哈希**，而非真正的格式破坏。

#### 修复方案

1. **在干净的 Release 构建上重新生成 golden**：
   ```powershell
   cmake --build build --config Release
   cd tests
   ..\build\tests\fceux11_golden_savestate_test.exe --generate
   cd ..
   ```
   这会更新 `tests/fixtures/golden/golden_index.json` 的 `md5` 字段并写出 `.fc0` 文件。

2. **人工审核 diff**：
   - 仅 `md5` 与 `.fc0` 二进制应变化；`frames_after_load`、`rom`、`scenario` 必须不变。
   - 若发现 `.fc0` 大小突变，说明存在真正的 savestate 格式回归，禁止直接覆盖。

3. **引入跨构建稳定性加固**（防止再次漂移）：
   - 在 `FCEUSS_SaveMS` 路径上审计所有 `AddExState` 注册项，确保没有注册未初始化内存、堆指针或构建相关字符串（如 git rev）。
   - 给 `golden_savestate_test` 增加 `--compare-layout` 模式：把 savestate 按 SFORMAT chunk 拆分，逐 chunk 比对大小与内容，便于定位漂移来源。

4. **CI 中加入 golden 再生门禁**（可选）：
   - PR 阶段仍运行 VERIFY；若修改了 `state.cpp`/`x6502.cpp`/`ppu.cpp`/`sound.cpp`，由维护者在本地或指定 runner 上 `--generate` 后提交。

#### 验证

```powershell
ctest --test-dir build -R golden_savestate_test -V
```

> 目标：9/9 通过（FDS 两项因 BIOS 缺失 SKIP 仍计为 soft pass）。

### 3.3 BUG-3：savestate_regression_test 超时

#### 根因分析

测试流程为：对每个 ROM `Initialize → LoadGame → Emulate 60 帧 → SaveMS → Kill`。CI 在首个 `mapper_nrom.nes` 上挂死，本地可正常推进，说明是**进程级初始化/销毁重入或 headless 环境下的阻塞**问题，而非 ROM 本身。

#### 修复方案

1. **给测试加“帧上限 + 实时 watchdog”**：
   - 在 `computeSavestateHash` 的 `for (int i = 0; i < FRAMES_TO_RUN; ++i)` 循环中，若单帧耗时超过 30 秒则 `abort` 并打印当前 PC/scanline/timestamp。
   - 把 CTest 的 `TIMEOUT` 从 2400 秒降到 300 秒，让失败快速暴露。

2. **修复 `Initialize / Kill` 重入**：
   - 当前 `Kill()` 未关闭 `nes_shm`，`savestate_regression_test` 每次循环都重新 `open_nes_shm` 但只检查 `if (!nes_shm)`。应改为 `Initialize` 时无条件 `close_nes_shm()` 再打开，或让 `Kill()` 调用 `close_nes_shm()`。
   - 检查 `AutosaveStatus_owner` 在 `LoadGameVirtual` 中的作用域 bug（当前 `if (!AutosaveStatus)` 缺少大括号，导致 `AutosaveStatus = ...` 始终执行）。

3. **排查 headless 阻塞源**：
   - 在 `fceu11::Emulate` 入口/出口加 TRACE 日志（仅 `FCEUX11_EMULATE_TRACE` CMake 选项开启）。
   - 确认 `AutoResumePlay`、`FCEU_StateRecorderIsEnabled()` 在测试进程中为 `false`；若为 `true`，在测试入口显式关闭。

4. **fallback 方案**：若短期无法定位挂死，可临时把 `savestate_regression_test` 拆分为 12 个独立 CTest 用例（每 ROM 一个），利用 CTest 单进程隔离缩小影响面，同时保留根因排查入口。

#### 验证

```powershell
ctest --test-dir build -R savestate_regression_test -V --timeout 300
```

> 目标：240 秒内完成 12 个 ROM 的 MD5 比对。

## 4. Phase 1：v1.3 CPU 对象化骨架

### 4.1 新增文件

| 文件 | 职责 |
|------|------|
| `src/cpu.h` | 声明 `fceu11::Cpu` 类与全局兼容别名 |
| `src/cpu.cpp` | 实现 `Cpu::init / reset / power / run` 及钩子 |

### 4.2 `Cpu` 类设计（与 roadmap §3.1 对齐）

```cpp
// src/cpu.h
#pragma once
#include <cstdint>
#include <functional>
#include "x6502struct.h"

namespace fceu11 {

class alignas(64) Cpu {
public:
    // 寄存器访问
    uint16_t pc() const noexcept;
    void set_pc(uint16_t v) noexcept;
    uint8_t a() const noexcept;
    uint8_t x() const noexcept;
    uint8_t y() const noexcept;
    uint8_t s() const noexcept;
    uint8_t p() const noexcept;
    bool jammed() const noexcept;

    // 生命周期
    void init() noexcept;
    void reset() noexcept;
    void power() noexcept;
    void run(int32_t cycles);

    // 中断
    void trigger_nmi() noexcept;
    void trigger_irq(uint32_t source) noexcept;
    void clear_irq(uint32_t source) noexcept;

    // 调试钩子
    void set_cpu_hook(std::function<void()> fn);
    void set_read_hook(std::function<void(uint32_t)> fn);
    void set_write_hook(std::function<void(uint32_t, uint8_t)> fn);

    // 时间戳
    uint64_t timestamp_base() const noexcept;
    int32_t  timestamp() const noexcept;

    // Savestate 兼容：仅序列化代码使用
    X6502& native_layout() noexcept;
    const X6502& native_layout() const noexcept;

private:
    X6502 layout_;                 // 必须保持偏移 0
    uint32_t timestamp_ = 0;       // 原 ::timestamp
    uint32_t sound_timestamp_ = 0; // 原 ::soundtimestamp
    int      scanline_ = 0;        // 原 ::scanline
    MapIRQHook map_irq_hook_ = nullptr; // 原 ::MapIRQHook

    std::function<void()> cpu_hook_;
    std::function<void(uint32_t)> read_hook_;
    std::function<void(uint32_t, uint8_t)> write_hook_;
};

// 全局唯一实例
Cpu& cpu_instance() noexcept;

} // namespace fceu11

// 兼容别名：v1.3 先保留 extern 符号，后续 v1.x 逐步移除
inline auto& g_cpu = fceu11::cpu_instance();
```

### 4.3 布局断言

```cpp
// src/cpu.cpp
static_assert(offsetof(fceu11::Cpu, layout_) == 0,
              "Cpu::layout_ must remain at offset 0 for savestate compatibility");
static_assert(alignof(fceu11::Cpu) == 64,
              "Cpu must remain 64-byte aligned");
```

### 4.4 接入 `fceu11::State`

修改 `src/core_state.h/cpp`：

- `CpuView::reg()` 返回 `cpu_instance().native_layout()`。
- `CpuView::timestamp()` 等返回 `cpu_instance()` 的对应成员。
- 保持旧的全局 `::X`/`::timestamp` 等符号作为 `inline` 引用别名，确保未迁移的文件仍能链接。

## 5. Phase 2：全局变量迁入 `Cpu`

### 5.1 迁入列表

| 原全局 | 新归属 | 兼容别名 |
|--------|--------|----------|
| `X6502 X` | `Cpu::layout_` | `inline auto& X = g_cpu.native_layout();` |
| `uint32 timestamp` | `Cpu::timestamp_` | `inline auto& timestamp = g_cpu.timestamp_ref();` |
| `uint32 soundtimestamp` | `Cpu::sound_timestamp_` | `inline auto& soundtimestamp = g_cpu.sound_timestamp_ref();` |
| `int scanline` | `Cpu::scanline_` | `inline auto& scanline = g_cpu.scanline_ref();` |
| `MapIRQHook MapIRQHook` | `Cpu::map_irq_hook_` | `inline auto& MapIRQHook = g_cpu.map_irq_hook_ref();` |

> 在 `cpu.h` 中暴露 `timestamp_ref()` 等 `noexcept` 引用访问器，便于生成 `inline` 别名。

### 5.2 迁移顺序

按“写入者少 → 写入者多”的顺序，每改一个文件跑一遍 `ctest`：

1. `src/x6502.cpp`（拥有者，必须先改）
2. `src/fceu.cpp`（`Initialize / Kill / Emulate`）
3. `src/ppu.cpp`（读取 `scanline`、`timestamp`）
4. `src/sound.cpp`（读取 `soundtimestamp`）
5. `src/boards/*.cpp`（仅读取 `timestamp` 的 mapper 优先）

### 5.3 验证清单

```powershell
ctest --test-dir build -R "cpu_test|savestate_core_test|golden_savestate_test" -V
```

> 目标：每个文件迁移后上述测试全绿。

## 6. Phase 3：`X6502_Run` 内联重构

### 6.1 目标

保持 `X6502_Run` 为自由函数（热路径无虚调用），但改为接受 `Cpu&` 参数。

### 6.2 接口变更

```cpp
// src/x6502.h
void X6502_RunDebug(fceu11::Cpu& cpu, int32 cycles);
#define X6502_Run(cycles) X6502_RunDebug(g_cpu, cycles)
```

### 6.3 `ADDCYC` 宏改造

原宏类似：

```cpp
#define ADDCYC(x) { timestamp += (x); ... }
```

改为内联成员方法：

```cpp
// cpu.h
class Cpu {
    ...
    void add_cycles(int32_t c) noexcept {
        timestamp_ += c;
        // 原宏中的其余副作用
    }
};
```

在 `x6502.cpp` 中把宏替换为 `cpu.add_cycles(x)`。

### 6.4 验证

```powershell
ctest --test-dir build -R "cpu_test|bench_x6502_exec" -V
```

> 目标：`bench_x6502_exec` 性能与 v1.0 偏差 ≤ 1%。

## 7. Phase 4：调用点迁移与 CMake 更新

### 7.1 调用点迁移

使用 `Grep` 找出所有直接访问 `X.PC`、`X.A`、`timestamp`、`scanline`、`MapIRQHook` 的代码：

```bash
grep -Rnw --include="*.cpp" --include="*.h" src/ \
  -e "\bX\.\(PC\|A\|X\|Y\|S\|P\)" \
  -e "\btimestamp\b" \
  -e "\bsoundtimestamp\b" \
  -e "\bscanline\b" \
  -e "\bMapIRQHook\b"
```

优先迁移：
- `src/x6502.cpp` 自身实现
- `src/fceu.cpp` 的 `Initialize / Emulate`
- `src/ppu.cpp` / `src/sound.cpp`
- 热门 mapper：`src/boards/mmc1.cpp`、`mmc3.cpp`、`mmc5.cpp`、`vrc6.cpp`

每迁移 5~10 个文件提交一次，确保 `ctest` 通过。

### 7.2 CMake 更新

在 `src/CMakeLists.txt` 中把 `cpu.cpp` 加入核心库源文件列表：

```cmake
target_sources(fceux11_core PRIVATE
    ...
    cpu.cpp
    ...
)
```

### 7.3 保留的旧符号

```cpp
// src/cpu_compat.h（可选，或放在 x6502.h 底部）
#include "cpu.h"
extern fceu11::Cpu& g_cpu; // 已作为 inline 别名存在
```

> v1.3 结束时，原 `X6502 X` 等全局变量应仅剩兼容别名；真正的存储全部位于 `g_cpu` 内。

## 10. 风险与回滚

| 风险 | 影响 | 缓解 |
|------|------|------|
| `Cpu` 布局变更破坏 savestate | 高 | `static_assert(offsetof(Cpu, layout_) == 0)` + golden 往返测试 |
| `X6502_Run` 引入额外间接层导致性能退步 | 中 | 保持自由函数、`__forceinline`、跑 `bench_cpu_frame` |
| 全局别名循环依赖 | 中 | 每迁移一个文件跑 `ctest`；发现 ODR 立即回滚 |
| CI 超时/MD5 漂移复发 | 高 | Phase 0 已加入 watchdog 与 golden 再生流程；复发时优先用 `--compare-layout` 定位 |

### 回滚策略

- 每个 Phase 完成后打 tag：`v1.3-phase0`、`v1.3-phase1` 等。
- 若任一阶段 `golden_savestate_test` 或 `bench_cpu_frame` 失败，立即 `git revert` 该阶段提交，回到上一 tag 重新设计。
