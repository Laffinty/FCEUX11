## 1. 单位勘定（本批的关键前提）

先厘清既有实现里 CPU 步进的**单位**，否则无法表达 3.2：

| 层 | 参数单位 | 依据 |
|----|----------|------|
| `X6502._count`（C++ 内部预算） | **1/48 CPU cycle**（每条指令扣 `CycTable × 48`） | `src/rust/crates/fceux11-core/src/cpu/ffi.rs:236-245` 的换算注释 |
| `run_with_tick(state, bus, cycles)` | `_count` 单位（直接 `count += cycles`） | `cpu/tick.rs:193-196` |
| `fceux11_cpu_run_with_tick(cpu, cycles)` | **dot 单位**（内部 `cycles × 16`） | `cpu/ffi.rs:308` |
| 交错循环每次 PPU dot 的调用 | `run_with_tick(cpu, 1)` → 实际 16 个 `_count` 单位 = **1/3 CPU cycle** | `src/rust/src/lib.rs:511` |

于是：**NTSC/Dendy = 每 dot 16 单位（3.0），PAL = 每 dot 15 单位（3.2 = 48/3.2）**。既有的 `fceux11_cpu_run_with_tick` 最小粒度是 16 单位，无法表达 15，因此需要一条原始 tick 的 FFI。

## 2. 落地内容

| 文件 | 改动 |
|------|------|
| `crates/fceux11-ppu/src/video_system.rs` | 新增 `VideoSystemTimings::cpu_ticks_per_dot()` = `48 × den / num`（NTSC 16 / PAL **15** / Dendy 16）+ 单测 `cpu_ticks_per_dot_matches_the_interleave_ratio` |
| `crates/fceux11-ppu/src/ffi.rs` | 新增 `fceux11_ppu_cpu_ticks_per_dot(state)`（只给 Rust 内部用，C++ 不调用） |
| `crates/fceux11-core/src/cpu/ffi.rs` | 新增 `fceux11_cpu_run_ticks(state, ticks)` —— 与 `run_with_tick` 同体，但**不做 ×16 缩放**，参数就是 `_count` 单位 |
| `src/lib.rs`（root crate，`fceux11_run_frame_interleaved`） | 循环前读一次 `ticks_per_dot`；per-dot 的 CPU 授权由 `fceux11_cpu_run_with_tick(cpu, 1)` 改为 `fceux11_cpu_run_ticks(cpu, ticks_per_dot)` |

**NTSC 字节一致性证明**：旧调用 `run_with_tick(cpu, 1)` 内部注入 `1 × 16 = 16` 个 `_count` 单位；新调用 `run_ticks(cpu, 16)` 注入 16 个 —— 数值完全相同，因此 NTSC 路径逐位不变（gate 已证）。

未改动、需登记的两处：

- **NMI 延迟（`FCEUX11_E1_NMIDELAY`，默认 8）** 仍走 `run_with_tick(cpu, 8)`：这是 C++ 引擎手调的 NTSC 标定值（vbl_05 对齐），PAL 下沿用同一常量；若后续 PAL vbl 测试显示需要按制式缩放，另开一批处理。
- **C++ 防御性回退循环**（`ppu_rendering.cpp`，「bridge active but no PPU state」才可达）仍用 `cpu_instance().run(1)`（3.0 比例）。属死路径，已留注释；B.5-2d 可顺手标注。
