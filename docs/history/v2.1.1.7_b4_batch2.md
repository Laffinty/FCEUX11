## 1. 落地内容

### 1.1 被迁移的直读点（§0.4 A 组）

| 文件 | 原读取 | 迁移后 |
|------|--------|--------|
| `src/debug.cpp` `GetMem()` | `PPU[0]` / `PPU[1]` / `PPU[2]` / `PPU[3]` / `SPRAM[PPU[3]]` / `XOffset` / `VRAMBuffer` | `PpuRegRead(0..3)` / `PpuOamRead(PpuRegRead(3))` / `PpuXOffsetRead()` / `PpuVramBufferRead()`（`$2002` 的 open-bus 部分走 `PpuDataBusRead()`） |
| `src/debug.cpp` watchpoint 判定 | `PPU[3]` ×2 | `PpuRegRead(3)` |
| `src/drivers/Qt/ConsoleDebugger.cpp` 寄存器栏 | `PPU[0..3]` ×4 | `PpuRegRead(0..3)` |
| `src/drivers/Qt/ConsoleDebugger.cpp` PPU 控制对话框 | `PPU[0]`/`PPU[1]`/`PPU[2]` ×13 | 每次刷新读一次 `ppuCtrl` / `ppuMask` / `ppuStat` 三个局部量 |
| `src/drivers/Qt/ppuViewerContext.cpp` | `PPU[0]` ×2（8x16 模式、sprite bank） | `PpuRegRead(0)` |
| `src/drivers/Qt/NameTableViewer.cpp` | `PPU[0]` ×2（pattern table 选择） | `PpuRegRead(0)` |
| `src/ppu_core.cpp` `FCEUPPU_PeekAddress()` | `ppur.get_2007access()` / `RefreshAddr` | 桥激活时返回 `ppu_rust_bridge_get_v()`；未激活回落原路径 |

每个消费者文件里 `PpuRegRead()` 都是 **file-local `static inline`**，实现固定为 `ppu_rust_bridge_active() ? <accessor> : <原 C++ 全局>`。这样 `FCEUX11_RUST_PPU=OFF` 的兼容壳与 ON 但未初始化（`g_ppu_state == nullptr`）两种情况都保持今天的行为。

### 1.2 契约扩展（实现期决定，已在 plan §B.4 同步）

| 新增 | 理由 |
|------|------|
| `ppu_rust_bridge_get_x_offset()` / `get_vram_buffer()` / `get_data_bus()` | `GetMem()` 的 $2005 / $2007 / $2002-open-bus 三个 case 与 §0.4 A 组的其余读点同属"Rust 权威、C++ 墓碑"，不一起迁移会让同一函数里出现半迁移状态。三者都复用 B.1 的 staging 镜像（`bridge_xoffset` / `bridge_vram_buffer` / `bridge_ppu_gen_latch`） |
| `SpriteDMA` 镜像（无新增 accessor） | Rust 侧有 `oam_dma_page` 但无查询 FFI。按 Step A 的 "Rust → bridge → C++ staging" 模式，在 `ppu_rust_bridge_cpu_write()` 的 `$4014` 分支写入 `SpriteDMA`，替代已退役的 C++ `B4014`（`ppu.cpp:1151`）。`debug.cpp:338` 的读点保持读该镜像 |

### 1.3 顺带修正

`ConsoleDebugger.cpp:7551-7571`（PPU 控制对话框）原属 §0.4 A 组清单，但 13 处读取散落在一段 UI 代码中；本批改为"每次刷新读一次寄存器"，同时避免同一刷新内多次跨 FFI 取值。
