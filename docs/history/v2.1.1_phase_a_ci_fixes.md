## 1. 三个修复的单 commit 拆解

523059b 把 3 个独立修复打包 commit，导致 nestest frame 2 回归（未定位是哪一个 fix 引起的）。Phase A 的策略：**逐一拆出 + 单 commit 验证 + 必要的 Do-NOT**。

### 1.1 修复 #2 v-walk gate → `ef2ba86`（独立可用，无 Do-NOT 需）

- **文件**: `src/rust/crates/fceux11-ppu/src/rendering.rs`（+18/-5）
- **行为**: `render_scanline` 在 `bg_show = 0`（mask $2001 渲染关闭）时跳过 v-walk 函数（34 coarse-X 增量 + NT-X 翻转），与 C++ engine blank path 一致
- **NESdev spec 校准**: 渲染关闭时次级 OAM clear / sprite evaluation / sprite 0 hit 均不发生（NESdev wiki PPU_rendering）
- **验证**:
  - `ctest -R '^rom_regression_rust_smoke$'` PASS 4.07 sec（frame 2 = `0xee065d4f` 旧 golden 不变）
  - `ctest -R '^savestate_regression_rust_smoke$'` PASS 3.16 sec（savestate 不变）
  - `ctest -R '^kagami_qa_direct_smoke$'` 3P/9F (2 blocking) — baseline 一致
  - kagami read_buffer 改进 0x80 卡死 → 0x1B=27（修复 #2 让 sprite0 hit 行为更接近 C++，但仍有 sprite0 hit in DMA + $2007 写时序根因）

### 1.2 修复 #3 $2007 increment parity → `0958848`（独立可用，无 Do-NOT 需）

- **文件**: `src/rust/crates/fceux11-ppu/src/{ffi.rs, registers.rs, tests/open_bus.rs}`（+73/-25）
- **行为**:
  - 新增 `rendering_2007(sb)` helper（`sl ∈ [0, 241) AND mask & 0x18 != 0`，与 C++ `PPUON` 宏一致）
  - `read_data/write_data/increment_v` 新增 `rendering: bool` 参数
  - 渲染期 `increment_v` 用 `increment_vs()`（coarse-Y / fine-Y / NT-Y walk），非渲染期 +32 形式丢 carry 入 NT-Y bit（`vt++; ... vt &= 31`）
- **NESdev spec 校准**: C++ `Ppu::increment2007`（`src/ppu_class.h:147`）+ NESdev wiki PPU scrolling
- **验证**:
  - `ctest -R '^rom_regression_rust_smoke$'` PASS 4.02 sec
  - `ctest -R '^savestate_regression_rust_smoke$'` PASS 3.23 sec
  - `cargo test -p fceux11-ppu` 16/17 pass（1 个 pre-existing `status_read_at_sl_241_dot_0` vbl_nmi unit test 失败）
  - `ctest -R '^kagami_qa_direct_smoke$'` 3P/9F (2 blocking) — 与 baseline + fix #2 一致

### 1.3 修复 #1 NMI dispatch delay → `b50e685`（**redesigned**，Do-NOT v2.1.1.2 必需）

- **文件**: `src/rust/src/lib.rs`（+46/-0）
- **行为**: `fceux11_run_frame_interleaved` 的 `take_nmi_direct != 0` 分支中，于 `trigger_nmi` 之前 grant `nmi_delay_cycles`（默认 8）CPU cycles 的 CPU-only budget
- **NESdev spec 校准**:
  - C++ engine `X6502_Run(8)` 在 `TriggerNMI()` 之前 grant 8 CPU cycles
  - C++ 注释明确"X6502_Run grants CPU budget (1 CPU cycle per 3 dots) with zero PPU advance"
  - `fceux11_cpu_run_with_tick(state, cycles)` 取 CPU cycles（内部 `scaled_cycles = cycles * 16`）
- **Redesign**（vs 523059b 原始代码）:
  - 变量名 `nmi_delay_dots` → `nmi_delay_cycles`（澄清单位）
  - 大段注释明确"Units are PPU dots" 的 C++ 注释（ppu_rendering.cpp:1614）是**误导**——`X6502_Run` 实际取 CPU cycles；8 = 8 CPU cycles = 24 PPU dots worth，**不是** 8 PPU dots = 2.67 CPU cycles
  - 数值与 523059b 完全一致（都是传 8），但变量名和注释正确化防止下个 agent 误读
- **验证（核心指标）**:
  - `ctest -R '^rom_regression_rust_smoke$'` PASS 4.64 sec（frame 2 = `0xb4a510ca` 不变）
  - `ctest -R '^kagami_qa_direct_smoke$'` **4P/8F (1 blocking)** — baseline 3P/9F (2 blocking) → **+1 PASS, -1 blocking**
  - `blargg_vbl_05_nmi_timing: PASS` ✅（修复 #1 之前 FAIL）—— 核心指标
  - `ctest -R '^savestate_regression_rust_smoke$'` FAIL（savestate 漂移 → Do-NOT v2.1.1.2 处置）
