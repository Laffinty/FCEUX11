## 1. 落地内容

### 1.1 LoadState 接线（B.1-4）

```cpp
void FCEUPPU_LoadState(int version) {
	bridge_state_apply_to_rust();
}
```

`bridge_state_apply_to_rust()`（`src/ppu_bridge_state.cpp`，第二批落地、此前无调用者）把 chunk-3 / chunk-31 反序列化后的 staging 块写回 Rust PPU（`regs[4]` / `oam[256]` / `write_toggle` / `vram_buffer` / `fine_x` / `data_bus` / `v` / `t` / `scanline` / `dot`），随后调用 `ppu_rust_bridge_refresh_windows()`（CHR / NT / palette 三窗口重灌）与 `ppu_rust_bridge_push_mirror_mode_if_dirty()`（镜像模式推送）。

调用点：`src/state.cpp:673`（`FCEUSS_LoadFP` 内），位于 chunk 循环之后（chunk-3 在 `:594`、chunk-31 在 `:597`），因此进入本函数时 staging 已持有存档值。

### 1.2 移除 TempAddrT / RefreshAddrT（B.1-4）

- 删除 `static uint16 TempAddrT, RefreshAddrT;`；
- `FCEUPPU_LoadState()` 不再执行 `TempAddr = TempAddrT; RefreshAddr = RefreshAddrT;`；
- `FCEUPPU_SaveState()` 不再写这两个 scratch。

理由：chunk-3 的 `RADD` / `TADD` 自第三批起指向 `bridge_refresh_addr` / `bridge_temp_addr`，这两个 file-static 只能是进程内残留（跨存档无意义）。删除后 LoadState 的语义由「恢复 C++ 墓碑」变为「恢复 Rust 运行态」。

### 1.3 newppu_hacky_emergency_reset() 调用点评估（B.1-4 要求项）

结论：**保留，本批不改动。**

- 该函数（`src/ppu_core.cpp:42`）只做 `if (ppur.status.end_cycle == 0) ppur.reset();`，防的是「载入旧格式存档后 ppur 未初始化导致除零」。
- 第三批起 chunk-31 已不再序列化 `ppur`（改指 staging 槽位），`ppur` 在当前引擎下无运行时写入者，`end_cycle` 恒为 reset 初值 341，因此该守卫在 Rust PPU 路径下**惰性**（不会触发），但也不会造成错误。
- `ppur` 本体与 `newppu_get_scanline/dot` 的迁移属 §0.4 C 组 / Step C（M4），届时连同 `ppu_legacy_stub.cpp` 一并处理，**本批不提前动**。
