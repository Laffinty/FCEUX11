## 2. 设计决策（本批新增，需 owner 知悉）

### 2.1 RADD / TADD 与 Rust v / t 的对应方向

plan §0.4 与第一批记录的字段表只给了偏移与来源名，未定义方向。代码核查结论：

- FCEUX `RefreshAddr` 是 `$2007` 实际访问并自增的地址（`src/ppu.cpp:813` `tmp = RefreshAddr & 0x3FFF`、`:946/:951` 自增），`$2006` 第二次写入时 `RefreshAddr = TempAddr`（`src/ppu.cpp:1075-1078`）——即 **NES 语义的 `v`**。
- FCEUX `TempAddr` 是 `$2005`/`$2006` 累加的锁存值（`src/ppu.cpp:1066-1076`）——即 **NES 语义的 `t`**。
- Rust `registers.v` = 当前 VRAM 地址、`registers.t` = 临时地址（`src/rust/crates/fceux11-ppu/src/registers.rs:81-84`）。

故映射为 `RADD <- Rust v`、`TADD <- Rust t`，并在源码注释中显式写明"不要交换"。

### 2.2 KOOK / DEAD / PSPL 的兼容处理

三者无 Rust 对应物（`PPUSPL` 属 §0.3 的 C++ 墓碑清单，`kook`/`ppudead` 是旧引擎内部标志）。本批让 staging 在 save 路径**镜像 C++ 墓碑当前值**，使第三批把 SFORMAT 改指 staging 时字节内容与今日完全一致（golden 不因这三项变化）。载入路径不回推它们（Rust 无对应字段）。

### 2.3 为什么窗口刷新要走 wrapper

Rust 渲染器读的是 CHR/NT/palette 的**拷贝**（`g_chr_window` / `g_nt_window` / palette 窗口），镜像模式也缓存在 bridge 内。载入后若不重装，会出现"状态已恢复但画面/调色板仍是旧的"。wrapper 是唯一不复制 bridge 内部逻辑的做法。

## 3. 过程事故与修复

1. **`apply_patch` 在本沙箱不可用**：任何 `apply_patch` 调用都返回 `fs sandbox helper failed ... CreateProcessWithLogonW failed: 267`（非管理员权限的沙箱 helper 无法以当前工作目录 spawn，Z: 为映射网络盘）。改用受控 PowerShell 写入（逐文件、保留 BOM / 行尾、写后 `git diff --stat` 复核）。
2. **`src/CMakeLists.txt` 行尾误转**：首次写入按 `.editorconfig`（`end_of_line = crlf`）转换，导致全文件 1705 行 diff。实测该文件与多数 `.cpp` 在本仓库实际存的是 **LF**（`CR=0`），`.editorconfig` 与实现不符。已改回 LF，diff 收敛为 `+1` 行。
3. **新 TU 缺自包含头**：首次编译报 `C2065: bridge_newppu_pst0/pst1 未声明`、`C2660: WriteLe16 不接受 1 个参数`（枚举缺失导致的级联）。补 `#include "ppu_bridge_state.h"` 后通过。
