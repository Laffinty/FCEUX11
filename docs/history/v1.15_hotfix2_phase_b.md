## 三、各 PR 实现要点

### P1-1 `BGData::ppu1[]` SoA split
- `BGData::Record` 移除 `ppu1[8]`（用 8 字节 `_pad` 占位保持原结构布局）。
- `BGData` 新增 `alignas(64) uint8 ppu1[34][8]` —— 272 字节常驻 L1。
- `Record::Read()` 加 `int slot` 参数；内部所有 `ppu1[i] = PPU[1]` 改为 `bgdata.ppu1[slot][i] = PPU[1]`。
- 调用方 `bgdata.main[xt+2].Read()` → `bgdata.main[xt+2].Read(xt+2)`。
- 内层像素循环 `bgdata.main[xt+2].ppu1[xp]` → `bgdata.ppu1[xt+2][xp]`（直接索引，无 record 解引用）。

### P1-2 `pal_mask` hoist（完整覆盖）
- `RefreshLine` 入口加 `const uint8_t pal_mask = (PPU[1] & 0x01) ? 0x30 : 0xFF;`。
- `RefreshLine` 内 3 处 `READPAL(0)` 重复（`* 4`）改为直接 `PALRAM[0] & pal_mask`。
- `FCEUX_PPU_Loop` 主循环前 hoist `scanline_pal_mask`，替换 `READPAL(0)`。
- `DoLine` 内 `READPAL(0)` 替换为展开的 `PALRAM[0] & mask`。
- **风险**：FF1 polygon effect 在 mid-frame 切换 GRAYSCALE。**缓解**：PPU[1] 写入仅由 mapper 在 tick handler 内触发，mapper tick 不会与 `RefreshLine` 重入；正常游戏无可观察差异。

### P1-3 `cycle` 取模 → wrap-around
- `runppu(int x)`：`% end_cycle` 替换为 `c = cycle + x; if (c >= end_cycle) c -= end_cycle;`。
- **预期**：~67k 次 DIV / 帧 → ~67k 次高度可预测 `cmp+jcc`（仅 1/341 触发 taken branch）。

### P1-4 `runppu1_inline` FCEU_ALWAYS_INLINE
- 新增 `FCEU_ALWAYS_INLINE inline void runppu1_inline() noexcept` 包装 `runppu(1)`。
- `BGData::Read` 内 8 处 `runppu(1)` 全部替换为 `runppu1_inline()`。
- `runppu(int)` 保留作 fallback（处理 `kFetchTime=2` / `kLineTime=341` 等大 x 场景）。

### P1-5 `PPU_hook` 去虚化
- `pputile.inc` 3 处 `#ifdef PPUT_HOOK` 加 `if (PPU_hook) [[unlikely]]` 守卫。
- `pputile_template.cpp` 3 处 `if constexpr ((Flags & kFlagHook) != 0)` 内同样加守卫。
- 与 P1-6 dispatcher 配合：non-hook 路径 `kind != Hook`，根本不进 `PPUT_HOOK` 块；hook 路径多 1 个 null-check 分支，可被 branch predictor 完全预测为 taken。

### P1-6 `RefreshKind` enum dispatcher
- `RefreshLine` 入口一次 select `RefreshKind`（9 个值：`Normal`/`MMC5SP`/`MMC5CHR1SP`/`MMC5CHR1`/`MMC5Only`/`Hook`/`HookBGFetch`/`BGFetch`/`VRC5Fetch`）。
- 替换原 `if (MMC5Hack) ... else if (PPU_hook) ... else ...` 三层嵌套为 `switch (kind)`。
- **MMC5SP 路径**保留 per-tile `tochange` 逻辑（其语义为"split-screen 切换点"，是 per-scanline dynamic，**不能** hoist 到 RefreshLine 入口）。
- **风险**：mapper 矩阵回归未跑（Phase C 验证内容）；Phase B 单元测试仅覆盖 enum 定义 + RefreshKind 的 `select` 顺序。

### P1-7 `scanline_ref` value-return
- `Cpu` 新增 `int scanline() const noexcept { return scanline_; }` 与 `void set_scanline(int v) noexcept { scanline_ = v; }`。
- 原 `int& scanline_ref()` 保留作 back-compat。
- **热路径全部改造**：
  - `DoLine`：`int sl = g_cpu.scanline();`（替换 4 处 `g_cpu.scanline_ref()` 调用 + 1 处 `set_scanline` 写）。
  - `FetchSpriteData`：`const int sl = g_cpu.scanline();`（64 次循环读取 hoist 出循环）。
  - `FCEUPPU_Loop`：`for (int sl = 0; sl < totalscanlines;)` 替换 `g_cpu.scanline_ref()` 5 处调用。
  - `FCEUX_PPU_Loop`：`g_cpu.set_scanline(yp)` 替换 `g_cpu.scanline_ref() = yp`。
- **未改**：mapper (`src/boards/*.cpp`)、debug、Qt driver 等冷路径 —— 保留 `scanline_ref()` 兼容。
