## 一、收益事实（已实测，留档复用）

| 场景 | 基线（/GL + /LTCG，无 PGO） | Phase-2（/USEPROFILE） | 收益 |
|---|---|---|---|
| 魔界村 | 578.6 fps | 762.0 fps | **+31.7%** |
| SMB3 | 579.6 fps | 792.1 fps | **+36.7%** |

- 读数条件：同生成器、同 `/GL`+`/LTCG` 基线（量的是 **PGO 增量**而非「LTCG+PGO 合计」）；
  7 轮交替 A/B；训练 = 魔界村 / SMB3 / 塞尔达各 12,000 帧。
- 结论：PGO 在本仓有**真实、显著**的吞吐收益（模拟器核心体验）。

## 二、立项材料 ① · 训练流程脚本化（✅ 本批交付）

`scripts/train_pgo.ps1`：三场景（魔界村 / SMB3 / 塞尔达，各 12,000 帧，`SDL.KillFCEUXonFrame`
定帧退出）→ Phase-1 插桩 exe 上逐场景运行 → `.pgc` 落在 exe 旁供 Phase-2 `/USEPROFILE`
链接消费。流程四步（脚本头注释有完整命令）：

```
cmake -B build-pgo -DFCEUX11_PGO=ON ...        # Phase-1 插桩树
cmake --build build-pgo -j 1                    # 串行（坑 12）
powershell -File scripts\train_pgo.ps1 -Exe build-pgo\src\fceux11.exe -Rom1 ... -Rom2 ... -Rom3 ...
cmake -B build-pgo2 -DFCEUX11_PGO_USE=ON ...    # Phase-2 消费 profile
```

⚠️ 训练 ROM 路径参数化（三张卡在业主手上，不入库）；`.pgc` 的落盘位置 = exe 目录。

## 三、立项材料 ② · `.pgc` / 训练 ROM 的可复现性决策（两个选项，待裁决）

| 选项 | 做法 | 代价 | 可复现性 |
|---|---|---|---|
| **A（描述性重建，建议）** | 训练 ROM 不入库；脚本 + 场景定义 + 帧预算入库；任何人用**自己的**三张卡跑同一脚本即得到语义等价的 profile | 零存储成本；profile 数据**逐字节不可复现**（ROM 不同），但训练**覆盖面**可复现 | 中 |
| B（入库） | `.pgc` + 训练 ROM 哈希清单入库，CI 直接消费 | ROM 是业主私人资产 ⇒ **入库不可行**；`.pgc` 二进制入库膨胀仓库 | 高（但前提不成立） |

**建议**：选项 A。`.pgc` 不入库，CI 侧不做 PGO artifact 的逐字节比对；release 时以
「训练脚本 + 场景定义」作为可复现性的载体。

## 四、立项材料 ③ · CI 双 job 成本清单（若 CI 出 PGO artifact）

- 两个开关互斥（`FCEUX11_PGO` / `FCEUX11_PGO_USE`，CMakeLists.txt:103 FATAL_ERROR）⇒ CI 需要
  **两个串行 job**：`build-pgo-phase1`（插桩构建 + 训练）→ `build-pgo-phase2`（消费重建）。
- 成本项：
  1. **构建时间翻倍**：Phase-1 + Phase-2 两次全量构建；本机 Release 全量 ≈ 40–60 min
     （LTCG，坑 13），CI runner 更慢 ⇒ 两个 job 合计 ≈ 2.5–3 小时；
  2. **训练时间**：3 × 12,000 帧（脚本内定帧退出，分钟级）；
  3. **CI 无声卡**：无音频设备路径已被 v2.0.5 的 `sound_no_device_test` 修复覆盖
     （WriteSound 闸门），训练帧率不受 runner 无声卡影响——已实测前提成立；
  4. **artifact 体积**：PGO exe 与普通 exe 同量级（.pgd/.pgc 不随 exe 分发）；
  5. **缓存**：Rust 版本锁定（坑 16）与训练脚本无交互，无新增缓存键。
- 结论：CI 侧做「每周/每 release 一次」的 PGO artifact job 可行，代价约 3 小时 runner 时间/次；
  **不建议**把 PGO 放进 PR 门禁（时间成本不可接受）。
