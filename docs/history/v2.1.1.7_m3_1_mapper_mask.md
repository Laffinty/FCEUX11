## 1. 关键发现：plan 指定的做法在该处**不安全**

plan §0.4 A 组要求 mapper 侧 `mmc5.cpp:676` / `coolgirl.cpp:1893` 改走 `ppu_rust_bridge_get_register(1)`。实施前核查发现这会踩到借用约束：

- `MMC5_hb` 由 `PPU_hook` 调用，而 `PPU_hook` 是桥在 `bridge_notify_scanline()` 内触发的 —— 也就是说它**运行在 Rust 调度器回调里、StateBox 借用被持有**。
- B.4 accessor 的文档明确写着这类位置**禁止**调用任何 `fceux11_ppu_*` FFI（借用别名/死锁），Phase 5.1 就是为这个 bug 修的桥。

因此本批改用**桥维护的 C++ 镜像**（Step A 的 "Rust → bridge → C++ staging" 模式，零 FFI）：

| 位置 | 行为 |
|------|------|
| `ppu_rust_bridge.cpp` | 新增 `g_ppu_mask_mirror`，只在三处更新：`$2001` 写（写入值即新值，Rust `write_mask` 原样存储）、`ppu_rust_bridge_power()`、`ppu_rust_bridge_refresh_windows()`（savestate 载入路径） |
| `ppu_rust_bridge.h` | 新增 `ppu_rust_bridge_get_mask_mirror()`（纯内存读）+ OFF 分支 stub |
| `src/boards/mmc5.cpp` | `MMC5_hb` 的 `ppuon` 改读镜像（`ppu_rust_bridge_active()` 时），否则回落 `PPU[1]` |
| `src/boards/coolgirl.cpp` | `$5204` 的 in-frame 判定同上 |

`ppu_rust_bridge_active()` 只读两个普通全局量，回调内安全。

**这是修既存缺陷**：迁移前 `PPU[1]` 在 Rust 引擎下恒为 0 → `ppuon` 恒 0 → `MMC5_hb` 每个扫描线都重置 IRQ 计数器（`MMC5IRQR &= ~0x40/~0x80`、`MMC5LineCounter = 0`），MMC5 扫描线 IRQ 时序基本失效；coolgirl 的 `$5204` 同理恒判"渲染关闭"。
