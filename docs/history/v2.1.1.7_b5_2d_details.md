## 1. 制式细节：PAL/Dendy 强调位互换

- 新增 `PpuState::effective_mask()`（`state.rs`）：50 Hz 制式下 `$2001` 的 bit5（green）与 bit6（red）emphasis 互换，其余位（含 grayscale、sprite/BG enable）不变——依据 Mesen2 `NesPpu.cpp:569-570` 的注释。
- `rendering.rs` 的 BG 渲染改用它取 mask（`palette_adjust_pixel` 的调用方）；精灵路径的 mask 由调用方传入 `state.registers.mask`，后续 Step D 统一时一并收口。

**验证边界（登记）**：本项是纯 PAL 路径，**没有视觉基准可对照**（无 PAL 参考截图/ROM 输出），因此只做到"实现与文献一致 + NTSC 零影响"；真机观感由 owner GUI QA。

## 3. 新增 gate：`pal_timing_test`（ctest 第 30 项）

`tests/kagami/pal_timing_test.cpp`（headless，链接 core + kagami 桥）：8 项检查，实测全过：

```
ok: NTSC frame = 89342 dots
ok: PAL frame = 106392 dots
ok: Dendy frame = 106392 dots
ok: FCEUPPU_SetVideoSystem(1) selects the PAL frame budget
ok: FCEUPPU_SetVideoSystem(0) selects the NTSC frame budget
ok: PAL frame budget active after kagami_bridge_set_video_system(1, 0)
ok: 600 PAL frames ran without error
PASS: pal_timing_test ok
```

为支撑第 6/7 项，新增 `kagami_bridge_set_video_system(int pal, int dendy)`（`src/kagami_bridge.{h,cpp}`）：设置 `dendy` 全局 + 调用 `FCEUPPU_SetVideoSystem`（即生产接线）。load_rom 之后调用，避免被 ROM 自身的制式复位覆盖。

CMake：注册在 `if(FCEUX11_RUST_PPU)` 内，并给该 TU 加 `FCEUX11_RUST_PPU` 编译定义（否则头文件走 OFF 分支、只有 stub 可用）。

### 本批踩到的编译错误（接手参考）

1. `ppu_rust_bridge.h` 的 `#else`（OFF 分支）里 stub 引用了 `PPU_RUST_NTSC_PPU_DOTS_PER_FRAME`——该宏只在 `#ifdef FCEUX11_RUST_PPU` 分支定义 → C2065。已改为字面量 `89342u`。
