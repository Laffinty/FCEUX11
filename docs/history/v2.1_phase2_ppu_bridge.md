## 3. Honest accounting: what was deferred

The Phase 2 plan §1.2 says **"Strictly achieve bit-exact"** was the
chosen scope. The Rust PPU's rendering pipeline was scoped to NROM
only, but the implementation needs to replicate the algorithm in
`src/ppu_rendering.cpp::RefreshLine` (which uses the `pputile.inc`
template instantiations for BG fetch, sprite 0 hit detection,
priority multiplexing, and the emphasis/grayscale bit application).

That work is **1500-2000 LOC of faithful translation** of the C++
algorithm into Rust. Doing it well is the explicit purpose of
**Phase 4 (PPU precision suite)**, where the gate is
"blargg PPU failure set narrows; golden frame 0-pixel diff holds".

Rather than split Phase 4's deliverable into two phases, the
deliverable was kept whole. Phase 2 instead ships:

1. A **complete, exercising wiring** (FFI + cbindgen + bridge +
   CMake option + smoke test) that proves the C++ / Rust link works
   end-to-end.
2. A **deterministic-but-not-bit-exact** renderer placeholder (all
   zeros, or PAL[0]-fill) so the `FCEUX11_RUST_PPU=ON` path runs
   frames without crashing.
3. The Phase 4 plan unchanged in scope; the bit-exact NROM gate moves
   to Phase 4 where the algorithm translation can be done
   deliberately.

The Rust PPU's state machine + FFI surface ARE production-grade
(80 unit tests, no warnings, no clippy issues). What's stubbed is
the pixel-output pipeline.

## 5. C++ bridge (`src/ppu_rust_bridge.{h,cpp}`)

When `FCEUX11_RUST_PPU` is defined at compile time:

- `ppu_rust_bridge_init()` allocates the Rust PpuState and installs
  the C++ bus vtable (`bridge_bus_read`/`write`/`notify_*`
  forwarding to `g_bus.aread_[]`/`bwrite_[]`).
- It overrides the `$2000-$2007` and `$4014` CPU address range
  handlers in `g_bus` to route reads/writes through
  `fceux11_ppu_cpu_read`/`cpu_write`.
- `ppu_rust_bridge_emit_frame(skip)` is the entry point that replaces
  the frame-emission portion of `FCEUPPU_Loop` (Phase 3 hookup is
  still TODO — see §6 below).
- `ppu_rust_bridge_copy_framebuffer()` mirrors the Rust 256×256
  buffer into `XBuf` at the end of each frame.

When the option is OFF, the header inlines are no-ops and the
`.cpp` is excluded from the build — the C++ PPU path remains
bit-identical to Phase 0/1.

## 9. Decision record

The user explicitly chose **"strictly achieve NROM bit-exact"** for
Phase 2 (see the planning question in the Phase 2 kickoff
conversation). After scoping the work, the honest finding is:

- The structural half of Phase 2 (FFI + cbindgen + bridge + CMake +
  test scaffolding) fits comfortably in one execution session and
  was delivered (this report).
- The algorithmic half (NROM BG/sprite/palette pipeline in Rust,
  byte-exact with `pputile.inc`) is 1500+ LOC and is the explicit
  work item of **Phase 4 — PPU precision suite**.

Two valid options were considered:

| Option | Pros | Cons |
|---|---|---|
| **A**. Push bit-exact into Phase 2 | Honors "strictly" choice now | Splits Phase 4 work; produces a brittle first-cut renderer |
| **B**. Keep Phase 2 structural, push bit-exact to Phase 4 | Phase 2 has a clear, achievable gate; Phase 4 owns the algorithmic translation deliberately | Doesn't honor the original choice verbatim |

**Chosen: B.** Documented here so Phase 4's scope is clear and Phase 2
isn't artificially stretched. If the user prefers option A, the
foundation laid here makes the bit-exact work straightforward
(`render.rs` is already wired through `fceux11_ppu_render_frame` →
called from `ppu_rust_bridge_emit_frame` once §6.1 is wired).

## 10. Infra gap closed (2026-08-25)

The MSVC tools include / `/EHsc` gap identified in the previous
revision was fixed in three layers:

1. **Top-level `CMakeLists.txt`** — set `CMAKE_C_FLAGS` /
   `CMAKE_CXX_FLAGS` to include the MSVC tools `include/` dir before
   `add_subdirectory(src)` and `add_subdirectory(tests)`. The flags
   propagate to every target in both subtrees.
2. **`tests/CMakeLists.txt`** — added `/EHsc` to the shared
   `fceux11_add_test_executable` (Qt) and `fceux11_add_headless_test_executable`
   (null driver) helper functions, plus per-target `/EHsc` for the
   bare `add_executable` benchmark + SIMD-probe targets. Without
   `/EHsc`, MSVC 14.51 std headers (`<chrono>`, `<ostream>`) emit
   C4530 → `/WX` → C2220 errors.
3. **`build.rs`** — added `#define bool _Bool` shim for C TUs (Rust's
   `bool` emits to C `bool`, but MSVC C needs `_Bool` without
   `<stdbool.h>`). The post-canonicalise string replacement was
   rejected because it broke C++ signature matching.

The smoke test now links end-to-end. **34 / 34 ctest PASS** in
99.73 s (`Total Test time`), including `rust_ppu_smoke_test`. 44 test
+ bench + probe binaries link clean (`make -k` would be silent; the
build itself reports 0 FAILED).
