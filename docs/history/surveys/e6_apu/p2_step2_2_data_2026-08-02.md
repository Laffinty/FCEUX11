## 1. 改动内容（src/sound.cpp，`Write_IRQFM`）

`fcnt=1` 后的计时器重置由无条件 `fhcnt=fhinc` 改为：

```cpp
// 硬件语义（blargg readme + 04.clock_jitter.asm）：
//  - $4017 写须等下一个偶数 APU clock（/2 clock）才重置计时器；
//  - 落在奇数 APU clock 的写多延迟 1 cyc（clock jitter，blargg sub-test 4/5 检测）；
//  - 可观测目标（apu_single_4）：sub-test 2 在 write+29831 读须 CLEAR，sub-test 3 在
//    write+29833 读须 SET，get_jitter 在 write+29832 读须随写时刻 APU 相位翻转。
const uint32 ts2 = g_cpu.timestamp_ref();
const bool e3_odd_apu = (ts2 & 1) != 0;          // 写时刻 CPU ts 奇偶 = APU /2 相位
fhcnt = fhinc + (1 + (e3_odd_apu ? 1 : 0)) * 48;  // 偶数 +1 cyc，奇数 +2 cyc
```

- **offset=1**（生产默认，`FCEUX11_E3_OFFSET` 可覆盖）：第 4 个 quarter（IRQ 置位 / 二次 length clock）
  由 write+29831 推至 **write+29832（偶）/ +29833（奇）**。
- **jitter 相位 = `g_cpu.timestamp & 1`**：两次 get_jitter 调用间隔偶周期 → 相位相同 → 结果相同；
  间隔奇周期 → 相位翻转 → 结果不同（blargg sub-test 4/5 判据）。

### 2.3 根因（未闭合项，`apu_single_5/6` "second too soon"）

1. **hook 量化方差**：`FCEU_SoundCPUHook` 只在指令边界检测 `fhcnt<=0`，quarter 触发点
   = 首个 ≥ 真实 crossing 的指令边界，随指令流浮动 **±2-3 cyc**（同 offset 下 q4 实测
   29829–29835 均有出现）。blargg 的 1-cyc 容差窗口（读 29831 须 CLEAR / 29832 须 SET）无法
   被固定参数覆盖。
2. **2-quarter span 差 ~1 cyc**：M2 读点 14913 需 q2 ≤ 14913，M3 读点 29831 需 q4 ≥ 29832；
   模型 2-quarter span（14915 + 量化）实测 14918，差 1 cyc。offset 0→1→2 扫描中
   single_5 依次 0x04→0x04→0x03，**无 offset 使窗口非空**。
3. **已尝试方案（全部不足以收敛）**：

| # | 方案 | 结果 |
|---|---|---|
| A | offset 0/1/2/3/4 整数扫描 | 仅 offset=1 过 single_4；single_5/6 永不 0x00 |
| B | fhinc 扫描（7457.5/7458/7458.5） | single_5/6 仍 0x03–0x05 |
| C | 分数 offset 1.25/1.5/1.75 | 1.25 即把 single_4 打回 0x03（触发点已量化） |
| D | fcnt==3 时 4-step 加 48 单位（第 4 quarter 后移 1） | single_5 0x04→0x05（过冲），single_4 0x00→0x03（回归） |
| E | fhcnt 递减改用 `g_cpu.timestamp` delta | single_4/5/6 全 0x03（整体过晚） |

**结论**：需消除 hook 量化方差（cycle-accurate 帧计数器模型 / 精确 crossing 记账），超出本步参数
范围。按方案 §6 记为**有据已知限制**，后续以独立 PR（Step 2.2 深化或 Step 2.2b）处理。

## 5. 结论与下一步

- Step 2.2 一阶近似（offset=1 + jitter）**正确、零回归**，独立闭合 `apu_single_4_jitter`。
- 未闭合项：`apu_single_5/6`（hook 量化方差，参数级无法收敛 → 有据已知限制，§2.3）；
  `apu_reset_4017_timing/written`（power/reset 路径，归 Step 2.1 校准）；
  `apu_test`（组合套件，随 single_5 同步）。
- **下一步建议**：
  1. 若继续 Step 2.2 深化：以 cycle-accurate quarter crossing（消除 hook 量化）为唯一可行路径，
     需评估 x6502 采样模型改动面（风险高，与 Phase 1 Step 1.3 同族）。
  2. 否则按方案顺序推进 **Step 2.3（5-step 立即 clock 触发条件 V&0x1）**（独立、低风险），
     或回到 Phase 1 Step 1.3（E-1 CPU 侧采样模型）。
  3. `apu_reset_4017_timing` 的 "delay 2" 与 single_5 的 span 缺口疑同源（power/write 两路径
     的 effective-write 记账），建议并入 1 的深化项一并处理。
