## 2. 测试 ROM 源码实证（漂移来源 = 亚指令粒度）

`build/vbl_06-suppression.s`（`loop_n_times test,10`）：
- 每行 `jsr print_a`（A=行号）→ `jsr sync_vbl_delay`（A 额外延迟）→ `delay 29748` → 开 NMI →
  `nop; nop; lda PPUSTATUS`（测量读）。
- 头部注释 "Reads $2002 one PPU clock later each time" 即来自 `sync_vbl_delay(A=行号)`：
  `build/vbl_sync_vbl.s` 的 A 循环每迭代等效延迟 1 PPU dot（1/3 CPU 周期）。

**关键**：漂移为 1/3 CPU 周期/行（亚指令粒度）。而 `A2002` 派发发生在指令边界
（`x6502.cpp` 执行循环：整条指令执行后 `ADDCYC`，读的 timestamp = 指令起始边界），
且 CPU run 期间 `ppur.status.cycle` 停驻 —— 10 行仅产出 2 个离散落点
（行 0-3 Δ=0、(240,0)；行 4-9 Δ=+4、(241,0)，8-02 调查表 1.1）。

## 3. 新发现：残量在差值中抵消 → 漂移被重同步摧毁（非"未建模"）

8-02 调查建议"用 `_count` 残量携带子周期相位"。复核后不成立：

1. 行 4-9 的读全部位于同一指令边界（Δ=+4 CPU 周期），其相对 VBL_ENTER 的残量
   = VBL_ENTER 残量 + (4×48 mod 48) = VBL_ENTER 残量 → **残量在 (读 − 置位点) 差值中抵消**。
2. 读相对置位点偏移恒为 +12 dots（3×4），无任何亚周期结构可恢复。
3. 因此漂移不是"未建模"，而是被帧边界重同步（VBL 块 `X6502_Run(nd)` → `TriggerNMI` →
   runppu 驱动的 VBL 周期）**确定性摧毁**。恢复漂移需 CPU 在帧边界附近的亚指令级读时序
   （cycle-accurate 内存访问时序 / CPU-PPU 联合仿真改造），超出"A2002 加相位"范围。
4. vbl_02 read2 cycle 序列（8-02 调查 §1.3：`338,336,340,332,333,328,329,330,340,332`）
   同样量化且非单调——行 1/7 命中 (240,340)（过抑制）而行 04 未命中（欠抑制）。

## 4. 顺带发现的真实缺口（小修，独立于深模型）

`A2002` 在 (241,0-1) 执行 `X6502_IRQEnd(FCEU_IQNMI)` 是 **no-op**：
- 读发生在 VBL 块 `X6502_Run(nd)` 期间，**早于** `TriggerNMI()`（`:1642`/`:1648` 顺序），
  NMI 尚未 latch，`X6502_IRQEnd` 无事可清；随后 `TriggerNMI` 照常 latch → NMI 照发。
- 当前代码注释声称"读置位点取消 NMI"，实际未生效——真实正确性缺口。
- 正确语义（硬件：读置位点拉高 /NMI，CPU 下一边界不采样）：标记"本帧 NMI 被读取消"，
  VBL 块跳过 `TriggerNMI`。

> **🚨 2026-08-03 实测证伪"可独立落地"（`vbl_step1_2_nmi_cancel_gap_2026-08-03.md`）**：
> 按上述语义实装（marker + VBL 块跳过 `TriggerNMI`）后，探针证实取消**机制正确生效**
> （vbl_06 × 600 帧：10 帧全部 `nmi_cancel=1`、0 次 `NMI_SET`，基线为 10 次），
> vbl_06 行 5-6 转 `V -`（目标达成）；**但 vbl_04（PASS→0x03）与 vbl_05（PASS→0x01，
> X=255 = NMI 未触发）回归**——vbl_04/05 的 VBL 轮询读同样落在 (241,0)（模拟器 ~2-3 dot
> 帧边界偏移），取消一旦生效即误伤其本应触发的 NMI。
> **结论**：取消语义在"读落点正确"时硬件正确，但当前所有 VBL 附近读被量化到同一指令边界，
> 无法区分"应取消"（vbl_06 行 5-6）与"不应取消"（vbl_04/05 轮询）→ **落地绑定深模型
> （CPU 侧读落点/帧边界偏移），不可独立落地**。已回滚（§0.2 任一红即回滚），代码保持基线。
