# E-1 vbl_05 ROM 反汇编与时序诊断（2026-07-30）

## 范围

读取 blargg `ppu/vbl_05_nmi_timing.nes` 的实际 6502 代码，回答
"测试每行在测什么、对哪个 PPU 时序参数敏感"。这是 `e1-step2-attempt-2026-07-30`
memory 推荐的"先读 ROM 再动 PPU"路径的第一步。

## iNES 与向量

| 字段 | 值 |
|---|---|
| Mapper | 1 (MMC1) |
| PRG | 2 × 16KB = 32KB |
| CHR | 1 × 8KB |
| NMI vector | $E308 |
| RESET vector | $E8E7 |
| IRQ/BRK vector | $E681 |

NMI handler 仅 5 字节：`STX $20 / RTI` —— **X 寄存器被存到零页地址 $20**。
这意味着 blargg 5 整个测试架构是：CPU 在循环里递增 X，NMI 触发瞬间
存住当时的 X 值，作为测量值。

## 主测试循环（10 行输出对应 10 个不同的测试条件）

`$E30B-$E31A`：循环 10 次，每次调 `$E32C`（per-test）：
```
E30B: JSR $E96B
E30E: LDA #$00
E310: PHA
E311: JSR $E32C
E314: PLA
E315: CLC
E316: ADC #$01
E318: CMP #$0A
E31A: BNE $E310
```

每次 push 当前行号（A=0..9），调 `$E32C` 跑一个测试子项。

## 每测试子项（$E32C-$E365）

```asm
E32C: JSR $E48B       ; print行号
E32F: JSR $E7D9       ; 关渲染 ($2001=0)
E332: JSR $E2E0       ; ★ 真正的时序测量 ★
E335..E33E:           ; 打印 "t8" 调试前缀
E343: LDA #$FF
E345: STA $20         ; 清测量槽
E347: LDX #$00        ; X 基线 = 0
E349: LDA #$80
E34B: STA $2000       ; 启 NMI (但还没 $2001 渲染)
E34E: LDX #$01        ; X = 1
E350: LDX #$02        ; X = 2
E352: LDX #$03        ; X = 3
E354: LDX #$04        ; X = 4
E356: LDX #$05        ; X = 5 (覆盖前值，净效果 LDX #$05)
E358: LDA #$00
E35A: STA $2000       ; 关 NMI
E35D: LDA $20         ; 读 NMI 触发时存下的 X
E35F: JSR $E52F       ; 转换成 ASCII 数字
E362: JSR $E4F9       ; 打印
E365: RTS
```

E34E-E356 是 dead store：6 条 `LDX imm` 只有最后一条（X=5）生效，
前 5 条被覆盖。但代码**保留**这 5 条，每条 2 CPU cycle，**累计多烧
10 CPU cycle**——blargg 测试代码显式地用它们当作"等待时间"，让
X 在 NMI 触发前有 5 个不同起点。换言之：每行测的不是"X 终值"，
而是"在 X 已经被设为不同值的多个时点上，NMI 触发相对 $2002 bit 7
变可见的相位差"。**这与本会话前的假设 "1 cycle 整体偏移" 完全不符
——每行是不同的相位对位。**

## 时序测量核心（$E2E0-$E233）

```asm
E200: PHA                  ; 保存 A
E201: SEI                  ; 关 IRQ 避免干扰
E202: LDA #$00
E204: STA $2000            ; 关 NMI
E207: BIT $2002            ; 读 $2002 清 VBL flag
E20A: BIT $2002            ; 二次读稳定
E20D: BPL $E20A            ; 等 VBL set（首次）
E20F..E21C: 打印 "t"      ; 调试输出
E21D: BIT $2002            ; 再读 $2002
E220: BMI $E224            ; 若 VBL 仍 set → 直接进循环
E222: NOP                 ; VBL 已清 → 烧 2 cycle
E223: NOP
E224: JSR $E484
E227: JSR $E488            ; 每轮 +1 X
E22A: BIT $2002            ; 读 VBL flag
E22D: BIT $2002
E230: BPL $E227            ; 未 set → 继续
E232: PLA                  ; VBL set → 跳出循环
E233: RTS
```

**每轮循环** = `JSR $E484 (6c) + JSR $E488 (6c) + BIT $2002 (4c) +
BIT $2002 (4c) + BPL taken (3c)` = **23 CPU cycle**。

NMI handler 触发时把当前 X 存到 $20。X 是"已经经历的循环轮数"。
blargg 把 X 换算成 cycle count，再除 23 取整（或直接打印 X）。

## 行 00-06 期望 = 2，实测 = 1 的含义

期望 2 = "CPU 看到 VBL set 之前，循环已跑 2 轮 = 46 cycle"（这是
NTSC PPU 在 VBL 清到下次 set 之间的间隔 ≈ 2270 PPU dot ≈ 756.7 CPU cycle，
循环每轮 23 CPU cycle → 期望 X ≈ 33。但实际打印 1 位数 = 0..9 → blargg
做的不是直接打印 X，而是把 X % 10 或类似映射到 1 位输出。）

无论具体映射，**实测 = 期望 - 1** 意味着：
- NMI 触发相对 VBL flag 变可见**早 1 CPU cycle**（约 3 PPU dot）；
- 或者：CPU 看到 VBL set 之前循环少跑了 1 轮 = NMI 派发点偏早。

**修法不是 "delay by 1 cycle"**——这是上次回退 PR 的错。正确做法是：
在 `TriggerNMI()` 调用之前**精确插入 1 个 CPU cycle 的 PPU 等待**，
让 VBL flag 真正可见后再 dispatch NMI。即把 `ppu_rendering.cpp:1570`
的 `if (VBlankON) TriggerNMI();` 改成：

```cpp
// Real hardware: VBL flag (bit 7 of $2002) is set at dot 1 of sl 241.
// NMI is dispatched 1 CPU cycle (= 3 PPU dot) later — the dispatch
// observes the just-set flag and the enabled NMI bit ($2000[7]).
if (VBlankON) {
    runppu(3);  // 1 CPU cycle = 3 PPU dots
    TriggerNMI();
}
```

但**此改动有回归风险**：
- `vbl_01_basics` 当前 PASS，可能依赖 "cycle 0 即派发"
- `vbl_04_nmi_control` 当前 PASS
- `rom_regression_test` + `golden_savestate_test`（Oracle A）
- `vbl_02_set_time` 当前 0x01（VBL set 沿偏晚 1 row），加 3 PPU dot
  后可能仍 FAIL 或可能反向
