## 3. 根因（定案）

1. **硬件**：跳点门控在**被跳 dot 340** 处判定 `PPUMASK&0x18`，$2001 写经 ~1-3 dot 延迟生效（NESdev/联机资料）。Y 写 true dot A=4=337、A=5=338（亚 dot 差 1 dot）→ 有效点 338/339（延迟 1）→ gate 340 下 **A=4 跳、A=5 不跳** → 帧长差 1 dot → 吸收初始 1 dot 相位 → 计数 8,8。
2. **模拟器**：写**立即生效**且**批末量化**（两 sub-test 的写同批末 dot 338，true dot 不可区分）→ 决策(dot 338)看到两写均已生效 → **A=4、A=5 都跳** → 帧长相同 → 初始 1 dot 相位原样传播 → 计数 8,7。
3. **本质**：模拟器跳点门控的"写接受边界"= true-dot ≤ 338，硬件 = ≤ 337（= gate 340 − 2-3 dot 延迟）。差 1 dot。修复需**逐写亚 dot 位置**（写指令在批内的子相位），当前 CPU/PPU 交错模型只到批粒度，**无法表达**。
4. **与 vbl_02/06 同族**：vbl_02/06（读侧量化）与 vbl_10（写侧量化）均为帧边界亚指令级 CPU↔PPU 时序。方案 §3 2026-08-03 评估已定：该类闭合需 CPU/PPU 联合仿真改造，收敛无保证，用户决策"有时间再推进"。
