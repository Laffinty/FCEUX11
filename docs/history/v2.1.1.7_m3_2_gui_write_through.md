## 2. 新增 OAM 写通道

`SPRAM` 在 Rust 引擎下是墓碑，因此 HexEditor 的 OAM 编辑此前是**无效操作**（写进墓碑）。本批补上写通道：

| 层 | 内容 |
|----|------|
| Rust `fceux11-ppu/src/ffi.rs` | `fceux11_ppu_set_oam_byte(state, addr, value)` → `state.oam[addr & 0xFF] = value` |
| root crate `src/lib.rs` | `#[unsafe(no_mangle)] fceux11_ppu_set_oam_byte` wrapper（cbindgen 生成声明） |
| C++ 桥 | `ppu_rust_bridge_write_oam(addr, value)`（+ OFF 分支 stub） |

## 3. 三个 GUI 编辑器的写穿接线

| 文件 | 写入类型 | 接线 |
|------|----------|------|
| `HexEditor.cpp` `writeMem` | CHR（353）、NT（357）、OAM（368） | CHR/NT → `ppu_rust_bridge_note_nt_write(addr)`（该入口重建 CHR+NT 两份窗口副本）；OAM → `ppu_rust_bridge_write_oam`（桥未激活时回落 `SPRAM`） |
| `HexEditor.cpp` `PalettePoke` | palette | `ppu_rust_bridge_note_palette_write()`（文档化 no-op：窗口是 `PALRAM` 活指针，写入本就立即可见，调用只为契约显式化） |
| `ppuViewerContext.cpp` `writeMemPPU` | CHR（110）、NT（114） | 同上（两处 `note_nt_write`） |
| `ppuViewerContext.cpp` `PalettePoke` | palette | `note_palette_write()` |
| `PaletteEditor.cpp` `PalettePoke` | palette | `note_palette_write()` |

修好的既有缺陷：在 Rust 引擎下，HexEditor / PPU Viewer 修改 CHR 或命名表后画面不变（Rust 渲染器读的是窗口副本，而副本只在 `$2007` 写或页指针移动时刷新）。
