## 1. 落地内容

### 1.1 新增 `video_system.rs`（制式常量表）

新模块 `src/rust/crates/fceux11-ppu/src/video_system.rs`：`VideoSystem { Ntsc, Pal, Dendy }` + `VideoSystemTimings` 表 + `from_pal_flag()` / `is_50hz()` / `timings()`。数值取自 plan §B.5 D4.1 的联网核验（Mesen2 主证据、Nestopia UE 旁证）：

| system | scanlines | VBL set | VBL end | dots/frame | dots per CPU cycle | odd-frame skip |
|--------|-----------|---------|---------|------------|--------------------|----------------|
| NTSC | 262 | 241 | 260 | 89342 | 3.0 (3/1) | 是 |
| PAL | 312 | 241 | 310 | 106392 | **3.2 (16/5)** | 否 |
| Dendy | 312 | **291** | 310 | 106392 | 3.0 (3/1) | 否 |

附 6 条 `#[cfg(test)]` 单测：三行数值、`dots_per_frame == scanlines × 341`、只有 PAL 是 3.2 比、`from_pal_flag` 映射。

### 1.2 接线（NTSC 行为不变）

| 文件 | 改动 |
|------|------|
| `lib.rs` | `pub mod video_system;` + 再导出 `VideoSystem` / `VideoSystemTimings` |
| `scheduler.rs` | `set_video_system(&mut self, pal: bool)` → `set_video_system(&mut self, system: VideoSystem)`；`frame_cycles` 改由 `system.timings().dots_per_frame` 驱动；新增 `video_system()` 读取器；`NTSC_CPU_CYCLES_PER_FRAME` / `PAL_CPU_CYCLES_PER_FRAME` 改为从表派生（值不变：89342 / 106392） |
| `ffi.rs` | `StateBox.pal: bool` → `video_system: VideoSystem`；C ABI `fceux11_ppu_set_video_system(state, pal: bool)` **签名不变**，内部走 `VideoSystem::from_pal_flag`；4 处 `sched.set_video_system(sb.pal)` 改传枚举 |

**本批刻意不做**：光栅行数/VBL 行/交错比例仍是 NTSC 路径——分别留给 B.5-2b / B.5-2c。Dendy 暂无 C ABI 表达（`bool` 只有两态），B.5-2b 补。

## 3. 既有问题登记（非本批引入）

`cargo test -p fceux11-ppu` 报 2 条失败，均在 `frame::tests`：

- `nmi_asserted_at_sl_241_dot_1_when_enabled`
- `vbl_suppression_via_sl_240_dot_340_read_blocks_set`

**归因（提交历史证据）**：这两个测试的期望（VBL/NMI 在 `(241, dot 1)`）由 Phase 2 提交 `fb4c6e0` 写入；而 `bb4a9f2`（"A.2 VBL set dot — switch Rust from dot=1 to dot=0"）把实现改成 `sl == 241 && dot == 0` 后**没有同步更新**这两个单测。本批未触碰 `frame.rs`，且改动面（常量派生、枚举字段、调度器签名）不在其调用路径上。

**影响评估**：低——crate 的 `cargo test` 不在 CMake/ctest gate 内（CI 与本地 gate 都跑 `ctest`），且这两个断言与当前实现的一致性是历史遗留问题。**建议**：B.5-2d 收尾时一并修正（改名/改期望到 dot 0），或明确登记为"已知过期单测"。
