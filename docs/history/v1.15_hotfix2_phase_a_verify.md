## 1. Bug fix: `oam_bucket_idx[32][8]` overflow

**File**: `src/ppu_rendering.cpp:1315-1340`

**Symptom**: P0-2's `alignas(64) static uint8 oam_bucket_idx[32][8]` can silently overflow when `FCEUI_DisableSpriteLimitation(1)` raises `maxsprites` from 8 to 64 (ppu_rendering.cpp:687-694) and 9+ sprites on the same scanline share `x >> 3`. The original `oams[2][64][8]` accommodates 64 sprites; P0-2's bucket did not.

**Fix** (1 line):
```diff
-alignas(64) static uint8 oam_bucket_idx[32][8];
+// hotfix2 P0-2 (post-Phase-A review): widen each X-bucket
+// from 8 to 64 sprite slots. …
+alignas(64) static uint8 oam_bucket_idx[32][64];
```

**Why not silent drop (Option A2)**: `ppu_rendering.cpp:1521-1544` deliberately continues past 8 sprites when `maxsprites != 8`; that is the whole purpose of `FCEUI_DisableSpriteLimitation(1)`. Silently dropping at bucket-fill would lose sprites in a supported mode.

**Cost**: +1.75 KiB BSS; zero runtime. `oam_pat_lo[64][8]` / `oam_pat_hi[64][8]` already accommodate 64 sprites per scanline (per-sprite dimension).

## 5. Deviations from plan §11.1 / §10 P0-1 verification

1. **Bug fix added to P0-2**: `oam_bucket_idx[32][64]` instead of `[32][8]`. Necessary because hotfix1's `maxsprites=64` mode (via `FCEUI_DisableSpriteLimitation(1)`) was OOB-writing under unsplit test ROMs; my P0-2 commit did not include this because existing fixtures don't trigger the path.

2. **PP_RENDERING_LUT_TEST CTest PATH-injection OOM fixed manually**: `tests/CMakeLists.txt:383-395` lists tests receiving `ENVIRONMENT_MODIFICATION` for vcpkg PATH. `ppu_rendering_lut_test` is registered at lines 275-283 but omitted from the injection list — verified in `build-asan/tests/CTestTestfile.cmake:51`. The `ctest` run got a 0 from this test thanks to the framework's PATH already carrying the vcpkg DLLs (or the test wouldn't have run at all); I ran it manually with explicit PATH for absolute certainty in `scripts/run_asan_p0_tests.bat`. **Follow-up issue**: 1-line patch to `tests/CMakeLists.txt:383-395` to add `ppu_rendering_lut_test` to the property list.

3. **UBSan integer**: deferred — MSVC toolchain substitute only covers `/RTC1`. Recommend a clang-cl / WSL Linux route for future UB coverage.

4. **`tests/golden/pputile.inc`**: my `src/pputile_template.h:7-20` comments imply a golden copy of `pputile.inc` was preserved at `tests/golden/pputile.inc` per plan §10 P0-3. The directory does not exist (only `tests/fixtures/golden_frames/` and `tests/fixtures/golden_wav/` and `tests/fixtures/golden_mapper/`). The original `src/pputile.inc` is still present at its original location and uncommitted. Recommend either deleting the misleading doc comment or actually copying the file when P0-3 dispatcher substitution resumes.
