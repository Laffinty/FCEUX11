```cpp
void FCEUPPU_LineUpdate(void) {
	// Rust PPU engine: no-op. The renderer consumes the CHR / NT window
	// copies that ppu_rust_bridge.cpp re-installs at scanline granularity,
	// so a mid-line bank switch needs no flush.

```

## 2. 探针证据（plan B.2 验收项）

插桩旧实现（只在 flush 分支打一行、并记录首个调用），跑三类代表性 gate：

| 测试 | 覆盖 | 输出 |
|------|------|------|
| `ppu_frame_diff_test` | nrom/mmc1/mmc3/mmc5/vrc6 帧对比 | `B2PROBE first call: newppu=0 Pline=0000000000000000`，无 FIRED 行 |
| `rom_regression_rust_smoke` | 780 帧（nestest / 003.smb 等） | 同上 |
| `mapper_mmc3_byte_diff` | MMC3 CHR bank 切换 | 同上 |

结论：函数确实被调用（首个调用行即证据），`newppu=0` 所以没有走早退分支，但 `Pline` 恒为 0，flush 体（`RefreshLine(GETLASTPIXEL)`）从未执行。因此删除调用点、把定义改成空实现，是行为等价的。

`Pline` 的三个写点（`ppu_rendering.cpp` 的 `ResetRL` / `DoLine` / `EndRL`）全部属于已退役的 C++ 渲染管线，Rust 引擎不会进入。

## 4. 与 plan 的偏差 / 遗留

- plan §B.2 的调用点清单是 6+1 处（引擎外）；本批把已退役 C++ 引擎内部的 9 处（`ppu.cpp` 8 + `ResetRL` 1）也删了。理由：空实现让它们等价于死调用，而验收要求 `rg` 只剩空实现与注释；删掉后 `ppu.cpp` 的改动是纯删行（0/8），可单独 review。
- 副作用（已评估、接受）：`FCEUX11_RUST_PPU=OFF` 的兼容壳里，旧 C++ 管线失去 mid-line flush。该构建不在产品路径（§0.5），且 Step C 会把它变成 configure error。
- 符号本身留到 Step C：它已无调用者，只有 `ppu.h` 的声明 + `ppu_shared.cpp` 的空定义。
