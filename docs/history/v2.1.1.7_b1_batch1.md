## 1. 落地内容

### 1.1 两条新 FFI

`src/rust/crates/fceux11-ppu/src/ffi.rs` 新增 2 条 C-ABI 出口，都往返 272 B 字节块（host little-endian）：

```rust
pub const STATE_BLOCK_SIZE: usize = 272;

#[unsafe(no_mangle)]
pub unsafe extern "C" fn fceux11_ppu_state_block_export(
    state: *mut PpuState,
    out: *mut u8,
    len: u32,
) -> i32;

#[unsafe(no_mangle)]
pub unsafe extern "C" fn fceux11_ppu_state_block_apply(
    state: *mut PpuState,
    buf: *const u8,
    len: u32,
) -> i32;
```

### 1.2 字节块布局（272 B）

| 偏移 | 大小 | 字段 | 来源 |
|------|------|------|------|
| 0..4 | 4 | `regs[4]`（ctrl, mask, status, oam_addr） | `registers` |
| 4..260 | 256 | `oam[256]` | 主 OAM |
| 260..261 | 1 | `write_toggle`（bool as u8） | `registers` |
| 261..262 | 1 | `vram_buffer` | `registers` |
| 262..263 | 1 | `fine_x` | `registers` |
| 263..264 | 1 | `data_bus`（open-bus 缓冲） | `registers` |
| 264..266 | 2 | `v`（u16 LE） | `registers` |
| 266..268 | 2 | `t`（u16 LE） | `registers` |
| 268..270 | 2 | `scanline`（i16 LE） | 进展 |
| 270..272 | 2 | `dot`（u16 LE） | 进展 |

设计决策：**主机小端**与 `2 | FCEUSTATE_RLSB` SFORMAT 在 MSVC/x86-64 上的语义一致（RLSB swap 是 no-op，见 `src/state.cpp:172-188`）。未来补 cross-endian 时只需在 C++ 侧加 swap，Rust 侧不动。

### 1.3 返回值约定

`0` 成功；`-1` 参数错（null 指针或 `len != STATE_BLOCK_SIZE`）。C++ 侧在 `ppu_bridge_state.cpp` （B.1 第二批）中会检查返回值并记 log，在 release 上不崩。

### 1.4 build.rs cbindgen manual append

`src/rust/build.rs` 在 cbindgen 0.29.3 输出后手动追加 2 条 C 声明。原因：

- Rust 2024 法规中 `pub unsafe extern "C" fn` 为 deprecated 语法，必须写 `pub unsafe extern "C" fn` 后加 `#[unsafe(no_mangle)]`（Rust 2024 strict mode）或者采用新形式 `unsafe extern "C" fn`。
- cbindgen 0.29.3 还不能正确识别 Rust 2024 strict 下的 `pub unsafe extern "C" fn`，会在生成的 `fceux11_rust.h` 中跳过该函数，导致 C++ 端 include 后报未定义符号。
- 解决方案：保留 cbindgen 生成路径不动，在 `build.rs` 中读取 `fceux11_rust.h`、检测是否已包含该 2 条声明，若否则追加。为了避免与未来 cbindgen 升级不干净，手动追加区段包含了 `if !defined FCEUX11_PPU_STATE_BLOCK_DEFINED` 保护。

## 2. 过程中事故

### 2.1 cbindgen 跳过 `pub unsafe extern "C" fn`

发现路径：第一次 build 后，`fceux11_rust.h` 中仅含 fceux11-ppu 原 9 条 FFI，新增 2 条不在列。

调查：minimal repro 在 cbindgen issue tracker 上不是未知 bug（0.29.3 以后版本会补），但 FCEUX11 在依赖锁 `cbindgen = "0.29.3"` 下需要手动补。

修复：上述 1.4 的 `build.rs` manual append 区段。以后 cbindgen 升级到 0.30+ 后可删除该区段。

### 2.2 `fceux11_rust.h` rerun 问题

`src/rust/CMakeLists.txt` 使用 `file(GLOB_RECURSE src/*.rs)` 监控 Rust 源码，但 `build.rs` 不在该模式中。本次提交后 build 中 cargo 仍能正常跳 cbindgen rerun（原因：`add_custom_command` 语句明确依赖 `${RUST_STATIC_LIB}`，而 cbindgen header 是 `add_custom_command` 的 OUTPUT）。

未来 B.1 第二批 C++ 端 include 新声明时，如果 cmake 未检测到 cbindgen 需要 rerun，会报未定义符号。二批需提前验证 `fceux11_rust.h` 中是否包含该 2 条，否则需手动 `touch build.rs`。

### 2.3 PowerShell 5.1 `[IO.File]::WriteAllText` 写入 UTF-8 默认带 BOM

本次未发生（使用 Python 写文件避开了），但下次如果用 PowerShell 写文件记录需要 `New-Object System.Text.UTF8Encoding($false)`。
