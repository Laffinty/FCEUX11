## 五、phase 切分（关键：避免 AI agent 注意力溢出）

### 5.1 切分原则

1. **每 phase PR 数 ≤ 6**（hotfix2 Phase B 7 PR 实测已接近上限）
2. **每 PR 文件改动 ≤ 5、单 PR 代码净增 ≤ 150 行**
3. **每 phase 风险类目单一**：崩溃 / 性能 / 清理不混在同一 phase
4. **phase 间依赖显式**：先修崩溃后修性能

### 5.2 切分结果

| Phase | 主题 | PR 数 | 比例 | 主要内容 |
|-------|------|------|------|---------|

- **Phase A (5 PR)**: A-1+A-2（合并 Lua）, A-3（nes_shm）, A-4（Qt 析构）, A-5（mutex atomic）, A-6（movie name）

## 附录 A：CRITICAL 项完整描述

### A.1 RUST-CRASH-01: Lua 引擎裸指针并发 UB

**文件**: `src/rust/crates/fceux11-lua/src/lib.rs:27-33`

```rust
static LUA_ENGINE_PTR: AtomicPtr<c_void> = AtomicPtr::new(std::ptr::null_mut());
fn get_engine<'a>() -> Option<&'a mut LuaEngine> {
    let raw = LUA_ENGINE_PTR.load(Ordering::Acquire) as *mut LuaEngine;
    unsafe { raw.as_mut() }
}
```

**问题**: 把裸指针直接转 `&mut LuaEngine`，**无同步原语**。Emulator 线程与 GUI 线程并发调用 FFI 时可同时拿到两个 `&mut` → Stacked Borrow UB。

**修复**: 用 `Mutex<Box<LuaEngine>>` 替换。

### A.2 RUST-CRASH-02: Lua 引擎无析构

**文件**: `src/rust/crates/fceux11-lua/src/lib.rs:516-532`

```rust
LUA_ENGINE_PTR.store(Box::into_raw(boxed) as *mut c_void, Ordering::Release);
```

**问题**: `Box::into_raw` 后**无对应 `Box::from_raw`**，两次 init 覆盖指针，前一个 `LuaEngine`（含 `mlua::Lua` Registry 中注册的 callback）永久泄漏。

**修复**: 提供 `fceux11_lua_shutdown` 配对 FFI。

### A.3 QT-CRASH-01: nes_shm 剩余字段非原子

**文件**: `src/drivers/Qt/nes_shm.h:26-37, 51-55`

```cpp
struct { int ncol; int nrow; int pitch; int xscale; int yscale; int xyRatio; int preScaler; int test; } video;
uint32_t render_count;
uint32_t blit_count;
int pid;
int run;
```

**问题**: hotfix1 P1-12 修了 `runEmulator`/`blitUpdated`/`pixBufIdx`，但 `video.*` 等仍非原子。Emulator 写 + GUI 同帧读 → torn read + reordering → 错位/闪屏。

**修复**: 升 `std::atomic<int>` + 逐路径 `.load()`/`.store()`。

### A.4 QT-CRASH-03: fceuWrapperLock 在析构路径 UAF

**文件**: `src/drivers/Qt/ConsoleWindow.cpp:350`、`fceuWrapper.cpp:1186-1195`

```cpp
// ConsoleWindow.cpp dtor (当前):
delete mutex;     // 没等 emulatorThread
```

**问题**: non-closeApp 析构路径未等 emulatorThread → emulator 仍在 `fceuWrapperTryLock` → mutex 已 delete → UAF。

**修复**: dtor 中先 `requestInterruption()` + `wait(5000)` + `terminate()` 兜底，再 `delete mutex`。

### A.5 LUA-CRASH-02: movie get_name / get_filename 共享 static

**文件**: `src/lua-engine.cpp:612-627`

```cpp
const char* fceux11_lua_movie_get_name() {
    static std::string name;     // ← 共享
    name = fceu11::GetMovieName();
    return name.c_str();
}
const char* fceux11_lua_movie_get_filename() {
    static std::string name;     // ← 共享
    name = fceu11::GetMovieName();
    // ...
}
```

**问题**: 两个函数共享同一 static `name`。Rust 端连续调用 → 第二次赋值覆盖第一次的 `c_str()` → UAF。

**修复**: 改 thread_local 或返回 strdup 副本。

## 附录 B：phase 切分的"AI agent 注意力窗口"分析

> 此节专门解释为何切分 5 phase 而非 3 phase 或 7 phase。

### B.1 上限推导

实测在类似规模代码库上，单个 AI agent 在一次完整 session 中：
- 可阅读 ~3000 行新代码并形成完整 mental model
- 可产出 5-7 个独立 PR（含 build + test + fix 迭代）
- 单 PR 超过 ~150 行净增时，agent 容易遗漏 corner case
- 单 phase 超过 ~4000 行 diff 时，agent 容易在尾部 PR 出现 regression

### B.2 hotfix2 经验

hotfix2 Phase B 7 PR 是上限边界：
- P1-1 ~ P1-7 7 个微结构 PR
- 单 PR 平均 ~80 行净增
- Phase 总 diff ~600 行
- 报告（`docs/history/v1.15_hotfix2_phase_b.md`）显示编译验证通过，但 reviewer 反馈"接近注意力窗口"

### B.3 hotfix3 选择 5 phase / 26 PR

| Phase | PR 数 | 单 PR 平均行净增 | Phase 总 diff |
|-------|------|----------------|--------------|
| A | 5 | ~50 | ~250 |
| B | 6 | ~50 | ~300 |
| C | 5 | ~30 | ~150 |
| D | 5 | ~80 | ~400 |
| E | 5 | ~10 | ~50 |
| 合计 | 26 | ~45 | ~1150 |

每 phase 都**严格低于** hotfix2 Phase B 的 600 行上限。Phase D 最重（400 行），但每 PR 仍是机械式重构（无新算法），AI agent 可分 5 步独立完成。

### B.4 触发 phase 二次拆分的条件

任一 phase 出现以下情况即触发拆分：
1. PR 数 > 6
2. 单 PR 文件改动 > 5
3. 单 PR 代码净增 > 200 行
