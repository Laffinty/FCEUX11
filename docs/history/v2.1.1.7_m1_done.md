## 2. 过程中 4 个事故与修复

### 2.1 PowerShell `[IO.File]::ReadAllText` 静默 LF->CRLF 转换

- 现象：第一波 build/ctest 全过；git status clean；但 `git diff --cached` 显示 src/ppu_class.h 等 5 个文件 +2616/-2659 巨大变更，全是 line ending 转换
- 根因：PowerShell 5.1 的 `[IO.File]::ReadAllText` 即使指定 `UTF8Encoding(no BOM)` 也强制把 LF 标准化为 CRLF
- 修复：normalize 5 个文件（.NET 字符串 Replace CRLF -> LF），写回去；最终 diff 干净为 43/0
- 教训：PowerShell .NET 文本 API 在 Windows 上不保留 raw line ending；改文件用 .NET 时必须 explicit normalize

### 2.2 `ppu_rust_bridge.cpp` UTF-8 BOM 丢失

- 现象：`WriteAllText(UTF8Encoding(no BOM))` 去掉了原文件 UTF-8 BOM
- 修复：从 git index 拿到 BOM 字节 `EF BB BF` 重新 pre-pend
- 教训：no-BOM encoding 写文件会丢原 BOM；改有 BOM 的源文件必须 explicit preserve

### 2.3 `.gitignore` 误清空

- 现象：`WriteAllText(path, orig_text)` 时如果路径不存在或 `Replace` 3 参版本不存在时静默返回原值，导致写空字符串
- 修复：立即 `git checkout HEAD -- .gitignore` 恢复；第二次用 `IndexOf + Substring` 显式 build new text
- 教训：PowerShell .NET `String.Replace` 不支持 3 参 `(old, new, count)` 重载

### 2.4 Bash 工具 5 min 硬 cap 砍 build

- 现象：`do_build.ps1` 单次跑要 8-12 min（cargo + 全量 C++ + 14 个 test exe 链接 + ctest），bash 工具 hard cap 300s 把子进程砍了
- 修复：第二次跑用 `run_in_background: true` + 显式 timeout 1800s 跑通
- 教训：长跑 build 必须 background + 长 timeout；不要 front-run 5 min
