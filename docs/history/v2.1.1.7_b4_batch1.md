## 1. 落地内容

### 1.1 新增 7 个 accessor（`ppu_rust_bridge.h` / `ppu_rust_bridge.cpp`）

```cpp
uint8_t  ppu_rust_bridge_get_register(uint32_t idx);   // 0..3 -> ctrl/mask/status/oam_addr
uint8_t  ppu_rust_bridge_get_oam(uint32_t addr);       // $2004 语义（addr & 0xFF）
int16_t  ppu_rust_bridge_get_scanline();
uint16_t ppu_rust_bridge_get_dot();
uint16_t ppu_rust_bridge_get_v();                      // NES v / FCEUX RefreshAddr
void     ppu_rust_bridge_note_nt_write(uint32_t ppu_addr);
void     ppu_rust_bridge_note_palette_write();
```

`FCEUX11_RUST_PPU=OFF` 分支同步补了 7 个 inline stub（返回 0 / 空实现），保证关闭选项时的兼容壳仍能编译。

### 1.2 实现选择（与 plan §B.4 草稿的三处偏差，已在 plan 内同步）

| 项 | 实现 | 理由 |
|----|------|------|
| `get_register` / `get_scanline` / `get_dot` | 直接映射既有 FFI `fceux11_ppu_get_register_state` / `_get_scanline` / `_get_dot` | 零新增 FFI 面 |
| `get_v`（**实现期新增的第 7 个**） | 映射既有 `fceux11_ppu_get_v_state` | plan §B.4 验收点名 `FCEUPPU_PeekAddress` 走 accessor，而 `PeekAddress` 的语义就是 NES `v`；不新增这条就只能保留墓碑读 |
| `get_oam` | 调 `bridge_state_refresh_from_rust()` 后取 `bridge_oam[addr & 0xFF]` | Rust 侧无逐字节 OAM 查询 FFI；复用 B.1 的 state-block export 让块布局只有一处定义（代价：每次读一次 272 B 导出，仅调试路径） |
| `note_nt_write` | `bridge_refresh_windows()` 全量重建 + TODO 指向 B.3a | 契约先落地；页粒度刷新属 B.3a（度量前置，plan §B.3） |
| `note_palette_write` | **文档化 no-op** | palette 窗口是 `PALRAM` 活指针，Rust 渲染器直接解引用，写入无需拷贝；保留入口供 Step D 调用点统一写穿 |

线程约束写进了实现注释：这些 accessor 从 GUI/debug 线程调用（暂停态或帧间），**不得**在 Rust 调度器回调内调用（`StateBox` 借用被持有）。

### 1.3 本批无调用者

除头文件/实现本身外零调用点，因此行为零变化、无需 golden regen。消费者接线（`debug.cpp` / `ConsoleDebugger` / `ppuViewerContext` / `NameTableViewer` / `FCEUPPU_PeekAddress`）留给 B.4-2。

## 3. 环境注意（本次踩到，接手必读）

- **必须在映射盘 `Z:` 下运行构建**。从 UNC 工作目录（`\\172.16.1.253\...`）跑 `do_build.ps1` 会在 `cmake --build` 阶段失败：生成的规则用 `cmd /C "cd /D \\...` ，而 `cmd.exe` 不支持 UNC 当前目录，表现为 i18n `.qm` 生成、Rust crate 构建、autogen 全部 `FAILED`。改到 `Z:\Project\FCEUX11` 后同一命令直接通过。
- 该次失败的 configure 会把 `build-rust-ppu` 的缓存写成 UNC 路径；**在 `Z:` 下重跑一次 `do_build.ps1` 即可自愈**（脚本每次都重新 configure，会重写为 `Z:` 路径），但会触发一次全量重建（1054 target，本次约 13 分钟）。
- `$env:VCPKG_ROOT` 在本会话为空，脚本回落到 `vcpkg_installed\x64-windows`（`CMAKE_PREFIX_PATH`），configure 正常——但 `CMAKE_TOOLCHAIN_FILE` 不会被注入。
