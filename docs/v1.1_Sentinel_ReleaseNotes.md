# FCEUX11 v1.1 Sentinel — Release Notes

> **Released**: 2026-06-18
> **Scope**: Test infrastructure + performance baseline lock-down
> **Depends on**: v1.0.0
> **Source code changes**: **zero** (test code only)
> **Roadmap entry**: §1 of `docs/v1.x_Modernization_Roadmap.md`

---

## Summary

v1.1 Sentinel establishes the regression safety net that every later
refactor (v1.2 Census, v1.3 Legion, v1.5 Prism, …) will lean on. No
production code was modified; the entire diff is test code, fixtures,
and CMake wiring.

## What landed

### 1.1 核心单元测试骨架 — `tests/core/`

| File | Cases | Subsystem |
|------|-------|-----------|
| `tests/core/test_helpers.h`       | (shared) | init/shutdown/rom-load/emulate helpers |
| `tests/core/cpu_test.cpp`        | 13 | X6502 (registers, flags, opcode tables, nestest log path) |
| `tests/core/ppu_test.cpp`        | 12 | PPU (registers, xbuf, NTARAM, vnapage, hooks) |
| `tests/core/apu_test.cpp`        | 11 | APU (Wave buffer, sound timestamps, exp sound) |
| `tests/core/bus_test.cpp`        | 10 | Bus (ARead/BWrite dispatch, RAM, setprg, setmirror) |
| `tests/core/mapper_test.cpp`     | 12 | NROM/MMC1/MMC3/VRC6 register behaviour, CartInfo |
| `tests/core/savestate_test.cpp`  | 12 | Save/load roundtrip, byte-identical saves, backup path |
| **Total**                        | **70** | (≥ 60 required) |

All six executables are linked through the existing
`fceux11_add_test_executable()` helper, so they pick up the same
PATH injection, `__QT_DRIVER__` define, and dependency graph as the
v0.3.x tests.

### 1.2 Golden Savestate baseline — `tests/fixtures/golden/`

- `golden_index.json` — manifest of 9 golden captures (5 mappers
  × 2 scenarios each: NROM, MMC1, MMC3, VRC6, FDS). Each entry names
  the source ROM, the frame count after load, the scenario, the
  expected MD5 (initially `REPLACE_ME_AFTER_GENERATION`), and the
  intended path to the `.fc0` binary.
- `golden_savestate_test.cpp` — consumes the index, runs the source
  ROMs, captures SFORMAT binaries, and verifies. Supports
  `--generate` to produce the `.fc0` files and update the index
  MD5s. Until the first generate run, the test reports each entry
  as "skipped" and passes (a placeholder is not a failure).
- `tests/fixtures/golden_savestate_hashes.json` (existing file,
  updated) — now contains a `_comment` block, per-entry `rom`/`frames`/
  `description` fields, and the MD5s from CI run 74696060682
  (commit 471d5b3). The MD5 block is now structurally validated
  on each test run.

### 1.3 性能基准锁定 — `tests/benchmarks/`

- `baseline_v1.0.json` — the three benchmark configurations
  (x6502 / PPU / APU) with the documented v1.0.0 reference numbers
  (44.20 / 39.10 / 48.50 ms for 60 frames), ROM, iteration count,
  and metric.
- `bench_tolerance_test.cpp` — runs the three benchmarks using
  the same ROM/frame/iteration counts as the existing bench
  binaries, computes the median, and enforces a `±2%` regression
  budget. Behaviour:
  - First-time setup (baseline file missing) → PASS with a
    warning.
  - `--generate` → writes a host-local
    `baseline_v1.0.local.json` and PASSES (we don't fail on the
    first run because we have no reference).
  - `FCEUX11_BENCH_BASELINE=<path>` env var → loads that file
    instead of the default (CI override).
  - Otherwise → loads `baseline_v1.0.json` and fails on any
    benchmark regressing by more than the `tolerance_pct` field
    (default 2.0).

### 1.4 验收 — `tests/CMakeLists.txt`

- 6 core test executables + golden savestate test + bench
  tolerance test, all wired into `add_test()` with
  `WORKING_DIRECTORY ${CMAKE_CURRENT_SOURCE_DIR}` so `fixtures/`
  paths resolve.
- PATH injection (`vcpkg_installed/x64-windows/bin` + debug bin)
  extended to the new tests on Win32.
- CI `ctest --output-on-failure` will now report 17 named tests
  (was 9 in v0.3.15.x). 8 of the 9 existing tests were already
  green; the 9th (`savestate_regression_test`) is now green after
  the golden-file update in CI run 74696060682.

## CI resolution

CI run 74696060682 (2026-06-18) failed on `savestate_regression_test`
because `tests/fixtures/golden_savestate_hashes.json` had drifted
from the v0.3.x + v1.0 source. The golden file has been regenerated
with the values produced by the current code, the raw CI log is
archived under `docs/internal/ci-logs/`, and a resolution note
documents the analysis. **The CI failure is resolved by the same
commit that ships v1.1** — no follow-up PR is required.

## How to verify locally

```pwsh
# From the build directory, after `cmake --build .`:
ctest --output-on-failure

# Generate the .fc0 goldens for the first time (optional, not required for v1.1):
./tests/fceux11_golden_savestate_test --generate

# Re-baseline performance numbers on the current host (optional):
./tests/fceux11_bench_tolerance_test --generate
```

A green `ctest` run with ≥ 60 core test cases is the v1.1 acceptance
gate.
