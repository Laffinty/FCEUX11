# v1.6 Resonance 构建计划方案

> **基线版本**：v1.5 Prism（commit `117e4f1`，2026-06-27）
> **依赖**：`docs/v1.x_Modernization_Roadmap.md` §6 v1.6 Resonance
> **目标**：将 APU/声音系统全局状态封装为 `fceu11::Apu` 类；引入 `fceu11::ExpansionAudio` 虚基类替代 `EXPSOUND` 函数指针；完成 Rust FIR 音频后端的收尾清理
> **范围**：本方案覆盖 v1.6 启动所需的全部设计决策、迁移顺序、性能预算、验收清单
> **方法**：基于 Roadmap §6 拆解为可独立测试的子任务，每个子任务单独 commit/合入；不与 §7~§14 冲突
> **本文档状态**：方案（plan），未在本文档中直接修改源码

## 1. `fceu11::Apu` 类设计

### 1.1 类布局

### 1.2 与 Ppu / Cpu / Bus 类的一致性原则

- **直接 global**：`fceu11::g_apu` 与 `g_cpu` / `g_bus` / `g_ppu` 保持一致模式
- **`__forceinline` accessor**：热路径（`sound_cpu_hook` 内部使用）不通过 getter，直接访问 `g_apu.member_` 或 reference alias
- **生命周期**：`init()` / `power()` / `reset()` 对应 `FCEUI_Initialize` / `PowerNES` / `ResetNES` 调用点
- **savestate**：提供 `save_state` / `load_state`，但 v1.6 仍通过 `FCEUSND_STATEINFO` SFORMAT 表保持 v1.5 二进制兼容

### 1.3 与 v1.0 兼容：sound globals 的特殊处理

v1.5 PPU 采用 `extern T (&NAME)[N]` reference-to-storage alias 模式，v1.6 沿用：

```cpp
// src/sound.h 兼容层（Phase B 新增）
#include "apu.h"

extern int32 (&Wave)[2048 + 512];
extern int32 (&WaveFinal)[2048 + 512];
extern int32* WaveHi;                 // 原声明为 int32 WaveHi[]，需小心处理
extern uint32& soundtsoffs;
extern uint32& soundtsinc;
// ... 其他核心全局
```

**约束**：
- 兼容别名在 v1.6 内必须保留，供 `x6502.cpp` / `state.cpp` / `filter.cpp` / board 文件继续编译
- 别名目标指向 `g_apu` 成员字段，所以任何写入都会同步到 `g_apu`
- `WaveHi` 原声明为 `extern int32 WaveHi[]`（不完整数组类型），不能直接做 reference alias。方案：改为完整数组 `extern int32 (&WaveHi)[40000]`，或保留旧声明但提供 `int32* WaveHi` 指针别名。推荐前者（v1.6 内统一改为 `extern int32 (&WaveHi)[40000]`）。

### 1.4 性能预算的 inline 决策

| 路径 | 策略 |
|------|------|
| `FCEU_SoundCPUHook`（每 CPU 周期） | 保持为自由函数或 `Apu` 的 `__forceinline` 方法；内部访问通过 `g_apu` 直接成员或 reference alias，不引入虚函数 / getter |
| `FlushEmulateSound`（每帧） | 可改为 `Apu::flush_emulate_sound()`；非热路径，普通 inline 即可 |
| `ExpansionAudio::fill/hi_fill`（每帧，有扩展芯片时） | 虚函数可接受（调用频率远低于 CPU 周期），但 Phase D 仅做适配，不激活虚路径 |
| `GetSoundBuffer` / `SetSoundVariables` | 普通成员方法 |

## 2. 核心 APU 状态迁移（Phase C）

### 2.1 迁移清单

`src/sound.cpp` 当前全局变量分类：

| 类别 | 变量 | 迁入 Apu 字段 | 批次 |
|------|------|--------------|------|
| 输出缓冲 | `Wave`, `WaveFinal`, `WaveHi` | `wave_`, `wave_final_`, `wave_hi_` | C1 |
| 定时 / 重采样 | `soundtsinc`, `soundtsoffs`, `soundtsi`, `nesincsize`, `swapDuty` | `soundtsinc_`, `soundtsoffs_`, `soundtsi_`, `nesincsize_`, `swap_duty_` | C1 |
| 通道寄存器 | `PSG[0x10]`, `EnabledChannels`, `IRQFrameMode`, `nreg` | `psg_`, `enabled_channels_`, `irq_frame_mode_`, `nreg_` | C2 |
| 包络 / 长度 | `EnvUnits[3]`, `lengthcount[4]`, `TriCount`, `TriMode`, `tristep`, `wlcount[4]` | `env_units_`, `lengthcount_`, `tri_count_`, `tri_mode_`, `tristep_`, `wlcount_` | C2 |
| 方波 | `RectDutyCount[2]`, `sweepon[2]`, `curfreq[2]`, `SweepCount[2]`, `SweepReload[2]`, `sqacc[2]` | 对应 `_` 后缀字段 | C2 |

| 函数指针分发 | `DoNoise`, `DoTriangle`, `DoPCM`, `DoSQ1`, `DoSQ2` | **不迁**，保持 `static`（内部实现细节） | — |

**合入顺序**：批次 C1 → 批次 C2。每个批次 1 个 commit，commit message 显式标注 "v1.6 §2 批次 N/2"。

### 2.2 SFORMAT 兼容性

v1.5 的 `FCEUSND_STATEINFO` 表（`src/sound.cpp:1312`）通过变量地址注册 savestate chunk。迁入 `Apu` 后，必须保持：

1. **chunk 名不变**（如 `"FHCN"`, `"PSG"`, `"RWDA"` 等）
2. **每个 chunk 的字节数和顺序不变**
3. **总字节布局不变**

实现方式：将 `FCEUSND_STATEINFO` 迁移到 `src/apu.cpp`（或保留在 `src/sound.cpp` 但指向 `g_apu.member_`）：

```cpp
// src/apu.cpp
SFORMAT FCEUSND_STATEINFO[] = {
    { &g_apu.fhcnt_, 4 | FCEUSTATE_RLSB, "FHCN" },
    { &g_apu.fcnt_, 1, "FCNT" },
    { g_apu.psg_, 0x10, "PSG" },
    // ... 其余字段一一对应
    { 0 }
};
```

**验收**：`savestate_regression_test` / `golden_savestate_test` 字节级一致。

### 2.3 `FCEU_SoundCPUHook` 热路径

当前 `src/x6502.cpp:533` 调用 `FCEU_SoundCPUHook(temp)`，属于 CPU 热路径。

Phase C 方案：
- 保留自由函数 `FCEU_SoundCPUHook(int cycles)` 作为 ABI 兼容入口
- 内部转发到 `g_apu.sound_cpu_hook(cycles)`
- `sound_cpu_hook` 标记 `__forceinline`，内部直接访问 `g_apu` 成员（或 reference alias）

禁止：在 `x6502.cpp` 中直接调用 `g_apu.sound_cpu_hook()`（会改变 x6502.cpp 的 include 图与链接布局）。保持 `x6502.cpp` 只 `#include "sound.h"`，由 `sound.h` 提供 `FCEU_SoundCPUHook` 前向声明。

## 3. `ExpansionAudio` 抽象与适配器（Phase D）

### 3.1 当前 `EXPSOUND` 结构

```cpp
// src/sound.h:24
typedef struct {
    void (*Fill)(int Count);           // LQ
    void (*NeoFill)(int32 *Wave, int Count);
    void (*HiFill)(void);
    void (*HiSync)(int32 ts);
    void (*RChange)(void);
    void (*Kill)(void);
} EXPSOUND;

extern EXPSOUND GameExpSound;
```

当前 board 文件直接给 `GameExpSound` 的函数指针赋值：
- `src/boards/vrc6.cpp`: Fill / HiFill / HiSync / RChange
- `src/boards/vrc7.cpp`: RChange / Kill / Fill / NeoFill
- `src/boards/mmc5.cpp`: Fill / HiFill / RChange / HiSync
- `src/boards/n106.cpp`: Fill / HiFill / HiSync / RChange
- `src/boards/69.cpp`: Fill / HiFill / HiSync / RChange
- `src/fds.cpp`: HiSync / HiFill / Fill / RChange

### 3.2 `fceu11::ExpansionAudio` 虚基类

```cpp
// src/expansion_audio.h
#ifndef FCEU11_EXPANSION_AUDIO_H
#define FCEU11_EXPANSION_AUDIO_H

#include <cstdint>
#include <cstddef>

namespace fceu11 {

class ExpansionAudio {
public:
    virtual ~ExpansionAudio() = default;

    virtual void fill(int32_t count) = 0;                     // LQ: 原 Fill
    virtual void hi_fill() = 0;                               // 原 HiFill
    virtual void hi_sync(int32_t ts) = 0;                     // 原 HiSync
    virtual void region_changed() = 0;                        // 原 RChange
    virtual void kill() = 0;                                  // 原 Kill

    // NeoFill 是 VRC7 专用，为保持基类最小化，使用可选接口：
    virtual void neo_fill(int32_t* wave, int32_t count) {}    // 默认空实现
};

} // namespace fceu11
#endif
```

**设计要点**：
- `ExpansionAudio` 仅用于扩展音频路径，调用频率为每帧，不是 CPU 周期级，虚函数开销可接受
- `neo_fill` 提供默认空实现，避免所有子类被迫实现 VRC7 专用逻辑

### 3.3 `EXPSOUND` 适配器

v1.6 不改动 board 文件，而是把 `EXPSOUND` 改为内部持有 `ExpansionAudio*` 的适配器：

```cpp
// src/sound.h（Phase D）
typedef struct {
    // v1.6: 函数指针保留为 ABI，但内部优先走 expansion 对象
    void (*Fill)(int Count);
    void (*NeoFill)(int32 *Wave, int Count);
    void (*HiFill)(void);
    void (*HiSync)(int32 ts);
    void (*RChange)(void);
    void (*Kill)(void);

    // v1.6 新增：指向 C++ 子类对象的指针，board 文件可选择性设置
    fceu11::ExpansionAudio* expansion;
} EXPSOUND;
```

`Apu::set_exp_sound(const EXPSOUND& exp)` 保存传入的函数指针和 `expansion` 指针。

`FlushEmulateSound` 调用顺序（Phase D）：
1. 若 `expansion != nullptr`，优先调用 `expansion->hi_fill()` / `expansion->fill()` 等
2. 否则回退到原函数指针路径（保持 board 文件现有逻辑不变）

### 3.4 与 board 文件的边界

| 范围 | v1.6 处理 | v1.8 处理 |
|------|----------|----------|
| `ExpansionAudio` 接口定义 | ✅ | 沿用 |
| `EXPSOUND` 适配器 | ✅ | 沿用 |
| VRC6/VRC7/FDS/MMC5/Namco163/Sunsoft5B 子类化 | 仅 VRC6 PoC（Phase E） | 批量完成 |
| board 文件函数指针赋值 → 子类实例 | 仅 VRC6 | 全部 |

**原则**：v1.6 不批量改动 `src/boards/*.cpp`，避免与 v1.8 范围冲突。

## 4. 扩展芯片子类化 PoC（Phase E）

### 4.1 选择 VRC6 作为 PoC 的原因

- `src/boards/vrc6.cpp` 相对简单（~340 行）
- 已提供 `VRC6Sound`, `VRC6SoundHQ`, `VRC6SyncHQ`, `VRC6_ESI` 四个函数
- 无 `Kill` / `NeoFill` 特殊路径，覆盖 `ExpansionAudio` 基础接口

### 4.2 PoC 实现

```cpp
// src/boards/vrc6.cpp（Phase E 局部改动）
#include "expansion_audio.h"

namespace fceu11 {
class Vrc6Audio : public ExpansionAudio {
public:
    void fill(int32_t count) override { VRC6Sound(count); }
    void hi_fill() override { VRC6SoundHQ(); }
    void hi_sync(int32_t ts) override { VRC6SyncHQ(ts); }
    void region_changed() override { VRC6_ESI(); }
    void kill() override {}
};
}
```

在 `VRC6_ESI`（初始化）中：

```cpp
static fceu11::Vrc6Audio g_vrc6_audio;

void VRC6_ESI() {
    // ... 原有初始化 ...
    EXPSOUND es = {};
    es.expansion = &g_vrc6_audio;
    GameExpSound = es;
}
```

这样 `FlushEmulateSound` 优先走 `expansion->hi_fill()`，不再调用函数指针。

### 4.3 验收

- VRC6 ROM（Akumajou Densetsu）音频输出与 v1.5 WAV golden 采样级一致
- `bench_full_frame` 不触发回归（虚函数调用频率低）

## 6. 音频回归测试

### 6.1 测试目标

v1.6 没有 PPU 那样的像素级对比测试，需要新增**音频 WAV 采样级对比测试**：

- 选择 3~5 个 ROM（覆盖标准 APU + 扩展音频）：
  - NROM（Super Mario Bros.）— 标准方波/三角波/噪声/DMC
  - MMC1（Legend of Zelda）— 标准 APU
  - VRC6（Akumajou Densetsu）— 扩展音频 PoC
  - MMC5（Castlevania III）— 扩展音频
  - FDS（Metroid FDS，可选，需 BIOS）— 扩展音频
- 在 v1.5 Release 构建下录制 1~2 秒 16-bit mono WAV
- 在 v1.6 每 Phase 后重录并 `memcmp`

## 7. 性能预算

### 7.1 基线

v1.5 最终 Release 基线（来自 CHANGELOG [1.5]）：

- `bench_cpu_frame`:   ~65.0 ms / 60 帧
- `bench_ppu_frame`:   ~67.5 ms / 60 帧
- `bench_full_frame`:  ~68.2 ms / 60 帧

v1.6 是否需要重抓基线：
- Phase B（Apu scaffolding）理论上无热路径变更，不重抓
- Phase C/D/E 后若 `bench_full_frame` 稳定偏移 > +2.5%，则重抓 v1.6 基线

### 7.2 性能约束

| Phase | 约束 |
|------|------|
| Phase B | `bench_full_frame` ≤ v1.5 基线 +2.5% |
| Phase C1 | `bench_full_frame` ≤ v1.5 基线 +2.5% |
| Phase C2 | `bench_full_frame` ≤ v1.5 基线 +2.5%；`bench_cpu_frame` 重点关注（因 `FCEU_SoundCPUHook` 在 CPU 路径） |

| Phase F | 纯清理，应无变化 |

### 7.3 link-time layout 风险

- `sound.h` 是 hot header（被 `x6502.cpp` / `fceu.cpp` / board 文件 include）
- 任何 `sound.h` 的结构变化（新类、新 include）都可能扰动 `bench_tolerance_test`
- 缓解：Phase B 只新增 `apu.h`，尽量不动 `sound.h`；`sound.h` 改动集中在 Phase C，且一次完成

## 9. 风险与缓解

| 风险 | 可能性 | 影响 | 缓解 |
|------|--------|------|------|
| `WaveHi` 不完整数组类型无法做 reference alias | 中 | 编译失败 | 改为完整 `extern int32 (&WaveHi)[40000]`，同步修改所有声明/定义点 |
| `FCEU_SoundCPUHook` 热路径因 `g_apu` 访问引入额外开销 | 中 | `bench_cpu_frame` 回归 | 保留自由函数入口，内部 `__forceinline`；必要时保留 reference alias |
| `sound.h` 结构变化触发 link-time layout shift | 高 | `bench_tolerance_test` 偶发 FAIL | 分 Phase 控制 `sound.h` 改动次数；每次改动后跑 10 次 bench_tolerance |
| `SFORMAT` 字段顺序/名称变动导致 savestate 不兼容 | 低 | 严重 | 迁移时逐字段核对；跑 `savestate_regression_test` / `golden_savestate_test` |
| VRC6 PoC 与 board 文件范围冲突 | 低 | v1.8 重复工作 | PoC 只做一个芯片；其余推迟到 v1.8 |
| Rust FIR 清理误删仍在用的 C 数组 | 低 | 编译失败 | 先 grep 确认 `src/fir/*.h` 无 C++ 引用再清理 |

## 11. 与下游版本的接口契约

### 11.1 v1.7 Cart 需要的接口

- `Apu::set_exp_sound(const EXPSOUND&)` — Cart 在加载 ROM 时根据 mapper 设置扩展音频
- `Apu::reset()` / `Apu::power()` — Cart 生命周期回调可转发

### 11.2 v1.8 Mapper 需要的接口

- `fceu11::ExpansionAudio` 虚基类 — Mapper 子类化扩展音频的接口
- `EXPSOUND::expansion` — Mapper 实例写入自身 `ExpansionAudio*` 的入口

### 11.3 v1.9 Savestate 需要的接口

- `Apu::save_state(SFORMAT*)` / `load_state(const SFORMAT*)` — v1.9 若改用新 savestate 格式，可直接调用
- `FCEUSND_STATEINFO` 保持 SFORMAT 表可用

### 11.4 v1.14 LTO 需要的接口

- `Apu` 类热路径方法（`sound_cpu_hook`）必须 `__forceinline` 或定义在头内
- `g_apu` 是直接 global，便于 LTO 内联
- `ExpansionAudio` 虚函数在 LTO 下可被去虚化（若子类唯一）
