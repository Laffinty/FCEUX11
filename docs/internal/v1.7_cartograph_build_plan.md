> **基线版本**：v1.6 Resonance（commit `d9879a9`，2026-06-27）

> **方法**：基于 Roadmap §7 拆解为可独立测试的子任务，每个子任务单独 commit/合入；不与 §8~§14 冲突

### 0.5 v1.6 的 link-time layout shift 教训

v1.6 Phase E 在 `src/boards/vrc6.cpp` 中加入 `GameExpSound.expansion = &g_vrc6_audio;` 一行**不可达**的赋值，结果 `bench_full_frame` 回归 +3.63%（commit `7f032841`，详见 `docs/internal/phase6_vrc7_bench_regression.md` 的同模式分析）。根因：MSVC 对 .cpp 文件新代码做 -scanDependencies 与 LAYOUT 时会重新排序热路径指令。

**v1.7 缓解措施**：

1. **Phase B（Cart scaffolding）只新增 `cart_class.h` / `cart_class.cpp`，不修改任何已有 .cpp 文件**。`src/cart.h` 保持不变。`fceu.cpp::Initialize()` 增加 `g_cart.init()` 一行（v1.5 §5.2 `g_bus.attach_ppu` 已证明这种 init 顺序调整稳定）。
2. **Phase C/D/E 每批次 commit 前跑 `bench_tolerance_test` 3 次**，median 与 v1.6 Phase G 末态（70.728 ms）对比。若任一批次触发 +1.5% 以上 regression，**先 revert 该批次**，再分析 layout shift 来源，禁止"先 commit 后调"。
3. **避免在 `src/boards/*.cpp` 添加任何新代码**，除了 3 个 PoC 子类（NROM / MMC1 / MMC3）。PoC 子类只新增 .h 文件 + .cpp 末尾的子类定义，不修改原 `MapperNN_Init` 函数体。
4. **不实装 vrc7_PreSave**：v1.4 已证明这一行不可达赋值会触发 +6-9% regression。v1.7 只提供 `on_save_pre()` 虚方法 hook，**虚方法调用自身在 MSVC 无 LTO 时不可被去虚化**，仅当子类唯一且编译器可见时才能内联；为安全起见，vrc7 板的 on_save_pre() 默认实现 `{}`，不实装任何逻辑。

## 1. `fceu11::Cart` 类设计

### 1.1 类布局

```cpp
// src/cart_class.h
#ifndef FCEU11_CART_CLASS_H
#define FCEU11_CART_CLASS_H

#include <array>
#include <cstdint>
#include <cstddef>
#include <filesystem>
#include <vector>

#include "types.h"
#include "utils/cache.h"       // FCEUX11_CACHE_ALIGN

namespace fceu11 {

// 前向声明 Bus 与 Mapper（避免循环 include）
class Bus;
class Mapper;

// MirrorMode enum class（替代 MI_H / MI_V / MI_0 / MI_1 宏）
enum class MirrorMode : uint8_t {
    Horizontal = 0,    // 原 MI_H
    Vertical   = 1,    // 原 MI_V
    Mode0      = 2,    // 原 MI_0 (单屏 low)
    Mode1      = 3,    // 原 MI_1 (单屏 high)
};

class FCEUX11_CACHE_ALIGN Cart {
public:
    Cart() noexcept;
    virtual ~Cart() = default;

    // ---- 生命周期（原 Power / Reset / Close 函数指针）----
    virtual void on_power() noexcept = 0;
    virtual void on_reset() noexcept = 0;
    virtual void on_close() noexcept = 0;

    // ---- Savestate 钩子（履行 v1.4 vrc7_PreSave 延期项的接口预留）----
    // on_save_pre: 在 SFORMAT 序列化前调用，VRC7 等需要快照堆指针的 mapper
    // 可在此保存间接指针。v1.7 默认 {}；v1.14 Anvil LTO 之后实装。
    virtual void on_save_pre() noexcept {}
    virtual void on_load_post() noexcept {}

    // ---- 电池存档（v1.0 SaveGame vector 的对象化封装）----
    bool has_battery() const noexcept;
    bool save_battery(const std::filesystem::path& path) const;
    bool load_battery(const std::filesystem::path& path) const;
    void clear_battery() noexcept;

    // ---- ROM 元数据（v1.0 CartInfo 17 字段迁入）----
    const std::array<uint8_t, 16>& md5() const noexcept;
    uint32_t crc32() const noexcept { return crc32_; }
    int mirror_raw() const noexcept { return mirror_; }        // int 兼容旧 iNES 解析
    int mirror_as_2bits() const noexcept { return mirror_as_2bits_; }
    bool battery_present() const noexcept { return battery_ != 0; }
    bool ines2() const noexcept { return ines2_ != 0; }
    int submapper() const noexcept { return submapper_; }
    int wram_size() const noexcept { return wram_size_; }
    int battery_wram_size() const noexcept { return battery_wram_size_; }
    int vram_size() const noexcept { return vram_size_; }
    int battery_vram_size() const noexcept { return battery_vram_size_; }
    uint32_t mapper_number() const noexcept { return mapper_number_; }

    // ---- 元数据 setter（由 iNES / UNIF 解析代码调用）----
    void set_md5(const uint8_t (&md5)[16]) noexcept;
    void set_crc32(uint32_t v) noexcept { crc32_ = v; }
    void set_mirror(int m) noexcept { mirror_ = m; }
    void set_mirror_as_2bits(int m) noexcept { mirror_as_2bits_ = m; }
    void set_battery(bool b) noexcept { battery_ = b ? 1 : 0; }
    void set_ines2(bool b) noexcept { ines2_ = b ? 1 : 0; }
    void set_submapper(int s) noexcept { submapper_ = s; }
    void set_wram_size(int s) noexcept { wram_size_ = s; }
    void set_battery_wram_size(int s) noexcept { battery_wram_size_ = s; }
    void set_vram_size(int s) noexcept { vram_size_ = s; }
    void set_battery_vram_size(int s) noexcept { battery_vram_size_ = s; }
    void set_mapper_number(uint32_t n) noexcept { mapper_number_ = n; }

    // ---- v1.0 兼容：SaveGame 子结构 + addSaveGameBuf（PoC 阶段用）----
    struct SaveGame_t {
        uint8_t* bufptr;
        uint32_t buflen;
        void (*resetFunc)(void);
    };
    void addSaveGameBuf(uint8_t* bufptrIn, uint32_t buflenIn,
                        void (*resetFuncIn)(void) = nullptr);
    const std::vector<SaveGame_t>& save_games() const noexcept { return save_games_; }

    // ---- 扩展音频安装入口（履行 v1.6 §11.1 契约）----
    // 默认 no-op；Cart 子类覆盖以注入 ExpansionAudio*
    virtual void install_expansion_audio(class Apu& apu) noexcept;

    // ---- Savestate 注册便捷方法（履行 v1.4 §known issues 契约）----
    void register_state_chunk(const char* name, void* data,
                              uint32_t size, uint32_t count = 1);

    // ---- Bus 注入（与 v1.5 Ppu / Bus 模式一致）----
    void attach_bus(Bus& bus) noexcept { bus_ = &bus; }
    Bus* bus_ptr() const noexcept { return bus_; }

protected:
    // 子类通过 Bus 引用操作 bank-switching
    Bus* bus_;                       // null until attach_bus
    uint32_t mapper_number_ = 0;
};

// 全局唯一实例（由 fceu.cpp::Initialize() 分配具体子类）
extern Cart* g_cart;

} // namespace fceu11
#endif
```

### 1.2 与 Ppu / Apu 类的一致性原则

- **指针 vs 直接 global**：`g_cart` 与 `g_cpu` / `g_bus` / `g_ppu` / `g_apu` **不同** —— Cart 必须是**指针**而非直接对象，因为 mapper 子类在 ROM 加载时动态选择（168 个未迁移 board 仍走原函数指针路径）。
- **`attach_bus(Bus&)` 注入点**：与 v1.5 `Bus::attach_ppu(Ppu*)` 同模式；在 `fceu.cpp::Initialize()` 中 `g_cart->attach_bus(&g_bus)`，紧随 `g_bus.attach_ppu(&g_ppu)`。
- **生命周期**：`on_power()` / `on_reset()` / `on_close()` 对应 `PowerNES()` / `ResetNES()` / `FCEUI_CloseGame()` 调用点。
- **savestate**：`on_save_pre()` / `on_load_post()` 虚方法 hook 在 `FCEU_SetStatePreSave` / `FCEU_SetStatePostLoad` 注册点触发；v1.7 默认 no-op，不实装 vrc7_PreSave。
- **alignas(64)**：Cart 类 64-byte cache-line 对齐（与 `g_cpu` / `g_bus` / `g_ppu` / `g_apu` 一致），但**仅当 Cart 作为直接对象时**才生效。v1.7 的 `g_cart` 是指针，所以 alignas 实际无影响；保留以备 v1.8 若改为直接对象。

### 1.3 与 v1.0 兼容：CartInfo 的特殊处理

v1.5 PPU 采用 `extern T (&NAME)[N]` reference-to-storage alias 模式，v1.7 Cart **不能**直接采用 —— CartInfo 是结构体（不是数组），且成员函数（`addSaveGameBuf` / `clear`）无法做 reference alias。

**兼容方案**：

```cpp
// src/cart.h 兼容层（Phase B 新增，保持外部 API 不变）
struct CartInfo {
    // ... 原 17 字段 + SaveGame vector + addSaveGameBuf + clear ...

    // v1.7 新增：指向当前生效的 fceu11::Cart*（在 ROM 加载时由 iNES/UNIF 设置）
    fceu11::Cart* cart_obj = nullptr;

    // v1.7 新增：函数指针转发（Power/Reset/Close 改为转发到 cart_obj->on_*）
    void Power() const { if (cart_obj) cart_obj->on_power(); }
    void Reset() const { if (cart_obj) cart_obj->on_reset(); }
    void Close() const { if (cart_obj) cart_obj->on_close(); }
};

extern CartInfo *currCartInfo;        // 不变
extern fceu11::Cart* fceu11::g_cart;  // 新增
```

**约束**：
- `currCartInfo` 全局指针保留（16 处使用），所有调用点继续工作
- `currCartInfo->Power()` 等调用改为转发到 `cart_obj->on_power()`
- 未迁移的 168 个 board 文件继续用 `currCartInfo->SaveGame.push_back(...)` 直接访问，**不破坏现有逻辑**

### 1.4 性能预算的 inline 决策

| 路径 | 策略 |
|------|------|
| `PowerNES()` 中的 `cart_obj->on_power()` | 非热路径（每 ROM 加载 1 次），普通 virtual dispatch 可接受 |
| `FCEU_SetStatePreSave` 中的 `cart_obj->on_save_pre()` | 非热路径（每 savestate save 1 次） |
| `cart_obj->on_reset()` | 非热路径（ResetNES 调用，1 Hz 级） |
| `cart_obj->save_battery()` / `load_battery()` | 非热路径 |
| 元数据 getter（`crc32()` / `mapper_number()` 等） | 普通 inline；非热路径 |

**禁止**：
- 任何 .cpp 热路径（`x6502.cpp` / `ppu.cpp` / `sound.cpp`）直接调用 `g_cart->...` 虚方法 — 这些路径应继续走 `currCartInfo->SaveGame` 兼容层或 `g_bus` 直访
- 在 `cart_class.h` 中暴露 `g_cart` 的具体子类类型 — 仅暴露基类指针

## 2. 核心 CartInfo 状态迁移（Phase C）

### 2.1 迁移清单

`src/cart.h:14-89` `struct CartInfo` 当前字段分类：

| ROM 元数据 int | `submapper` / `wram_size` / `battery_wram_size` / `vram_size` / `battery_vram_size` | 对应 `_` 后缀字段 | C2 |

### 2.2 CartInfo 字段在 v1.7 期间的双写策略

**关键决策**：v1.7 Phase C **不**删除 `CartInfo` 字段，而是在 `Cart` 类中**复制**保存，并通过 setter 同步：

```cpp
// src/cart.cpp
void Cart::set_crc32(uint32_t v) noexcept {
    crc32_ = v;
    if (currCartInfo) currCartInfo->CRC32 = v;  // 双写
}
```

这样：
- 168 个未迁移的 board 文件继续通过 `currCartInfo->SaveGame.push_back(...)` 工作
- 3 个 PoC 子类（NROM / MMC1 / MMC3）通过 `cart_obj->addSaveGameBuf(...)` 工作
- 两者最终修改同一个 `currCartInfo->SaveGame` vector

**Phase G 收尾时**评估是否删除 `CartInfo` 字段；v1.7 期间保留。

### 2.3 MirrorMode enum class 引入

**问题**：当前 `src/cart.h:123-126` 的 4 个 `#define MI_H 0 / MI_V 1 / MI_0 2 / MI_1 3` 宏是 v1.0 C-style 标志。Roadmap §13.3 将 `#define → constexpr/inline 迁移` 列为 v1.13 Purify 目标，但 `MirrorMode` 是 v1.7 §7.1 的 Cart 接口成员类型，必须**早于** v1.13 引入。

**v1.7 引入方案**：

```cpp
// src/cart_class.h（已包含于 §1.1）
namespace fceu11 {
enum class MirrorMode : uint8_t {
    Horizontal = 0,    // 原 MI_H
    Vertical   = 1,    // 原 MI_V
    Mode0      = 2,    // 原 MI_0
    Mode1      = 3,    // 原 MI_1
};
}

// src/cart.h 兼容层（Phase B 新增）
// 保留 4 个宏为 enum 值别名（int 兼容）
#define MI_H static_cast<int>(fceu11::MirrorMode::Horizontal)
#define MI_V static_cast<int>(fceu11::MirrorMode::Vertical)
#define MI_0 static_cast<int>(fceu11::MirrorMode::Mode0)
#define MI_1 static_cast<int>(fceu11::MirrorMode::Mode1)
```

**约束**：
- `MI_*` 宏保留为 `int` 值别名，所有现有 board 文件的 `if (info->mirror == MI_V)` 继续工作
- 新代码（v1.7 Cart 子类、v1.8 Masonry）使用 `MirrorMode::Vertical` 类型安全
- **不**批量修改 168 个 board 文件中的 `MI_*` 用法（v1.8 Masonry §8.2 工作）

```cpp
struct CartInfo {

    bmap[mapper_number].init(&iNESCart);  // 原函数指针调用
    // ... 后续 ...
    iNESCart.cart_obj = create_cart_for_mapper(mapper_number);  // v1.7 新增
    iNESCart.Power = PowerForward;       // 转发到 cart_obj->on_power()
    iNESCart.Reset = ResetForward;
    iNESCart.Close = CloseForward;
}

static void PowerForward(void) {
    if (currCartInfo && currCartInfo->cart_obj)
        currCartInfo->cart_obj->on_power();
}
```

**设计要点**：
- `CartInfo::Power/Reset/Close` 函数指针**保留**（兼容 168 个未迁移 board 的 `info->Power = ...` 直接赋值）
- iNES/UNIF 加载时根据 mapper 编号创建对应 `Cart*`，赋给 `cart_obj`
- `Power/Reset/Close` 转发到 `cart_obj->on_*`
- 168 个未迁移 board 的 `info->Power = Mapper24_Init_aux;` 赋值被忽略（实际走 `cart_obj->on_power()` 路径）—— **这是 v1.7 的关键兼容保证**

## 7. 性能预算

### 7.1 基线

v1.6 Phase G 末态实测（commit `da8367d`）：
- `bench_cpu_frame`:  ~baseline
- `bench_ppu_frame`:  +2.00%

v1.7 是否需要重抓基线：

| Phase G | 若 Phase E/F 中任一触发 regression 且无法 revert 修复，**不重抓基线**，记录 advisory FAIL |

### 7.2 性能约束

| Phase | 约束 |
|------|------|
| A | 仅文档，无约束 |
| B | 仅新增 `cart_class.h/.cpp` + `Initialize()` 多一行 `g_cart = ...`，无热路径约束 |

| F (MMC1 + MMC3 PoC) | **重点监控**（MMC3 是 bench ROM） |

### 7.3 link-time layout 风险（v1.6 教训）

**已知风险**：
1. **Phase E 添加 `Vrc6Cart` 子类**会改 `src/boards/vrc6.cpp` 的代码布局。`vrc6.cpp` 不在 bench ROM 路径，但 MSVC LAYOUT 优化可能跨 TU 重排热路径指令 → `bench_full_frame` regression。
2. **Phase F 添加 `Mmc3Cart` 子类**会改 `src/boards/mmc3.cpp` 的代码布局。**`mapper_mmc3.nes` 是 `bench_full_frame` 的 ROM**（见 `tests/fixtures/bench_baseline.json:75`），MMC3 PoC **直接**影响 bench。
3. **`install_expansion_audio` 虚方法**调用频率 = 1 次/ROM 加载（非热路径），但虚方法本身的存在会增加 `Cart` vtable 体积，可能影响 `g_cart` 周围的 cache 布局。

**缓解措施**：
1. **每 Phase 提交前**跑 `bench_tolerance_test --iterations 7 --warmup-iterations 3` 3 次取 median
2. **Phase F (MMC3 PoC) 单独占一个 commit**，若 regression > +1.5%，**只 revert 该 commit**，不连带 Phase E 一起回滚
3. **Mmc3Cart 子类实现采用策略 A**（§3.3，调用 `MMC3_Init(currCartInfo)` 函数指针），不直接重写逻辑 —— 减小 v1.7 commit 与原 `MMC3_Init` 的代码差异，最小化 layout shift
4. **不实装 vrc7_PreSave**（§3.4）
