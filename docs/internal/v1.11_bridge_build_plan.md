### 0.5 v1.6 / v1.7 layout-shift 教训的延续

v1.6 Phase E 一行不可达赋值触发 `bench_full_frame` +3.63%；v1.7 Phase B/C 引入新 .cpp + `g_cart.init()` 叠加至 CPU 帧 +4.37%。**v1.11 的核心风险同源**：

1. **新增 `src/driver_callbacks.cpp` + `fceu_bridge.cpp` 等 5+ 个 .cpp 文件**会重排链接图，扰动热路径指令布局。
2. **`FCEUD_*` 调用点从直接自由函数改为 `g_driver->fn()` 间接调用**，若 `g_driver` 不内联，每次调用多一次 load + indirect call。

**v1.11 缓解措施**（见 §6 详述）：

1. **Phase B 引入 `DriverCallbacks` scaffolding 时**，所有 `FCEUD_*` 自由函数保持原实现不动；仅新增接口、不切换调用点。bench 必须零变化。
2. **Phase C~F 迁移 `FCEUD_*` 调用点分 4 批 commit**，每批后跑 3 次 `bench_full_frame` 取 median；任一批 +1.5% 即 revert 该批。
3. **`g_driver` 访问器设计为 `__forceinline` 返回 `DriverCallbacks&` 引用**，使 MSVC 在 LTO 前即可将 `g_driver->fn()` 优化为直接 call（与原自由函数等价）。验证手段：Phase C 后用 `/FAcs` 检查 `FCEUD_Message` 调用点的汇编，确认无多余 indirect call。
4. **Phase G fceuWrapper 拆分为单批 commit**，但拆分前先做"dry-run"：在分支上拆分但不合入，跑 bench 确认 layout shift 量级后再决定合入策略。
5. **Phase H 移除 `driver.h` shim 与 mutex pImpl 改造合并为单批**，避免两次头文件广覆盖变更引发滚雪球式重编译。

### 0.6 v1.10 反消极构建教训的延续

v1.10 §10.6.3 列举的作弊手法及对策，v1.11 全程适用：

## 1. 核心源码 driver `#ifdef` 审计（Roadmap §11.1）

### 1.1 审计结果（Phase A 已完成调研）

核心源码（`src/` 非 `drivers/`）共 **86 处 driver 条件编译指令**，分布于 **12 个 .cpp + 1 个 .h + 1 个测试**：

| `src/version.h` | 1 | `!__QT_DRIVER__` | `scmrev.h` include 条件 | Phase E |
| `src/tests/rom_regression_test.cpp` | 1 | （无条件） | `#include "drivers/Qt/nes_shm.h"` | Phase H（测试侧） |

**关键观察**：

1. **`__WIN_DRIVER__` 是死宏**——当前无任何构建配置（CMake / .vcxproj）定义它。27+17+8+3+2+1+1 = **59 处 `#ifdef __WIN_DRIVER__` 块全是死代码**，移除风险极低（仅须保留 `#else` 分支）。
2. **`__SDL__` 是冗余宏**——`src/CMakeLists.txt:82` 同时定义 `__SDL__` 与 `__QT_DRIVER__`，`lua-engine.cpp:42` 的 `#ifdef __SDL__` 恒为真，仅作为 Qt 分支的外层包装。
3. **`input.cpp` 27 块最均匀**——全是 Win-only emu-command handler（`handleEmuCmdByTaseditor` / `DoDebug` / `DoNTView` / `SetSearchType` 等），可一次性抽象为 `EmuCommandHandler` 回调表。
4. **`fceu.cpp` 20 块最复杂**——混合三类：(a) driver includes、(b) per-event UI refresh（`Update_RAM_Search` / `SetMainWindowText` / `UpdateCheatList`）、(c) 原生对话框（`MessageBox`，非 Win 有 `printf` fallback）。
5. **`mutex.h/.cpp` 是唯一 Qt 类型泄漏到核心工具 ABI 的位置**——`QRecursiveMutex` 成员类型使 `mutex.h` 的包含者传递依赖 Qt 头。Phase H 用 pImpl（`void*` 不透明指针）隔离。

### 1.2 移除策略分类

| 类别 | 处理方式 | 涉及块数 |
|---|---|---|
| **A. 死代码直接删**（`#ifdef __WIN_DRIVER__` 块无 `#else`，或 `#else` 为空 printf） | 删除 `#ifdef` 块，保留 `#else` 分支（如有） | ~45 |
| **B. 对话框抽象**（`MessageBox(...)` → driver 回调） | 新增 `DriverCallbacks::message_box(title, msg, type)`，Qt 注册 `QMessageBox` 实现 | ~8 |
| **C. UI refresh 抽象**（`Update_RAM_Search` / `SetMainWindowText` / `UpdateCheatList`） | 新增 `DriverCallbacks::on_*` 通知钩子，Qt 注册刷新实现 | ~15 |
| **D. driver includes 移除**（`#include "drivers/win/*.h"` / `drivers/Qt/*.h`） | 删除整个 include 块；所需符号改为 forward declare 或走 `DriverCallbacks` | ~18 |

## 2. `fceu11::DriverCallbacks` 接口设计（Roadmap §11.3）

### 2.1 接口定义

新建 `src/driver_callbacks.h` / `src/driver_callbacks.cpp`：

```cpp
// src/driver_callbacks.h
namespace fceu11 {

// Core→Driver 回调表。所有 FCEUD_* 自由函数迁移为此结构的字段。
// Qt 驱动在 fceuWrapperInit 中调用 register_driver() 注册实现；
// core 通过 g_driver()->fn(...) 调用，等价于原 FCEUD_fn(...)。
//
// 设计约束：
//   1. 字段全部为函数指针（非 std::function），避免热路径堆分配与类型擦除开销。
//   2. nullptr 表示"未注册"，core 调用前必须判空（debug 断言）。
//   3. DriverCallbacks 是 POD，可 std::memset 清零；不引入虚函数表。
//   4. g_driver() 访问器 __forceinline，使调用点编译为直接 call。
struct DriverCallbacks {
    // ---- Messages & lifecycle (Batch 1, Phase C) ----
    void (*print_error)(const char* s) = nullptr;             // FCEUD_PrintError
    void (*message)(const char* s) = nullptr;                 // FCEUD_Message
    const char* (*get_compiler_string)() = nullptr;           // FCEUD_GetCompilerString
    int  (*show_status_icon)() = nullptr;                     // FCEUD_ShowStatusIcon
    void (*toggle_status_icon)() = nullptr;                   // FCEUD_ToggleStatusIcon
    void (*hide_menu_toggle)() = nullptr;                     // FCEUD_HideMenuToggle
    bool (*pause_after_playback)() = nullptr;                 // FCEUD_PauseAfterPlayback

    // ---- Turbo / speed (Batch 7, Phase C) ----
    void (*set_emulation_speed)(int cmd) = nullptr;           // FCEUD_SetEmulationSpeed
    void (*turbo_on)() = nullptr;                             // FCEUD_TurboOn
    void (*turbo_off)() = nullptr;                            // FCEUD_TurboOff
    void (*turbo_toggle)() = nullptr;                         // FCEUD_TurboToggle

    // ---- File I/O (Batch 2, Phase D) ----
    FILE* (*utf8_fopen)(const char* fn, const char* mode) = nullptr;        // FCEUD_UTF8fopen
    EMUFILE_FILE* (*utf8_fstream)(const char* n, const char* m) = nullptr;  // FCEUD_UTF8_fstream
    ArchiveScanRecord (*scan_archive)(std::string fname) = nullptr;         // FCEUD_ScanArchive
    FCEUFILE* (*open_archive)(ArchiveScanRecord& asr, std::string& fname,
                              std::string* innerFilename, int* userCancel) = nullptr; // FCEUD_OpenArchive
    FCEUFILE* (*open_archive_index)(ArchiveScanRecord& asr, std::string& fname,
                                    int innerIndex, int* userCancel) = nullptr;       // FCEUD_OpenArchiveIndex

    // ---- Driver-command file dialogs (Batch 8, Phase D) ----
    void (*avi_record_to)() = nullptr;                        // FCEUD_AviRecordTo
    void (*avi_stop)() = nullptr;                             // FCEUD_AviStop
    void (*save_state_as)() = nullptr;                        // FCEUD_SaveStateAs
    void (*load_state_from)() = nullptr;                      // FCEUD_LoadStateFrom
    void (*movie_record_to)() = nullptr;                      // FCEUD_MovieRecordTo
    void (*movie_replay_from)() = nullptr;                    // FCEUD_MovieReplayFrom

    // ---- Video / palette (Batch 3, Phase E) ----
    void (*set_palette)(uint8 index, uint8 r, uint8 g, uint8 b) = nullptr;  // FCEUD_SetPalette
    void (*get_palette)(uint8 i, uint8* r, uint8* g, uint8* b) = nullptr;   // FCEUD_GetPalette
    void (*video_changed)() = nullptr;                        // FCEUD_VideoChanged
    bool (*should_draw_input_aids)() = nullptr;               // FCEUD_ShouldDrawInputAids
    uint64 (*get_time)() = nullptr;                           // FCEUD_GetTime
    uint64 (*get_time_freq)() = nullptr;                      // FCEUD_GetTimeFreq

    // ---- Sound (Batch 4, Phase E) ----
    void (*sound_toggle)() = nullptr;                         // FCEUD_SoundToggle
    void (*sound_volume_adjust)(int n) = nullptr;             // FCEUD_SoundVolumeAdjust

    // ---- Input (Batch 5, Phase E) ----
    void (*set_input)(bool fourscore, bool microphone,
                      ESI port0, ESI port1, ESIFC fcexp) = nullptr;          // FCEUD_SetInput

    // ---- Debug (Batch 6, Phase E) ----
    void (*debug_breakpoint)(int bp_num) = nullptr;           // FCEUD_DebugBreakpoint
    void (*trace_instruction)(uint8* opcode, int size) = nullptr; // FCEUD_TraceInstruction
    void (*flush_trace)() = nullptr;                          // FCEUD_FlushTrace
    void (*update_nt_view)(int scanline, bool drawall) = nullptr; // FCEUD_UpdateNTView
    void (*update_ppu_view)(int scanline, int drawall) = nullptr; // FCEUD_UpdatePPUView

    // ---- Netplay (Batch 9, Phase F) ----
    int  (*send_data)(void* data, uint32 len) = nullptr;      // FCEUD_SendData
    int  (*recv_data)(void* data, uint32 len) = nullptr;      // FCEUD_RecvData
    void (*netplay_text)(uint8* text) = nullptr;              // FCEUD_NetplayText
    void (*network_close)() = nullptr;                        // FCEUD_NetworkClose

    // ---- UI refresh / dialogs (Phase C/D, §1.2 类别 B/C) ----
    void (*set_main_window_text)(const char* s) = nullptr;    // SetMainWindowText 抽象
    void (*update_ram_search)() = nullptr;                    // Update_RAM_Search 抽象
    void (*update_cheat_list)() = nullptr;                    // UpdateCheatList 抽象
    int  (*message_box)(const char* title, const char* msg, int type) = nullptr; // MessageBox 抽象

    // ---- Emu-command handler (Phase F, input.cpp 27 块) ----
    void (*emu_command)(int cmd) = nullptr;                   // handleEmuCmdByTaseditor 等抽象
};

// 返回当前注册的 driver 回调表。未注册时返回全 nullptr 的静态实例。
// __forceinline 确保 MSVC 将 g_driver()->fn() 优化为直接 call。
__forceinline DriverCallbacks& g_driver() noexcept;

// Qt 驱动调用此函数注册实现。重复注册会 FCEU_DASSERT 失败（debug 构建）。
void register_driver(const DriverCallbacks& cb) noexcept;

} // namespace fceu11
```

### 2.2 兼容层：`FCEUD_*` 自由函数转发

迁移期间，原 `FCEUD_*` 自由函数声明保留在 `core_api.h` / `io_api.h` / `net_api.h` / `diag_api.h`，但实现改为转发到 `g_driver()->fn`：

```cpp
// src/driver_callbacks.cpp
void FCEUD_PrintError(const char *s) {
    if (auto* fn = g_driver().print_error) fn(s);
}
void FCEUD_Message(const char *s) {
    if (auto* fn = g_driver().message) fn(s);
}
// ... 其余 38 个 FCEUD_* 同模式
```

**迁移分批策略**：Phase B 引入 `DriverCallbacks` 与 `g_driver()`，但 `FCEUD_*` 实现不动（仍为 Qt 侧原实现）。Phase C~F 逐批将 Qt 侧实现迁入 `register_driver()` 注册的回调表，同时 `FCEUD_*` 自由函数改为转发。每批迁移后，对应 `FCEUD_*` 的 Qt 原实现删除。

### 2.3 与 `fceu11::State` 的关系

`src/core_state.h` 的 `ConfigView` / `DebugView` 已包含配置与调试全局状态。`DriverCallbacks` **不并入 `State`**，理由：

1. `State` 持有的是 core 拥有的状态（CPU/PPU/APU/Bus/Cart/Config/Debug），`DriverCallbacks` 持有的是 driver 拥有的回调——所有权方向相反。
2. `State` 是 core 单例，driver 在 core 之外注册；若并入 `State`，driver 须 `#include "core_state.h"`，反转依赖。
3. `g_driver()` 与 `global_state()` 平级，均为 process-wide 单例，访问模式一致。

`core_state.h` ConfigView 中 `game_attributes()` 的 deferred 注释维持——v1.0 无 `GameAttributes` 定义，v1.11 不引入。

## 5. `src/utils/mutex.*` Qt 类型泄漏修复（Phase H）

### 5.1 现状

`src/utils/mutex.h` 当前：
```cpp
#ifdef __QT_DRIVER__
#include <QMutex>
#include <QRecursiveMutex>
class FCEUX11_Mutex {
private:
    std::unique_ptr<QRecursiveMutex> mtx;  // Qt6
    // 或 std::unique_ptr<QMutex> mtx;     // Qt5
};
#else
    // 空 stub
#endif
```

问题：`QRecursiveMutex` 作为成员类型使 `mutex.h` 的包含者（`debugsymboltable.cpp` 等）传递依赖 Qt 头，破坏 core/driver 边界。

### 5.2 pImpl 改造

```cpp
// src/utils/mutex.h — 改造后
class FCEUX11_Mutex {
public:
    FCEUX11_Mutex();
    ~FCEUX11_Mutex();
    void lock();
    void unlock();
private:
    // 不透明指针——实现细节在 mutex.cpp，Qt 头不再泄漏到 core
    void* impl_;  // 实际为 QRecursiveMutex*（Qt6）/ QMutex*（Qt5）
};
```

`mutex.cpp` 内部 `#include <QRecursiveMutex>`，`impl_` 通过 `reinterpret_cast` 转换。core 包含 `mutex.h` 时只见 `void*`，无 Qt 传递依赖。

### 5.3 验收（§5）

- [ ] `src/utils/mutex.h` 不再 `#include <QMutex>` / `<QRecursiveMutex>` / 任何 Qt 头
- [ ] `src/utils/mutex.h` 无 `#ifdef __QT_DRIVER__`
- [ ] `mutex.cpp` 内部 Qt include 隔离在单一 TU
- [ ] `debugsymboltable.cpp` 等包含者编译时无需 Qt 头

6. 对比 best-of-3 的 `bench_full_frame` 中位数，计算退步百分比
7. 每 Phase 收官 commit 后跑一次；每子批 commit 后跑一次

### 6.4 `g_driver()` 内联验证

Phase C 后，用 `/FAcs`（MSVC 汇编输出）检查 `FCEUD_Message` 调用点：
- 期望：`call qword ptr [g_driver+offset]` 或经内联优化后的直接 `call <Qt实现>`
- 不期望：`load g_driver` + `load field` + `indirect call` 三步链（若如此，`__forceinline` 未生效，须改 `extern DriverCallbacks g_driver_callbacks;` 直接全局变量）

## 11. 与下游版本的接口契约

### 11.1 v1.12 Scissors 需要的接口

v1.12 巨型文件拆分（TasEditorWindow 6747 行 / ConsoleWindow 3999 行 / AviRecord 2800 行）依赖 v1.11 的：
- `DriverCallbacks` 稳定接口（v1.12 拆分后的子模块通过 `g_driver()` 调用 driver，不直接 `#include` driver 头）
- `fceuWrapper.cpp` 已拆分为 5 文件（v1.12 不再处理 fceuWrapper，聚焦 TasEditor/Console/Avi）

### 11.2 v1.13 Purify 需要的接口

v1.13 遗留 C 模式清理依赖 v1.11 的：
- 核心源码无 driver `#ifdef`（v1.13 的 `/W4 /WX` 编译不被 driver 条件块干扰）
- `DriverCallbacks` 为 POD（v1.13 的 C-style cast 清理不触碰回调表）

### 11.3 v1.14 Anvil 需要的接口

v1.14 性能硬化与收官依赖 v1.11 的：
- `g_driver()` `__forceinline` 稳定（v1.14 LTO/PGO 验证热路径无 indirect call）
- `driver.h` shim 移除（v1.14 编译时间优化不再受 shim 头传递依赖影响）
- `mutex.h` pImpl（v1.14 LTO 可跨 TU 优化 mutex 实现）

### 11.4 v2.0 准备态

v1.11 完成后，core→driver 边界正式建立。v2.0 可在此基础上：
- 移除 `FCEUD_*` 自由函数兼容别名（v1.x 保留，v2.0 删）
- 引入第二 driver（如 headless test driver）只需实现 `DriverCallbacks`，无需 `#ifdef`
- `fceu11::State` 与 `g_driver()` 成为 core 的两个公开单例入口
