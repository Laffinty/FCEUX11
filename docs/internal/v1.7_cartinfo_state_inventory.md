> **Phase A audit deliverable.** Captures the complete reader/writer distribution
> of the 17 fields in `struct CartInfo` (v1.0 legacy form), the 3 lifecycle
> function pointers, the `SaveGame` vector, and the related expansion-audio
> / state-save hook entry points that v1.7 Cart migration will consume.
> This is the source-of-truth for Phase C/D/E field-by-field migration.

> audit (`BMAPPINGLocal bmap[]`) is in `mapper_registration_audit.md` (Phase A
> companion doc, inlined below as §6 for completeness). The byte-diff
> golden format for `mapper_byte_diff_test` is in

## 3. 兼容层设计（v1.7 期间双写策略）

### 3.1 CartInfo 字段 → Cart 字段映射

```cpp
// 兼容层（src/cart.h）
struct CartInfo {
    // v1.0 字段（保留 — 168 个未迁移 board 继续读这些）
    void (*Power)(void);       // 改为 inline 转发到 cart_obj->on_power()
    void (*Reset)(void);       // 改为 inline 转发到 cart_obj->on_reset()
    void (*Close)(void);       // 改为 inline 转发到 cart_obj->on_close()
    std::vector<SaveGame_t> SaveGame;  // 双写目标
    int mirror, mirrorAs2Bits, battery, ines2, submapper;
    int wram_size, battery_wram_size, vram_size, battery_vram_size;
    uint8_t MD5[16];
    uint32_t CRC32;

    // v1.7 新增
    fceu11::Cart* cart_obj = nullptr;

    // v1.7 兼容层方法（替代原 addSaveGameBuf 直接 push）
    void addSaveGameBuf(uint8_t* bufptrIn, uint32_t buflenIn,
                        void (*resetFuncIn)(void) = nullptr) {
        SaveGame_t tmp = { bufptrIn, buflenIn, resetFuncIn };
        SaveGame.push_back(tmp);
        if (cart_obj) cart_obj->addSaveGameBuf(bufptrIn, buflenIn, resetFuncIn);
    }
};

// Power/Reset/Close 函数指针的"替换"（不在 struct 内，是 free function）
static void PowerForward(void) {
    if (currCartInfo && currCartInfo->cart_obj)
        currCartInfo->cart_obj->on_power();
}
static void ResetForward(void) {
    if (currCartInfo && currCartInfo->cart_obj)
        currCartInfo->cart_obj->on_reset();
}
static void CloseForward(void) {
    if (currCartInfo && currCartInfo->cart_obj)
        currCartInfo->cart_obj->on_close();
}
```

**iNES/UNIF 加载时**：
```cpp
// src/ines.cpp / src/unif.cpp
bmap[mapper_number].init(&iNESCart);   // v1.0 mapper init (填充 Power/Reset/Close)
// ↓ v1.7 新增
iNESCart.cart_obj = fceu11::create_cart_for_mapper(mapper_number, g_bus);
// ↓ 替换函数指针为转发函数
iNESCart.Power = PowerForward;
iNESCart.Reset = ResetForward;
iNESCart.Close = CloseForward;
```

**关键**：168 个未迁移 mapper 的 `info->Power = MapperNN_power_aux;` 直接赋值**在 v1.7 被忽略**（因 iNES 加载最后一步会把 Power 替换为 `PowerForward`）。这是 v1.7 §3.2 兼容层设计的关键保证。

### 3.2 双向同步矩阵

| 操作 | 旧路径 | v1.7 路径 | 同步策略 |
|---|---|---|---|
| `iNESCart.addSaveGameBuf(buf, len, reset)` | push 到 `iNESCart.SaveGame` | 双写：`cart_obj->addSaveGameBuf` + `iNESCart.SaveGame` | **双写**（v1.7 §2.2） |
| `iNESCart.Power = MapperX_power_aux;` | 替换函数指针 | 在 iNES 加载最后一步被 `PowerForward` 覆盖；原赋值**被忽略** | **忽略**（关键兼容保证） |
| `iNESCart.CRC32 = v;` | 直接赋值 | 双写：`cart_obj->set_crc32(v)` + `iNESCart.CRC32 = v` | **双写** |
| `currCartInfo->mirror` (read) | 直读字段 | 直读 `iNESCart.mirror`（不变） | **直读**（保留兼容） |
| `currCartInfo->SaveGame` (read by FCEU_SaveGameSave) | 直读 vector | 直读 `iNESCart.SaveGame`（不变） | **直读** |
| `iNESCart.Power()` (call) | 调用函数指针 | 调用 `PowerForward` → `cart_obj->on_power()` | **转发** |

### 3.3 何时删除 CartInfo 字段？

**v1.7 期间保留**（Phase B/C/D/E/F/G 全程）。删除时机：
- **v1.8 Masonry §8.2**：批量迁移剩余 168 个 mapper 到 Cart 子类时，每个 mapper 迁移完毕可移除对应字段的 CartInfo 副本
- **v1.13 Purify §13.4**：全局清理 `CartInfo` 残留字段（与 `scoped_ptr.h` 移除同期）
- **v1.14 Anvil §14.5**：v2.0 准备状态检查时确认 `currCartInfo` 全局指针可移除

### 4.2 v1.7 Phase E install_expansion_audio 设计含义

**主要观察**：

1. **VRC6 (PoC 已是 v1.6 子类模式)** — `Vrc6Cart::install_expansion_audio(Apu&)` 直接转发到现有 `g_vrc6_audio` 的 expansion 指针。**Phase E PoC 即可工作**。

2. **VRC7 运行期激活** ⚠ — VRC7 的 `GameExpSound.Fill = UpdateOPL` 在 `VRC7SW` write handler 内部设置（每次 CPU 写入 OPL 寄存器时）。这意味着 `install_expansion_audio` 不能只在 mapper init 调用一次；它需要：
   - mapper init 时设置 `expansion = &g_vrc7_audio`
   - `VRC7SW` write handler 内部**仍然**直接写 `GameExpSound.Fill = UpdateOPL`（运行时激活 LQ 路径）

   **v1.7 §0.3 决策**：vrc7 子类化推迟到 v1.8 Masonry，所以 v1.7 不需要解决这个运行期激活问题。

3. **MMC5 HiSync 内部调用** — `MMC5_ESI()` 内部会调用 `GameExpSound.HiSync = MMC5HiSync;`，这是**自指**安装（同一个 mapper 的 ESI 设置自己的 HiSync）。v1.8 子类化时需要小心循环依赖。

4. **N106 双重 RChange** — `n106.cpp` 在两个不同分支调用 `GameExpSound.RChange = M19SC;`（line 368 + 420）。这两个分支对应 N106 子型号（N106 / N106 variant）。

### 5.2 v1.7 §3.5 修正

> **本文档修正 v1.7 build plan §3.5 的文档错误**：build plan 引用了
> `FCEU_SetStatePostLoad`，但 codebase **不存在** 该函数。实际的
> load-path hook 是 `FCEUMOV_PreLoad` / `FCEUMOV_PostLoad`（movie 侧）
> 以及 SFORMAT 反序列化主循环（无外部 hook）。

**修正后的 v1.7 hook 设计**：

```cpp
// Save 路径（src/state.cpp::FCEUSS_Save line 347）
if (SPreSave) SPreSave();                        // v1.0 hook（保留）
if (currCartInfo && currCartInfo->cart_obj)
    currCartInfo->cart_obj->on_save_pre();       // v1.7 新增
addSformatChunk(0x10, SFMDATA);
if (SPostSave) SPostSave();                      // v1.0 hook（保留）

// Load 路径（src/state.cpp::FCEUSS_LoadFP line 601）
ret = FCEUMOV_PostLoad();                        // v1.0 movie hook（保留）
if (currCartInfo && currCartInfo->cart_obj)
    currCartInfo->cart_obj->on_load_post();      // v1.7 新增（在 FCEUMOV_PostLoad 之后）
```

**v1.7 决策**：
- `on_save_pre()` 虚方法：在 `SPreSave` 之后、`addSformatChunk` 之前触发（保证 SFORMAT 看到 cart_obj 已更新的间接指针）
- `on_load_post()` 虚方法：在 `FCEUMOV_PostLoad` 之后触发（保证 SFORMAT 反序列化已完成，cart_obj 可基于新 state 调整）
- v1.7 **不实装** vrc7 的 `on_save_pre()` 重写（避免 v1.4 +6-9% layout shift 风险）
- v1.14 Anvil §14.3 LTO 后再实装 vrc7_PreSave

### 5.3 风险点

| 风险 | 可能性 | 影响 | 缓解 |
|---|---|---|---|
| `on_save_pre()` 即使 default `{}`，vtable 多一项导致 `g_cart` 周边布局变化 | 低 | 微小 bench regression | 与 v1.6 VRC6 ExpansionAudio 同模式；接受并 defer 到 v1.14 LTO |

### 6.3 v1.7 兼容层含义

**关键观察**：168 个未迁移 mapper 的 `info->Power = MapperNN_power_aux;` 直接赋值，在 v1.7 §3 兼容层中**被忽略**（被 `PowerForward` 覆盖）。但 `bmap[].init` 函数指针仍会被调用一次（用于设置初始 state、SaveGame buffer 等），所以 bmap 表**保留不变**。

**v1.7 Phase E/F PoC 影响**：
- NROM (mapper 0)：bmap 调用 `NROM_Init`，该函数内部 setprg32/setchr8 + SaveGame；`NromCart::on_power()` 同样调用 `NROM_Init(currCartInfo)`（策略 A）
- MMC1 (mapper 1)：bmap 调用 `Mapper1_Init`，类似模式
- MMC3 (mapper 4)：bmap 调用 `Mapper4_Init`，**最复杂**（28 个 mapper number 共享）

**v1.7 Phase F (MMC3 PoC) 风险**：
- MMC3 是 `bench_full_frame` 的 ROM（`mapper_mmc3.nes`）— 任何 `src/boards/mmc3.cpp` 的改动都直接影响 bench
- MMC3 PoC 子类 `Mmc3Cart::on_power()` 采用策略 A（调用 `Mapper4_Init(currCartInfo)`），**不**重写逻辑 → 减小 layout shift
