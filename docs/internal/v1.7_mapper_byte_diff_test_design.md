# v1.7 mapper_byte_diff_test 设计方案

> **Phase A 设计文档。** 定义 v1.7 Phase E/F 的 `mapper_byte_diff_test`
> 的 golden 格式、3 个 PoC mapper（NROM / MMC1 / MMC3）的状态捕获
> 规约、`--generate` 模式、SKIP 行为。
>
> Phase A 仅产出 **设计** 与 **测试骨架**（test 文件编译通过，
> CTest 注册，无 golden 时 SKIP）。Phase E/F 实施期间实装捕获函数
> 并捕获初始 golden。

---

## 1. 设计目标与定位

### 1.1 目标

为 v1.7 Cart 迁移提供一个 **mapper 状态字节级回归测试**，捕获每个
PoC mapper 的内部寄存器状态（PRG bank / CHR bank / mirror / IRQ 等），
memcmp vs committed golden。

类似 v1.5 §5.3 的 `ppu_frame_diff_test`（像素级 XBuf 对比）和 v1.6
Phase A 的 `apu_wav_diff_test`（采样级 WAV 对比）—— 但目标数据是
**mapper 寄存器状态**而非像素/音频。

### 1.2 与现有测试的关系

| 测试 | 目标数据 | 用途 |
|---|---|---|
| `savestate_regression_test` | 完整 SFORMAT dump（CPU+PPU+APU+Mapper+RAM） | 端到端 savestate 兼容性 |
| `golden_savestate_test` | 完整 SFORMAT dump（9 个 entry） | 字节级 round-trip |
| `mapper_byte_diff_test` (新增) | **仅 mapper 寄存器状态**（~256-512 字节） | mapper 状态字节级对 Cart 迁移敏感 |

**关键差异**：
- `savestate_regression_test` 包含 CPU 内部寄存器、PC、timestamp 等
  —— 这些**不应**受 v1.7 Cart 迁移影响，所以 v1.7 不会触发 savestate
  回归测试失败
- `mapper_byte_diff_test` **只**捕获 mapper 寄存器，**专门**捕捉
  Cart 迁移导致的 mapper 状态变化
- 两者**互补**：savestate_regression_test 验证完整 savestate 不变；
  mapper_byte_diff_test 验证 mapper 行为不变（更细粒度）

### 1.3 字节级 vs MD5 抉择

**结论**：**字节级 memcmp**（与 `ppu_frame_diff_test` / `apu_wav_diff_test` 一致）。

理由：
- mapper 状态二进制 ~256-512 字节，足够小，memcmp 开销可忽略
- MD5 隐藏具体差异位置；memcmp 直接指向第几个字节漂移
- v1.5 / v1.6 已建立字节级 diff 惯例，CI 工具链（`cmp` / `xxd`）一致
- 若未来 golden 体量增长到 KB 级，再切到 MD5 + diff tool

## 2. Golden 文件格式

### 2.1 文件路径

```
tests/fixtures/golden_mapper/
    nrom.bin           # NROM 60 帧 mapper 状态快照
    mmc1.bin           # MMC1 90 帧
    mmc3.bin           # MMC3 120 帧
```

**文件名约定**：与 ROM mapper 类型一一对应（小写，无后缀）。**不**含
ROM 名字 / 帧数（避免每换一个测试 ROM 就生成新 golden；多 ROM 共享
mapper 时用同一个 golden）。

### 2.2 二进制格式

```
偏移    大小    字段
─────────────────────────────────────────────────────
0       8       magic = "FMAP\0\0\0" (8 bytes, ASCII + 3 个 null)
8       4       version = 1 (uint32 LE)
12      4       total_size (uint32 LE, 包含 header 的总大小)
16      ...     mapper-specific body
```

**Total size**：v1.7 初始固定为 ~256-512 字节（header 16 + body 240-496）。
保留 uint32 字段以备 v1.8 Masonry 加入更多 mapper 时扩展。

### 2.3 Magic + Version 字段

`"FMAP\0\0\0"` magic 用于快速识别（grep -l "FMAP"）；
version 字段允许未来扩展格式而不破坏向后兼容（类似 ELF e_ident）。

**v1.7 当前版本**：version = 1。

**v1.8 / v1.14 升级路径**：若 body 格式需变，version 字段升级到 2；
测试同时支持 v1 + v2 读取（双版本兼容）。

### 2.4 Body 格式（per mapper）

每个 PoC mapper 的 body 由 `Cart::save_mapper_state()` 虚方法返回
（v1.7 Phase E/F 实现）。body 是 **mapper 特定的二进制快照**，不
带字段名 / 长度前缀 —— 完全扁平，由 mapper 子类自行决定字段顺序。

#### NROM body (~64 bytes)

```
偏移    大小    字段
──────────────────────
0       4       PRG bank 0 (uint32 LE) — 通常为 0
4       4       PRG bank 1 (uint32 LE) — 通常为 0
8       4       CHR bank 0 (uint32 LE) — 通常为 0
12      4       mirror mode (uint32 LE) — 0/1/2/3 (MI_*)
16      4       wram_size (uint32 LE)
20      4       battery_wram_size (uint32 LE)
24      ...     SaveGame buffer 内容快照（前 32 字节）
56      8       MD5 hash
─────
total: 64 bytes
```

**NROM 是最简单的 mapper**：固定 PRG/CHR bank，无寄存器写 handler。
64 bytes 是合理上限（实际有意义数据 ~40 bytes，padding 到 64）。

#### MMC1 body (~256 bytes)

```
偏移    大口    字段
──────────────────────────────────────────
0       4       MMC1 shift register (uint32 LE)
4       4       MMC1 PRG bank 0 (uint32 LE) — $8000-$BFFF
8       4       MMC1 PRG bank 1 (uint32 LE) — $C000-$FFFF
12      4       MMC1 CHR bank 0 (uint32 LE) — 低 4KB CHR
16      4       MMC1 CHR bank 1 (uint32 LE) — 高 4KB CHR
20      4       MMC1 mirror mode (uint32 LE)
24      4       MMC1 PRG mode (uint32 LE, 0/1: 32K switch)
28      4       MMC1 CHR mode (uint32 LE, 0/1: 8K switch)
32      4       MMC1 PRG bank mask (uint32 LE)
36      4       MMC1 CHR bank mask (uint32 LE)
40      8       MMC1 write count (uint64 LE, 自 init 起)
48      ...     SaveGame buffer 内容快照（前 64 字节）
112     ...     PRGptr[2] + CHRptr[2] (4 pointers × 8 bytes)
144     8       MD5 hash
152     ...     PRG CRC32 (4 bytes) + padding
─────
total: 256 bytes
```

**MMC1 body 包含 SxROM 变体**：Mapper1 / Mapper11 / Mapper155 共享同一
body 格式（由 MapperNN_Init 决定具体寄存器数）。

#### MMC3 body (~512 bytes)

```
偏移    大小    字段
────────────────────────────────────────────────────
0       4       MMC3 PRG bank 0 (uint32 LE)
4       4       MMC3 PRG bank 1 (uint32 LE)
8       4       MMC3 CHR bank 0 (uint32 LE) — 2KB bank 0
12      4       MMC3 CHR bank 1 (uint32 LE) — 2KB bank 1
16      4       MMC3 CHR bank 2 (uint32 LE) — 1KB bank 2 ($1000-$17FF)
20      4       MMC3 CHR bank 3 (uint32 LE) — 1KB bank 3 ($1800-$1FFF)
24      4       MMC3 CHR bank 4 (uint32 LE) — 1KB bank 4 ($1C00-$1FFF)
28      4       MMC3 CHR bank 5 (uint32 LE) — 1KB bank 5 ($1C00-$1FFF)
32      4       MMC3 mirror mode (uint32 LE)
36      4       MMC3 PRG mode (uint32 LE, 0/1)
40      4       MMC3 CHR mode (uint32 LE, 0/1)
44      4       MMC3 IRQ counter (uint32 LE)
48      4       MMC3 IRQ counter reload (uint32 LE)
52      4       MMC3 IRQ enable (uint32 LE)
56      4       MMC3 IRQ pending (uint32 LE)
60      4       MMC3 a12 filtering (uint32 LE) — clock filter mode
64      8       MMC3 clock cycles total (uint64 LE)
72      ...     SaveGame buffer 内容快照（前 128 字节）
200     ...     PRGptr[2] + CHRptr[8] (10 pointers × 8 bytes)
280     8       MD5 hash
288     4       PRG CRC32
292     ...     padding
─────
total: 512 bytes
```

**MMC3 body 是最大的**：MMC3 是 v1.7 §6 bench ROM，PoC 风险最高，所以
body 设计成包含所有 28 个共享 mapper 的关键寄存器变体，确保任何
v1.7 Phase F commit 触发的 mapper 状态变化都能被检测到。

### 2.5 字节序

**所有 uint32 / uint64 字段使用 little-endian (LE)** —— 与
NES 6502 / x86 / FCEUX11 内部表示一致。`memcmp` 直接比较，无需转换。

## 3. 状态捕获 API 设计

### 3.1 Cart 虚方法（Phase E/F 实装）

```cpp
// src/cart_class.h
class Cart {
public:
    // ... 既有方法 ...

    // Phase E/F: 返回 mapper 状态二进制快照（写入 out buffer）
    // 默认实现返回 0 字节（base Cart 没有 mapper 状态）
    virtual size_t save_mapper_state(void* out, size_t max_size) const noexcept {
        (void)out; (void)max_size;
        return 0;
    }
};
```

### 3.2 NromCart / Mmc1Cart / Mmc3Cart 重写（Phase E/F）

```cpp
// src/boards/nrom_cart.h
class NromCart : public fceu11::Mapper {
public:
    size_t save_mapper_state(void* out, size_t max_size) const noexcept override {
        if (max_size < 64) return 0;
        uint8_t* p = static_cast<uint8_t*>(out);
        uint32_t zero = 0;
        std::memcpy(p + 0, &zero, 4);  // PRG bank 0
        std::memcpy(p + 4, &zero, 4);  // PRG bank 1
        std::memcpy(p + 8, &zero, 4);  // CHR bank 0
        std::memcpy(p + 12, &currCartInfo->mirror, 4);
        std::memcpy(p + 16, &currCartInfo->wram_size, 4);
        std::memcpy(p + 20, &currCartInfo->battery_wram_size, 4);
        // SaveGame 前 32 字节
        if (!currCartInfo->SaveGame.empty()) {
            std::memcpy(p + 24, currCartInfo->SaveGame[0].bufptr,
                        std::min<size_t>(32, currCartInfo->SaveGame[0].buflen));
        } else {
            std::memset(p + 24, 0, 32);
        }
        std::memcpy(p + 56, currCartInfo->MD5, 8);  // MD5 前 8 字节
        return 64;
    }
};
```

**MMC1 / MMC3 实现类似**，只是字段偏移 + total_size 不同。

### 3.3 与 v1.0 mapper 字段的关系

**v1.7 决策**：直接读 `currCartInfo->mirror` / `currCartInfo->SaveGame`
等 v1.0 字段（兼容层双写目标）。这样 `save_mapper_state()` 实现
不需要额外的数据通道 —— v1.0 mapper 状态已经在 `currCartInfo` 中。

**v1.8 Masonry 后续**：mapper 子类化完成后，`save_mapper_state()`
改为读 mapper 子类的内部字段（`this->prg_bank_` 等），不再依赖
`currCartInfo`。

### 4.2 --generate 模式

```bash
./mapper_byte_diff_test --generate
```

行为：
- 对每个 `RomTestCase` 调用 `generateGolden(test)`
- 写入 `tests/fixtures/golden_mapper/<name>.bin`
- 输出 `[GENERATE] <name>: <size> bytes written`
- 退出码 0

**v1.7 Phase E (NROM PoC)**：第一次跑 `--generate` 捕获 NROM golden
**v1.7 Phase F (MMC1 + MMC3 PoC)**：跑 `--generate` 捕获 MMC1 / MMC3 golden
**v1.8 Masonry**：批量 mapper 迁移时按需捕获新 golden

### 4.3 SKIP 行为（Phase A 当前状态）

Phase A 提交时 `fixtures/golden_mapper/` 目录**不存在**（无任何 .bin 文件）。
verifyGolden() 检测到 golden 文件缺失时：
- 打印 `[SKIP] <name>: golden not generated yet (run --generate first)`
- **不计入** fail
- 测试退出码 0（SKIP ≠ FAIL）

**与 v1.5 `golden_savestate_test` 的 placeholder 行为一致**：SKIP 而非 FAIL。

**Phase E 完成条件**：`tests/fixtures/golden_mapper/nrom.bin` 存在，
NROM test 不再 SKIP，byte-diff = 0。

### 4.4 CTest 注册

```cmake
# tests/CMakeLists.txt
fceux11_add_test_executable(mapper_byte_diff_test
    SOURCES tests/core/mapper_byte_diff_test.cpp
    DEPENCIES fceux11_core
)
```

仿 `apu_wav_diff_test` 注册模式（带 Win32 vcpkg-DLL PATH 注入）。

### 4.5 watchdog

仿 `apu_wav_diff_test` 加 per-frame watchdog：`WATCHDOG_SECONDS_PER_FRAME = 30.0`
防止 mapper init 卡死（28 个 mapper number 共享的 mmc3 在极端情况下可能
init 卡住）。

## 6. 错误处理

| 场景 | 行为 | 退出码 |
|---|---|---|
| golden 文件缺失 | SKIP + 提示 `--generate` | 0 |
| golden 文件 magic 不匹配 | FAIL + 错误信息 | 1 |
| golden 文件 version 不匹配 | FAIL + 错误信息 | 1 |
| golden 文件 total_size 不匹配 | FAIL + 错误信息 | 1 |
| mapper state capture 返回 0 字节 | FAIL（说明 Cart::save_mapper_state 未实装） | 1 |
| mapper state capture 返回字节数 ≠ 期望 total_size | FAIL + 错误信息 | 1 |
| body byte-diff ≠ 0 | FAIL + 第一个差异字节偏移 | 1 |
| ROM 加载失败 | FAIL + 错误信息 | 1 |
| 帧超时（>30 秒/帧） | FAIL + watchdog 触发 | 1 |

| 维度 | ppu_frame_diff_test | apu_wav_diff_test | mapper_byte_diff_test |

| Version | 无 | 无 | uint32 LE (=1) |
| Diff 机制 | memcmp | memcmp | memcmp |
| --generate 模式 | ✅ | ✅ | ✅ |
| SKIP 行为 | 无（v1.5 已有 golden） | 无（v1.6 已有 golden） | ✅（v1.7 Phase A 无 golden） |
| CTest 标签 | （无 perf 标签） | （无 perf 标签） | （无 perf 标签） |

**mapper_byte_diff_test 是第三个字节级 diff 测试**；前两个（ppu / apu）
已成 CI 习惯，mapper 沿用同样模式。
