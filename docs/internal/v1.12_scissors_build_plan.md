### 0.2 拆分原则

1. **纯代码移动**：拆分操作不改变任何行为的运行时结果。每 Phase 完成后运行对应回归测试，确认零 diff。
2. **编译单元新增即风险**：v1.6/v1.7/v1.11 的 layout-shift 教训表明，新增 .cpp 文件会重排链接图、扰动热路径指令布局（即使代码逻辑完全不变）。v1.12 的 4 个目标文件各拆为 3~10 个新 .cpp，layout-shift 累积效应必须监控。
3. **内联/头文件优先**：热路径中的拆分单元（如 ppu.cpp 的渲染函数）应尽量放入 `.h` 或声明 `inline`，避免因跨 TU 调用引入非预期的间接跳转。
4. **信号/槽延迟绑定**：Qt 子控制器的信号/槽在构造函数中硬连接即可，不用 `connect` 字符串形式（已在 v1.10 移除）。
5. **共享状态通过 Context 结构体传递**：每个拆分子模块的共享状态集中到 `*Context` 结构体，由主窗口持有 `std::unique_ptr<Context>` 并注入子模块引用。

class TasEditorContext : public QObject {

### 2.4 特别注意事项

1. **`loadTranslation()` / `retranslateUi()`**（v1.11 §11.5.3 强化）：`ConsoleWindow` 中翻译加载与 `retranslateUi()` 是 v1.11 的重要交付成果。拆分后 `retranslateUi()` 保留在主窗口，负责遍历所有子模块的 `retranslate()` 方法；每个子模块暴露 `void retranslate()` 公共方法。

3. **菜单栏 update 钩子**：部分菜单项需在 `updateMenu()` 中动态启用/禁用（如"关闭 ROM"在无 ROM 加载时灰化）。`ConsoleMenu::updateState()` 接收 `ConsoleWindowContext` 引用，集中处理所有 enable/disable 逻辑。

### 4.3 热路径保护

ppu.cpp 包含**热路径代码**（渲染循环每帧执行数万次），拆分必须确保：

| 函数 | 调用频率 | 拆分后位置 | 保护措施 |
|------|----------|------------|----------|
| `Ppu::loop()` | ~29780 次/帧（NTSC） | `ppu_rendering.cpp` | 声明 `__forceinline` in header |
| 背景 tile 获取 | ~960 次/帧 | `ppu_rendering.cpp` | `__forceinline` in header |
| 精灵评估 | 64 个精灵/帧 | `ppu_rendering.cpp` | `__forceinline` in header |
| 像素合成 | ~61440 次/帧 | `ppu_rendering.cpp` | `__forceinline` in header 或保留在原 .cpp |
| `Ppu::write_2000()` ~ `write_2007()` | 寄存器写入 | `ppu_core.cpp` | `__forceinline` in header |

### 4.4 迁移顺序

| 批次 | 文件 | 说明 |
|------|------|------|
| A | `ppu_state.h/cpp` | Savestate 逻辑，完全自包含，风险最低 |

## 8. 性能预算

### 8.1 每 Phase 的 layout-shift 容忍值

基于 v1.6/v1.7/v1.11 的教训，每个 .cpp 拆分成多个 .cpp 会因链接图重排导致 MSVC 生成不同的指令布局。以下为每 Phase 的容忍值：

| Phase | 新增 .cpp 数 | 预测退步方向 | 容忍值 | 超值动作 |
|-------|-------------|-------------|--------|----------|
| §1 TasEditor | 10 | GUI 代码 → 基准测试无影响 | +0% | —（GUI 代码不影响模拟热路径） |
| §2 ConsoleWindow | 7~8 | GUI 代码 → 基准测试无影响 | +0% | — |
| §3 AviRecord | 3 | GUI 代码 → 基准测试无影响 | +0% | — |
| §4 ppu | 3 | 🔴 热路径受影响 | +1.0% per batch | 任一 batch > 1% 即回滚该 batch |
| §5 movie | 3 | 🟡 轻微影响 | +0.5% per batch | 任一 batch > 0.5% 即回滚该 batch |
| §6 ppuViewer | 5 | GUI 代码 → 无影响 | +0% | — |

### 8.2 性能验证方法

采用 v1.10 §10.6.6 的验证协议：

1. `git worktree add` 创建 v1.11 baseline 独立工作树
2. 链接 `vcpkg_installed`（`mklink /J`）共享依赖
3. 构建 v1.11 baseline，从 `tests/` 目录运行 `fceux11_bench_tolerance_test.exe`
4. 当前版本同样从 `tests/` 目录运行
5. **顺序执行**（非并行，避免 CPU 竞争），各跑 3 轮取 best-of-3
6. 对比 best-of-3 的 `bench_full_frame` / `bench_ppu_frame` / `bench_cpu_frame` 中位数，计算退步百分比
7. 仅在 **ppu 和 movie 拆分批次**（§4、§5）要求强制 bench 验证；GUI 拆分批次（§1、§2、§3）仅在所有批次完成后的 Phase H 做一次综合 bench
