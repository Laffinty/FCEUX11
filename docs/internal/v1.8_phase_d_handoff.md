## 2. Phase D.11 — what landed and why

### 2.1 Root cause: D.10 build break

D.10 added the `MapperEntryRegister` blocks to 12 board files (Phase D.4-D.8
work) but the build failed for those files with `cart.h:11` errors
(`extern CartInfo *currCartInfo;` used before any CartInfo forward declaration
was guaranteed to be visible). The pre-D.10 source relied on `bus.h`'s
forward declaration reaching `cart.h` via `fceu.h`, but the board TUs include
`cart.h` via `mapinc_base.h` before `registry.h`, so the order was
non-deterministic depending on the D.10 `FCEU_DECLFW_GUARD` timing.

The user (working in WIP) had worked around this with `#if 0 ... #endif`
wrappers around the 12 `MapperEntryRegister` blocks. The proper fix landed
in D.11.

### 2.2 The proper fix (D.11 commit `ce485ee`)

1. **`src/cart.h`**: added explicit `struct CartInfo;` forward declaration
   at the top (line 16) before the `extern CartInfo *currCartInfo;` use.
   This guarantees `CartInfo` is declared regardless of include order.
2. **`src/boards/_cart_helpers.cpp`**: `GameHBIRQHook` is declared in
   `ppu.h:26`, not `x6502.h` — swapped the include.
3. **`src/boards/datalatch.cpp`**: updated the comment block above
   `kUnromRegister` / `kCnromRegister` / `kAnromRegister` / `kCpromRegister`
   to reflect that the registration is now re-enabled (not `#if 0`).
4. **Removed the `#if 0 ... #endif` wrappers** from 11 board files
   (32, 33, 34, 36, 40, 41, 42, 43, 46, 50, vrc2and4) so the D.4-D.8
   registrations are active again. After the WIP tree's `#if 0` stopgap
   wrappers were removed, these 11 files reverted to the D.10 committed
   state (registration code present, no `#if 0` guards) — so they appear
   as zero-diff in `git diff HEAD` and required no separate commit.

## 3. Known pre-existing failures (NOT introduced by D.11)

### 3.0 Bisect findings (added by P0 review)

The `rom_regression_test` + `savestate_regression_test` SEGFAULT was
**introduced at Phase D.3 commit `55771fd`** (Mmc3BaseCart + Strategy A
pattern), not by D.10 or D.11. Bisect across cb0fed9 → b8f2c23 → 19bb254
→ 55771fd → 8746431 → b09bc45 confirms:

| commit | build | rom_regression |
|---|---|---|
| ce485ee (D.11) | ✅ | SEGFAULT at 10th ROM (vrc2and4) |
| 06c19d7 (D.10) | ✅ (WIP fix) | SEGFAULT at 10th ROM |
| cb0fed9 (D.8) | ❌ cart.h | (build broken) |
| b8f2c23 (D.7) | ❌ cart.h | (build broken) |
| 19bb254 (D.4) | ✅ (re-include hack) | SEGFAULT at 3rd ROM (UNROM) |
| 55771fd (D.3) | ✅ (re-include hack) | SEGFAULT at 3rd ROM (UNROM) |
| 8746431 (D.2) | ❌ cart.h | (build broken) |
| b09bc45 (D.1) | ❌ cart.h | (build broken) |

D.11's `cart.h` forward decl is the **cleanest** of the build fixes
(prior fixes were re-include hacks at file tail, e.g. D.3's
`#include "../cart.h"` after the namespace, D.4's re-include of
`nrom_cart.h` / `datalatch_carts.h` / `registry.h` in datalatch.cpp).
D.4's hack was brittle — adding 12 more MapperEntryRegister blocks
in D.7-D.8 (each in a file that didn't have the hack) broke the build
again, which is why the user added the WIP `#if 0` wrappers.

The Strategy A pattern's `on_power()` in `src/boards/mapper_strategy_a.h:27-29`
calls `currCartInfo->Power()` directly, which is the call path that
SEGFAULTs when state from a previous ROM load isn't cleaned up. Fix is
**Phase E proper lifecycle wiring** — not a build issue, not a wrapper
issue.

### 3.1 cart_class_test 82/85 PASS — 3 known failures

All 3 are `find_mapper(406)` returning `nullptr` even though
`kMapper406Register` is registered in `mmc3.cpp`. Root cause: a single
translation unit overwrites the registry slot via a separate Init.
Documented in D.10 commit message; tracked in `v1.8_masonry_build_plan.md`
§11.10 followups. Fix: identify the overwriting TU in Phase E and either
remove the duplicate Init or have the second Init register under a
different mapper number.

### 3.2 rom_regression_test + savestate_regression_test SEGFAULT at vrc2and4

Both tests load multiple ROMs sequentially via `load_rom()`. The 10th ROM
(`mapper_vrc2and4.nes`, mapper 21) SEGFAULTs. Root cause: the legacy iNES
loader's `GI_CLOSE` path assumes a single Init/Power sequence, and the
Strategy A `on_power` depends on `currCartInfo` being freshly written by
the Init it just dispatched. The state from earlier ROM loads is not
cleaned up properly.

Documented in D.10 commit message. Fix is **Phase E proper lifecycle
wiring** (the same lifecycle fix noted in `datalatch.cpp` comment before
D.11's cleanup). The WIP tree's `#if 0` wrappers were a stopgap; D.11's
re-enable keeps the registration active so Phase E has a working baseline
to fix the lifecycle against.

### 3.3 mapper_byte_diff_test 3/3 [SKIP]

`tests/core/mapper_byte_diff_test.cpp` still has 3 test cases (nrom, mmc1,
mmc3) all in [SKIP] mode. The body byte-diff is deferred until each Cart
subclass implements `save_mapper_state()`. The API is in place (D.2), but
the per-mapper overrides haven't been written. Deferred to **Phase E §6.4**.
