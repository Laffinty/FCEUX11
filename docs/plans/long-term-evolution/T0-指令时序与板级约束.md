## ② kgmqa-078-serom-lidnariq

| 字段 | 值 |
|---|---|
| ROM | `lidnariq/serom/serom.nes` |
| 错误码 | `0xC3` |
| known_limit | MMC1 SEROM/SHROM bank-size constraint not modeled　**← 已过时，见下** |

### 根因（**原判断错误**；实测为两个独立缺陷，1 掩盖 2）

**缺陷 1（承载项）**：`$6000` 未被映射。ROM 头 NES 2.0 `mapper=1 submapper=5 PRG-RAM=0`，
`DetectMMC1WRAMSize()` 只对 **NES 2.0** 板信头部字段 → 0 KB WRAM；
**同一 ROM 写成 iNES 1.0** 则会落到该函数开头的 `int ws = 8;` 默认值 → 8 KB。
0 KB WRAM 意味着 `$6000` 无读写 handler，blargg 结果寄存器写不进去，
runner 读回一个常量 → `0xC3`。**与 mapper 译码无关**：改 mapper 行为不会有任何变化。

**证明**（零成本 header patch，不改代码）：把 byte10 低半字节改成 7（8 KB PRG-RAM），
其余字节不动 → `exit=0 value=0x00 PASS`。

**缺陷 2（规范项，非承载）**：submapper 5 = **Fixed PRG**
（SEROM / SHROM / SH1ROM，**PRG ROM A14 硬接 CPU A14，完全无 PRG bank 控制**；
ROM 自带字符串即述「do not support PRG banking at all」）。
`bmap[]` 只按 mapper 号索引，submapper 从未到达 mapper 层。

**但本 ROM 测不出差异**：32 KB PRG 时 `PRGmask16=1`，
32K 模式下 `(prg_reg & ~1) & 1` 恒为 0，与固定映射**数值上完全相同**。
A/B（同样 8K WRAM，只改 submapper 字节）→ submapper 0 与 5 **都 PASS**。

### 步骤

- [x] 读 `src/boards/` MMC1 CHR/PRG bank 写路径（+ `DetectMMC1WRAMSize` 的 `ws=8` 默认值）
- [x] 实现 submapper-5 路由：PRG-RAM 为空时回退 8 KB（承载项）+ `isFixedPRG` 固定映射
- [x] 单 ROM 验证 `$6000 == 0x00`（exit=0 / value=0x00 / diag 全 0）
- [x] 回归：ctest 34/34、blargg 177 ROM 147P/30F、矩阵 `pass_to_fail=0`

### 验收

kgmqa-078 PASS；`serom.nes` L2 PASS。
→ **已达成**（v1.18.2）：矩阵 107P/13F → **108P/12F**，`fail_to_pass=1`，`pass_to_fail=0`，grade B 不变，advisory 10.8% → 10.0%。
→ `serom.nes` 不在 blargg 177 manifest 内，故无独立 L2 条目。

### 风险

低–中。约束勿过严；用 mapper_byte_diff + 商业 ROM smoke 兜底。
→ **未触发**：`mapper_byte_diff` 与 `golden_savestate` 均通过，**无金标重生成**。
影响面经核实仅 `serom.nes` 一个镜像（fixture 集里唯一的 mapper 1 + submapper 5 + PRG-RAM=0）。
