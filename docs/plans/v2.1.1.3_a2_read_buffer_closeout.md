### 0.1 A.2 partial fix 记录 (commit bb4a9f2 2026-09-08)

**修复**: `src/rust/crates/fceux11-ppu/src/frame.rs:187` 把 `sl == 241 && dot == 1` 改为 `sl == 241 && dot == 0`，跟齐 C++ 引擎 (`build-ab-cpp/`) 的 "Working config: VBL at cycle 0" (per `ppu_rendering.cpp:1696` 注释)。

**tracediff 实证** (vbl_02_set_time.nes, 2400 frames):

| Engine | dot | diag (前 4 行) | hash |
|--------|-----|----------------|------|
| C++ engine (build-ab-cpp/) | cycle 0 | `00 - V / 01 - V / 02 - V / 03 - V` | `4103C340` |
| **Rust (this commit, bb4a9f2)** | **dot 0** | `00 - V / 01 - V / 02 - V / 03 - -` | **`C4BE5BE4`** |
| Rust (pre-fix, ef19eb5) | dot 1 | `00 - V / 01 - V / 02 - - / 03 - V` | `933AF95A` |

**结论**:
- Rust dot=0 修了 row 02 col 2 (从 `- -` 变 `- V`，与 C++ 一致)
- Rust 仍 1-row behind C++ (row 03 col 2: Rust `- -`，C++ `- V`)
- 这是 v2.1 4-sweep 失败的"frame layout alignment"类别，需要 architectural fix
- test 33 仍 FAIL，但 diag 现在与 C++ 引擎 byte-pattern 一致 (row 02)
- test 34 (frame 2) + test 35 (savestate) PASS 不变 (VBL set dot 不影响 frame 2/savestate golden)

**v2.1 6.1.e.v3 历史修正**: 之前 946ee31 revert 把 dot=0 实验否定了，理由是 "blargg 02-vbl_set_time calibrated to dot-1"。但 C++ 引擎本身就使用 cycle 0，**v2.1 推理把"硬件 spec dot=1"和"blargg 校准"混淆了**。empirical tracediff 明确显示 C++ cycle 0 才是正确校准。

**Do-NOT 不需**: diag hash 变化不在 tracked golden 中（diag hash 仅在 env-gated 探针输出，不影响 frame 2/savestate golden 文件）

## 2. A.1-2 read_buffer 0x1B=27 现状

### 2.1 修复 #2 进展

`commit ef2ba86` `fix(ppu-v2.1.1): skip v-walk when rendering off` 让 kagami read_buffer 从 **0x80 卡死** 推进到 **0x1B=27**（ROM 验证循环现在能完成 0x1B 步）。剩余 53% 失败归因：

> 引用 523059b commit message 修复 #2: "Now completes (0x1B, remaining failures in the sprite0-hit/DMA phase)."

### 2.2 根因定性（plan §A.3 / §A.4 范围）

- **sprite0 hit 误报**（sprite 0 hit 状态在 sprite 0 OAM 数据未就绪时不应 set）
- **DMA 仲裁**（$4014 OAM DMA 与 DMC fetch 的周期占位；`fceux11_ppu_dmc_dma_arbitration` Phase 6.3.c.2 follow-up 未实现）
- **`$2007` 写时序**（VRAM address increment 在不同 PPU 模式下的差异）

三者可能共根因（VBL 家族的同源 timing 漂移），也可能独立。

### 2.3 父 plan §B.2 联动（rendering-missing 大问题）

> 引用 v2.1.1_build_plan.md §B.2: "183 个 no-render 可能与 02-vbl_set_time 的 VBL 时序漂移同族（游戏在启动期等 VBL/NMI 挂死，永远不使能渲染）。"

bb4a9f2 修了 A.2 dot 校准，但 read_buffer 未改善（仍 0x1B=27）。**说明 read_buffer 与 VBL set dot 校准无关**，是独立根因（DMA 仲裁 + sprite0 hit）。

### 3.2 A.2 帧布局对齐（frame layout alignment）

bb4a9f2 修了 1-dot shift 的"set dot"维度。row 03 仍 1-row behind C++ 是另一个 1-row 偏移。两者相加应该是 1-row 后累积成 2-row。说明还有第三个 1-dot shift 在"frame layout"维度（sl -1 起点或 cycle counter 偏差）。

诊断方向：
1. 比对 C++ 和 Rust 在 sl -1 处的 vblank clear 行为（应在 dot 1 触发）
2. 比对 C++ 和 Rust 在 sl 0 处的渲染开始行为
3. 比对 cycle counter 起点（0 vs 1）
4. 看 `state.rs:204` "VBL flag set event at (sl 241, dot 1) lands in dot 1 of the frame" 注释

### 3.3 A.1-2 read_buffer 修复

- 与 A.2 frame layout 修复独立
- 需要 trace DMA 仲裁 + sprite0 hit 路径
- 可能需要新增 `fceux11_ppu_dmc_dma_arbitration` 实现（plan §A.3）

### 3.4 SKIP_RETURN_CODE for ctest 33

Per plan §A.2 escape valve: "若 Phase A 内无法全绿，底线交付 Grade B + ctest 对该单项临时 SKIP_RETURN_CODE 标注（需 owner 批准，不算静默绕过）"

实施：tests/CMakeLists.txt 的 `add_test(rust_ppu_vbl_nmi_timing_test ...)` 加 `set_tests_properties(... PROPERTIES SKIP_RETURN_CODE 77)`。

注意：这只让 ctest 33 不计入 FAIL，**不解决 kagami matrix grade**（grade 由 47 项 matrix 决定）。

### 3.5 预算

- A.2 帧布局对齐：1-2 session
- A.1-2 read_buffer 修复：1-2 session
- SKIP_RETURN_CODE 实施：0.5 session
- 全量验证 + batch_compat + tag：1 session
- **总计 3-5 session**

### 3.6 风险

- A.2 帧布局对齐可能触及 PPU 帧循环重写（sl -1 起点 + cycle counter）
- A.1-2 read_buffer 可能触及 DMA 仲裁（plan §A.3 已识别）
- 两者合起来可能让 batch_compat 锁档漂移（>±0.6pp 触发回滚）
