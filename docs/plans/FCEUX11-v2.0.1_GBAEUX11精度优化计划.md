## 二、Phase P0 — ARM 模式 SWI 编号修复（最高优先，独立立项）

**缺陷**：`gba-core/src/cpu/arm7tdmi.rs:686-696`，ARM 分支取 `swi_instr & 0xFF`；
真机约定（三重佐证）：THUMB SWI 编号 = 指令 bits 0-7，**ARM SWI 编号 =
指令 bits 16-23**。规范编码 `swi 0x060000`（Div，jsmolka/AGS 风格）被读成
0x00 = SoftReset → 任何 ARM 模式 BIOS 调用触发软复位循环。
佐证：① jsmolka 全部 ARM 编码按 bits 16-23；② mGBA 0.10.5 对同指令解码为 06
（外测报告 §五）；③ devkitPro/libgba `src/Div.s` 为 `.code 16`（THUMB）用
`swi 6`、而 ARM 汇编惯用 `swi 0x60000`——两种约定并存且都依赖正确分支。

**改动**：ARM 分支改 `(swi_instr >> 16) & 0xFF`（THUMB 分支不动）。
**同时改本仓库三处一手编码器**（`gate.rs` 的 `swi()`、`swi/mod.rs` 的
`arm_swi()` 与 `SWI_HALT_WORD`）——它们此前把编号写进低 8 位，是靠缺陷才绿的，
见 §十一 r1 ③。
**登记**：ATTRIBUTION §3.2（arm7tdmi.rs 本地补丁 10 处 → 11 处）。
**验证**：
1. 新锁测试：ARM 模式构造 `swi 0x060000` 断言 Div 语义生效且 CPSR/寄存器无
   SoftReset 副作用；变异可红（改回 `& 0xFF` 必须转红）。
2. jsmolka arm/bios 复跑：从"挂死"变为正常判卷（arm 应显示 Failed test 234，
   bios 显示 Failed test 001，参照报告 §五/§七）。
3. `ctest -LE perf` 全绿；SMA4/MKSC harness 冒烟。

## 三、Phase P2 — ~~S/N（顺序/非顺序）访问跟踪重构~~ → **等待窗口调查**（2026-10-06 改向）

> **改向裁决（用户，2026-10-06）**：本 Phase 原来的内容 —— 按 mGBA 语义重写
> `bus.rs` 的 S/N 跟踪 —— **正式取消**，因为它的前提被自己的证据证伪（§十一
> r2 ⑤：AGS 那两个 WAIT 测试测的是同一地址连读 4 次，本仓库 `last_used_address`
> 存起始地址的写法在这种情形下**恰好判对**，所以改 S/N 粒度动不了它们）。
> **基于自相矛盾数据的任何「修复」都是 r33 型错误**，故不改。
>
> **本 Phase 现为「等待窗口调查」**：先用差分探针把「我们测到多少」与「真机是多少」
> 的差逐周期定位，再决定改什么。**在裁决出该改哪一行之前，不动 `access_cycles`。**
> 当前进展见 §十一 r3/r4。
>
> 以下原文保留，作为**已证伪前提**的记录，不是待办。

**现状**：`bus.rs::access_cycles` 用单一全局 `last_used_address` 判顺序性
（`address - last_used_address == size`）。取指与数据访问交错时该启发式失效
——AGS 的测量循环里几乎每次数据访问都被误判为非顺序。

**目标语义**：参照 mGBA `memory.c`（`GBA_BASE_WAITSTATES*` 四张表 +
`GBARomWaitstates`/`GBARomWaitstatesSeq` = 非顺序 {4,3,2,8}、顺序
{2,1,4,1,8,1}，memory.c:37-42）的 S/N 判定方式实现；关键是明确
"上一个总线访问"的跟踪粒度（mGBA 以最近一次访问的地址+宽度为准，取指与
数据访问同流参与）。**只读参照，不抄代码**；语义对齐后按我们的结构实现。

**改动点**：`bus.rs` 的 `last_used_address` 跟踪 → 按 mGBA 语义重实现
（含 `read_opcode_*` 与数据访问同流）。
> **⚠️ 本节的「改动点」已被证伪，不要照做。** r4 ③ 证明按 stub 的 boot 值起算，本仓库
> 的 `2 + N + S` 逐读计价**与真机一致**，AGS 期望表在两边都留下**恒定残差**（12 / 15）
> —— 差异全在常数项，与每次读的计价无关。**N+S 线正式关闭**（r5 ①）。
>
> 调查已分裂为**两条独立线，不要混成一条**：
> · **线 A（访问层）**：`access_cycles` 的访问计价已平反，剩「窗口内恒定 3 周期」的
>   常数差，对应 AGS 的 `WAIT STATE` / `RAM WAIT` 两项。
> · **线 B（指令层）**：r6 实测**纯 IWRAM 指令时序是硬件的 2 倍**（`SUBS`+`BNE` 循环
>   8.00 周期/迭代 vs 真机 4.00，`TM0` 与 `master_cycles` 同向印证），**完全不碰
>   `access_cycles`**，对应 AGS 的 `TIMER PRESCALER`（很可能含 `TIMER CONNECT`）。
>
> **`access_cycles` 与 `arm7tdmi` 均一行未动**（用户指示）：先拿数据立项。
**验证**：
1. 先行工作项：解码 AGS `sub_800329C`/`sub_8003310` 汇编（Normmatt 仓库
   `src/sub_800326C.arm.s`），提取 WAIT STATE WAIT CONTROL 与 CARTRIDGE RAM
   WAIT CONTROL 的精确期望值（后者已知 0x1C/0x18/0x14/0x2C），写成常量锁测试。
2. AGS 复跑：两个 WAIT 类测试转 0。
3. `ctest -LE perf` + 锁测试全绿 + MKSC/SMA4 冒烟（时序改动可能影响限速感受，
   `bench_tolerance_test` advisory 只看不设卡）。

## 四、Phase P3 — 预取缓冲真模型（替换乐观近似）

**现状**：`bus.rs:1376-1385`——顺序取指在 WAITCNT bit14（预取使能）时按
`size/2` 计（"预取器已跟上"的乐观假设）。真机是 8×16-bit 预取队列：CPU 不占
Game Pak 总线时预取器推进、取指命中则 1 周期/半字、未命中照付等待、数据访问
使缓冲失效。测量循环（数据访问穿插）下乐观假设系统性偏差。

**目标语义**：mGBA 的预取实现（`memory.c:436-452` 的 prefetch 读取、
`gba.c:296` 总线缓冲、ARM 核心侧填充逻辑）——语义级参照。

**验证**：AGS PREFETCH BUFFER 测试转 0；TIMER PRESCALER 的期望值
（{4096,64,16,4}，测量循环 1024×(SUBS+BNE)=4096 周期）依赖预取精确性，
须与 P4 联合验收；`ctest` + 冒烟同上。

## 五、Phase P1 — DMA 传输时序

**现状**：`bus.rs::run_dma_block` 无 DMA 专属时序——逐单元借用
`read_word/write_word` 的 CPU 访问记账；无起始开销、无 DMA 的 S/N 模式。
mGBA 权威语义：**每次 DMA 起始固定 +3 周期**（`dma.c:115/147/175`
`when = now + 3 + cycles`），逐单元按源/目标区域等待周期计算。

**改动点**：`run_dma_block` 增加起始开销与显式逐单元时序（首单元非顺序、
后续顺序；源/目标各自计价），与 CPU 的 `last_used_address` 流解耦。
**验证**：
1. 先行工作项：解码 AGS `TimeDmaToAndFromMemory_U16/U32` 汇编，提取期望
   周期数（内存类测试各含 2 个计时位，是 8/9 内存测试失败的共同成分），
   写成常量锁测试（变异可红）。
2. AGS 复跑：DMA 类转 0；内存类 8 项中仅剩等待/预取相关失败。
3. `ctest` + 冒烟。

## 六、Phase P4 — 定时器计数边界对齐

**现状**：`timers.step(elapsed)` 按累计周期推进；mGBA 以 prescaleBits
{0,6,8,10}（timer.c:124）在事件调度器上精确对齐预分频边界与级联链。
AGS 期望值是**精确数**：PRESCALER 期望 {4096,64,16,4}（1024×4 周期循环）、
CONNECT 期望 512（sub_8009294：TM0 装载 65534、四级级联后读 TM3）。

**改动点**：`timers.rs` 的预分频推进边界（计数发生在分频窗口末端）与
级联递增的瞬时语义对齐 mGBA `timer.c`。
**验证**：AGS TIMER PRESCALER/CONNECT 转 0；把 {4096,64,16,4} 与 512 写成
核心级锁测试（不依赖 AGS ROM）；`ctest` + 冒烟。

## 七、Phase P5 — LCD DISPSTAT 窗口时序

**现状**：`lcd.rs` 在 pixel_index==240 置 HBlank 标志、行界清除；VBlank

**验证**：AGS LCD 7 项全 0；`ctest` + 冒烟。

## 十、开放问题（不阻塞立项）

`0x4017, 0x4017, 0x401F, 0x401F`，与「以某个非零初值起算、套 ROM 自己的掩码 `0xF8FF`、再或上 `setting<<2`」**完全自洽**。顺藤摸到根：**`bios.rs:34` 的 `WAITCNT_DEFAULT = 0x4317` 是我们 stub BIOS 有意写的**（注释原文：「0x4317 is the value a manufactured cartridge runs with — WS0/ROM 3,1 clocks, SRAM 8, prefetch enabled」）。`0x4317 & 0xF8FF = 0x4017`，与四次读回逐位吻合。**所以 WAITCNT 本身没有缺陷，探针也没有错。**（`0x401F` 是用户提示「必然产生于执行期」的那一档，来源就是这里。）

**④ PRESCALER 4096 循环的静态核算 —— 未取到可信读数，但抛出一条更小的候选缺陷。** 程序（IWRAM、纯 `SUBS`+`BNE`、无 Game Pak 无等待态）已汇编并可跑，`PC` 落在程序内，**但 `r0` 回读为 `0x4000204`**，且**另一个探针回读的 `r0` 是同一个值**。`ldrh` 只能写 16 位，这个高 16 位只能是**残留**。**候选缺陷：LDRH 未把目标寄存器的上半部清零**（`ldrh rd,[rn]` 应零扩展成 32 位）。它同时解释了 WAIT 探针里 `r0`-`r3` 的那些垃圾值。**⚠️ 这只是一条线索，尚未做直接验证**（最便宜的直接实验：`gba-core` 里写一条 LDRH 后检查 `rd` 上 16 位的单元测试）。在验证前不得动 `access_cycles`，也不得把它写成已确认缺陷。

**⑤ 同址重读的 S/N 语义（首要假设，未验证）**：用户指出「同址重读」是首要假设。本轮**未读** mGBA `memory.c` 的同址重读处理 —— 预算用在两个探针上了。已知的相关事实：AGS 测的是同址连读 4 次，本仓库的 `last_used_address` 存起始地址使这种情形**恰好判非顺序**（r2 ⑤）；而 AGS 期望表的分解 `base + 4×(n_wait + c)`（c∈{0,1}）里 **c 正是顺序/非顺序那一项**，所以「同址重读到底该算顺序还是非顺序」直接决定 c 取 0 还是 1。**这仍是首要假设，未动。**

**⑥ 「裁决口径」问题的现状**：AGS 期望表在 stub 的 boot 值下残差恒为 12，在真机上表现为 base=8（r2 ④ 用的是默认 s=2）。两者差 4，**且差在 base 而不在每读项**。PRESCALER 是纯指令时序、无内存等待，本应是最干净的裁决工具，但因 ④ 的读数不可信而暂不能用。**裁决前不动 `access_cycles`**（用户指示，已遵守）。 | 读回实验 + 静态核算（差异定位到常数项；新候选缺陷未验证） |

**① 本核其实有完整的预分频实现**：`Timers` 有四个 `tm*_prescaler_counter` 字段、`get_prescaler()`（`1/64/256/1024`）、`advance()` 按分频整除并保留余数，**并且有单测 `prescaler_divides_and_carries_remainder` 覆盖它**。**所以「补预分频」这个判断是错的 —— 错的是它从哪个寄存器取值。**

**测量窗口 = 1024 × (`SUBS` 1S + `BNE` 取 2S+1N) = 4096 主周期** —— 与计划记的 `{4096,64,16,4}` 完全吻合，我的探针循环形状**是对的**。

**② ⚠️ 但那次写入把分频码放进了高半字的 bit0-1。** `(j<<16) | 0x800000` 作 32 位写：`TMxCNT_LO` = **0x0000**（计数器 0、**分频 0**），`TMxCNT_HI` = **`0x8000 | j`**（bit0-1 = j、bit15 = 1）。**按 GBATEK 与 mGBA 的布局，预分频在低半字 bit0-1，使能是高半字 bit7 —— AGS 这一写既没设分频也没使能。**

**③ 于是出现一个我无法在本轮解决的真矛盾**：
· AGS 的期望表**随 j 变化**（4096/64/16/4），说明 j 确实被当分频码用；
· 但 AGS 把 j 写进**高**半字，mGBA 与我 r17 的修复都从**低**半字读；
· 且 AGS 写的 `0x8000` 在 GBATEK 布局下是未用位，**使能位 bit7 从未被置上**。

**④ 可能性（都未验，不下结论）**：(a) AGS 的 `REG_TMCNT(i)` 指向高半字（则低半字才是 HI，整个布局理解要翻过来）；(b) 老化卡上有与标准 BIOS 不同的寄存器行为（该 ROM 本就是老化测试卡，专测非常规时序）；(c) 我对 `&REG_TMCNT(i)` 指向的推断有误。**在 (a)/(b)/(c) 分开之前，r17 那个「分频读低半字」的修复不能算已验证** —— 它通过了单元与探针，但**探针是按我的假设写的**，而 AGS 例程恰好与该假设矛盾。
