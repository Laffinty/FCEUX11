## 1. 升级依据（Do-NOT 触发条件）

### 1.1 修复 #2 v-walk gate 的 NESdev spec 校准性（**非"为测试改"**）

**修复内容**（commit `ef2ba86` `fix(ppu-v2.1.1): skip v-walk when rendering off`）：

- `src/rust/crates/fceux11-ppu/src/rendering.rs` 中 v-walk 函数在 rendering off（mask = 0）时**跳过**次级 OAM clear / sprite evaluation / sprite 0 hit detection
- 23 行净增（+18/-5），与 C++ engine 老 PPU 在 blank path 下的语义对齐

**NESdev wiki `PPU_rendering` 章节**（权威 spec）：

- 渲染关闭时（`PPUCTRL.0` = 0 或 `PPUMASK.rendering` = 0），次级 OAM 不会被清零、sprite evaluation 不发生、sprite 0 hit 检测不发生
- 这意味着：v-walk 的所有 PPU dot 周期行为在 mask = 0 时应被跳过

**C++ engine 对照**（`src/ppu_rendering.cpp:1841-1886` blank path 注释）：

- C++ engine 注释明确：在 rendering off 时，sprite evaluation 阶段直接跳过 v-walk，与 NESdev wiki 一致
- 修复 #2 让 Rust PPU 与 C++ engine 在该路径上**行为一致**

### 1.2 旧 golden（frame 2 = `0xee065d4f`）的形成历史

- 旧 golden 来自 **v0.3.0 旧 PPU 实现**（rust PPU refactor 之前，2025 年之前）
- 旧 PPU 在 mask = 0 时**不严格按 NESdev spec 跳过 v-walk**，产生"巧合正确"的渲染输出
- 这种"巧合正确"是 v0.3.0 时代的 PPU 实现特征，**不是硬件真值**
- 修复 #2 让 Rust PPU 严格按 NESdev spec 跳过 v-walk，**触发了与旧 golden 的不一致**

**根因定性**：旧 golden 与硬件真值（NESdev wiki + C++ engine 行为）有偏差 —— 旧 golden **确实**过时。

### 1.3 修复 #2 单 commit 验证

### 1.4 拒绝 523059b 的根因（**为何不直接 cherry-pick**）

`commit 523059b` 中三个修复打包 commit：
