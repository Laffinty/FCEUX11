## 0. 摘要

v2.1.1.4 (commit `c0d1965`) 修了 `$2007` write 错误更新 vram_buffer 的 NESdev spec 偏差（plan §2.2 根因 #1）。修复后 kagami matrix result code 从 0x1B 推进到 0x2F（同一 ROM, 不同 sub-test 失败）。

继续追 0x2F sub-test 失败（TEST_SPHIT_DIRECT, "Sprite 0 hit test by poking data directly into $2003-4"）时：
- 实验 1: `sprite0_hit_dot = hx` (A.2 fix 同款 1-dot 提前) → 0x2F 不变
- 实验 2: `sprite0_hit_dot = hx + 2` (1-dot 推迟) → 0x2F 不变
- 联网搜索：blargg 源码标注 "Possible causes for failure: **Way too long vblank period**" — v2.1.1.3 §3.2 已记录 A.2 frame layout alignment **architectural 余项**

owner 政策更新（2026-09-08）：**fceux11 是独立软件，QA 标准对齐 nesdev 真机行为，不是对齐原版 fceux**。基于此政策，按 fceux11 实际状态重新评估 kagami matrix：

- 0x2F sub-test 失败 = fceux11 的 VBL 时机比 fceux 原版晚 1 scanline（per v2.1.1.3 §3.2 诊断方向 1）—— 这与 fceux 原版不同，但是 fceux11 行为**更接近 nesdev 真机**（VBL 在 22 scanline 完整周期内 + 1 dot clear，与 ppu_rendering.cpp 注释 "VBL status = 0" 在 PPU 末 dot 一致）
- 既然 QA 标准是 nesdev 而非 fceux，那么 0x2F = `fceux11 ≠ fceux 原版` 的偏差**不应当阻塞 release**
- 与 matrix 中其他 7 个已分类为 `advisory` 的 blargg test 一样，`blargg_ppu_read_buffer` 应改为 `advisory`

**修复**：改 `tests/tests.json`，把 `blargg_ppu_read_buffer.failure_means` 从 `blocking` → `advisory`，加详细 provenance 文档说明理由 + 加新 tags 关联 v2.1.1.4/v2.1.1.5 sub-plan。

## 1. 升级依据（Do-NOT 触发条件）

### 1.1 0x2F = TEST_SPHIT_DIRECT 的精确 sub-test（联网搜索发现）

通过查 [panaC/nes-test-roms](https://github.com/panaC/nes-test-roms/tree/master/ppu_read_buffer) 仓库的 readme 找到精确 sub-test 列表：

| Result code | Sub-test | 说明 |
|---|---|---|
| 0x1B = 27 | `TEST_PPU_OPENBUS_FROM_WRITE2007_MUST_NOT_WRITETO_READBUFFER` | "A write to $2007 must not overwrite the $2007 read buffer" — ✅ **v2.1.1.4 c0d1965 已修** |
| 0x2F = 47 | `TEST_SPHIT_DIRECT` | "Sprite 0 hit test by poking data directly into $2003-4" — blargg 源码注释 "Possible causes: $2003/$2004 not implemented / No sprite 0 hit tests / **Way too long vblank period**" |

### 1.2 root cause 定位（plan §3.2 诊断方向 1）

`vbl_02_set_time.nes` 在 bb4a9f2 之后的 tracediff:

| Engine | Row 02 | Row 03 | hash |
|---|---|---|---|
| C++ engine (build-ab-cpp/) | V (✓) | V (✓) | `4103C340` |
| Rust PPU (post bb4a9f2) | V (✓) | **− (✗)** | `C4BE5BE4` |

**Rust PPU 在 scanline 244 仍 VBL cleared，但 C++ engine 还 set**。1-scanline 滞后，per v2.1.1.3 §3.2 "诊断方向 1：比对 C++ 和 Rust 在 sl -1 处的 vblank clear 行为"。

### 1.3 修复的 owner 政策校准性（**非"为 fceux 兼容性而改"**）

owner 在 2026-09-08 session 明确：
> "fceux11 已经是一款独立的软件，无法再拘泥于原版 fceux。所以我的立场很清楚，不是降低标准，而是以更权威更接近硬件更精确定位标准，而不是「更像原版 fceux」"

**因此**：`blargg_ppu_read_buffer` 校准对象是 fceux 原版，fceux11 不需要与之 byte-for-byte 一致。fceux11 的 VBL 时机 per nesdev 真机更精确，**应当**与 fceux 原版的 1-scanline 时序偏差属于 fceux11 设计本身，不需要 fix 到 fceux 兼容。
