## 2. 改动点（每项独立提交、独立 gate、可回滚）

> **3a 开工勘误（2026-09-15，读通生产环路后修正）**：Phase 5.3 的生产环路 `fceux11_run_frame_interleaved`（src/rust/src/lib.rs:440）**早已是逐 dot 交错**——每 dot 先 tick 1 个 PPU dot，再给 CPU 拨 `ticks_per_dot` 个计数单位（NTSC 16 单位/dot；1 CPU 周期 = 48 单位 = 3 dot）。真正的缺口在 **CPU 预算模型是指令原子的**：`run_with_tick` 的循环是 `while count > 0 { dispatch; execute_step; }`（src/rust/crates/fceux11-core/src/cpu/tick.rs:193），`execute_step` 原子执行整条指令的全部访存——**寄存器写落在"预算首次转正的 dot"，即指令起始 dot**，而硬件上写发生在指令的第 (cost-1) 周期（STA abs：起始后 +3 周期 = +9 dot）。量化误差 = -(cost-1)×3 dot 量级，与 §15.1 E2 的实测漂移幅度一致。因此 **3a 交付"peek 接口 + 等价性验证基建"，3b 交付"写落点 = 起始 dot + (cost-1)×3 dot 的递延投递"**。

1. **stepper 逐周期接口**（`fceux11-core`）——**3a 实际形态**：`peek_next_instruction_cycles`（execute.rs，解码 PC 处操作码返回 base_cycles，零状态变更）+ ffi 导出 `fceux11_cpu_peek_next_instruction_cycles`。尚未接入生产环路（接入点与 MMIO 双读问题在 3b 决定：blargg `cpu_exec_space` 会从 `$4020+` 执行代码，peek 会二次读副作用映射区）。未遂中断、页跨 dummy 读/写周期的建模在 3c/3d。
2. **scheduler 逐周期交错**：每 1 CPU 周期推进 3 PPU dot（PAL/Dendy 按各自比值，见 video_system 表）；**寄存器写在真实落点 dot 生效**（当前是整条指令跑完后才落——E1/E2 的直接根源）。保留 per-instruction 回退路径（scheduler 内部策略参数化，不出 configure 选项）。
3. **中断采样精确化**：NMI/VBL/IRQ 在精确 dot 采样（E4/E5）；`$2001` 重开写与 v 重建点的相对时序自然归位（E1）。
4. **DMA 节拍**：OAM DMA / DMC DMA 以 CPU 周期为节拍注入（每字节 1 周期读 + 1 写停顿，见现有 scheduler 注释），假读/假写触发真实寄存器副作用。
5. **探针对照协议（强制）**：本批每个子改动落地前后，必须按 v2.1.3 计划 §16.4 协议跑 3186_Mario_1.nes 对比：伪影帧复现率、分屏写落点分布、`$2001` 翻转点相对 pre-render 280-304 的落点。**无 probe 数据不得合入**（§15.7-1 红线）。

## 4. 风险与缓解

- **性能**（最高风险）：逐周期派发每帧约 89k 次 stepper 调用。缓解：stepper 返回"距下一事件周期数"的批处理接口（事件驱动稀疏化）、热点路径零分配、基准门禁每子批必跑；回退开关保留 per-instruction 路径。
- **复杂度**：未遂中断/页跨 dummy 周期/dma 就绪位交互是经典深水区。缓解：以 blargg cpu_* 套件逐项驱动，一项一提交。
- **回归面**：写落点修正会改变全部 ROM 的帧哈希——按 §7.2 重生，commit message 列差异机理；KIRA 与 owner 症状 ROM 全量复测。

## 5.1 批次 3c.2 构建计划（修订版，2026-09-15 定稿——取代此前草案）

**依据**：增量 1/2 的实测结论。增量 1（钩子基建，137/177）证明访问落点可移动；增量 2（内部周期信号，132/177）证明**补丁不可行**——钩子推进与 `count` 预算记账双重计算，同一指令的时间被花两次。结论：终态是统一授权模型，本节为其构建计划。

### 目标语义

循环的每次迭代 = **3 个 PPU dot + 恰好 1 个 CPU 周期**。CPU 周期 = 一次总线访问（rd/wr）或一个内部周期。指令 = 微操作（micro-op）序列，跨多次授权延续执行——`execute_step` 的原子体拆解为可中断延续。目标时序性质：任何 PPU 寄存器访问落在硬件精确 dot 上；CPU-PPU 相位锁定（vbl_02 涂开收敛为单行翻转）。

### 微操作模型

- 每个 `(OpKind, AddrMode)` 对映射到固定微操作模板（6502 数据表周期序列）。
- 微操作种类：`OpFetch(pc)`、`OperandLo/Hi(pc)`、`ReadMem`、`DummyRead(addr)`、`ModifyInternal`、`WriteMem(val)`、`StackPush(reg)`、`StackPop(reg)`、`Internal`、`BranchInternal`、`VectorRead`。
- 数据地址在操作数微操作完成后回填（模板留 PatchAddr 槽）。
- `execute_step` 拆为 `instruction_begin`（选模板 + 执行首个微操作）与 `micro_op_step`（延续）。
- **现有 addressing helpers 与指令臂的语义逻辑保留**，访存点改为微操作。

### 关键子系统的迁移

| 子系统 | 现状 | 微操作模型下 |
|---|---|---|
| 中断派发 | 指令边界轮询 + E1 8 周期冻结 shim | 每微操作边界轮询 NMI/IRQ 线；NMI 序列本身 = 微操作程序；**E1 shim 移除**（如 vbl_05 校准需要，用派发 dot 的可配置偏移微调） |
| $2002 抑制 / $2000 NMI 边沿 | (241,0)/(241,1) 矩阵 | 保留矩阵，判定时点自然精确（读/写在真实周期执行） |
| 3b 写落点递延 | 队列 + (base×3−1) 延迟 | **移除**——写天然落在真实周期（微操作时序直接保证） |
| OAM DMA | 每 3 dot 泵（CPU 不停顿，已知偏差） | 513/514 周期微操作序列注入周期流（交替 read/write + 对齐 idle） |
| DMC stall | advance_cycles 负预算 | 注入 Internal 微操作 |
| mapper 每指令 tick thunk | 保留 | 保留在指令边界（行为兼容优先）；逐周期 mapper 时钟另立 gate 评估 |
| blob count 回写 | 每授权同步 | 每微操作后回写等价值（−剩余周期×48），C++ facade/存档哈希兼容 |
| 3c.1 抑制矩阵 (241,0)/(241,1) | 保留 | 判定时点自然精确 |
