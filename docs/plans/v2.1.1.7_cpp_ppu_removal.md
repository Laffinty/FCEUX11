**两条方向性结论（本 plan 地基，替代一审"两边读写同一份存储"）：**

1. **Rust → C++ 无任何寄存器/OAM 回写**。GUI、mapper、savestate 读到的 `PPU[]`/`SPRAM` 是墓碑值；默认构建下 `PPU[0..3]` 恒为 power 时的 0。这是**既存缺陷**，不是本 plan 引入的。
2. **C++ → Rust 的 NT/CHR 是拷贝而非共享**。(a) GUI 直接写 `vnapage` 不会立刻进入渲染；(b) savestate 载入后 `NTARAM` 已恢复，但 Rust 渲染器仍读旧副本，直到下一次 $2007 写或页指针移动才刷新。

### 0.2 Rust PPU FFI 表面盘点

默认 ON build 的运行需求已全部覆盖（生命周期 / bus vtable / 窗口 / CPU 寄存器 / 每帧驱动 / 调试状态 / VBL 抑制互斥），清单与一审一致。**缺口三条**：

1. **无"整块状态导出/应用"FFI**：`fceux11_ppu_get_register_state` 只能逐字节读，没有任何写回 Rust 的入口 → savestate 载入无法恢复 Rust 状态。
2. Rust 侧**已存在**为这件事准备的机制：`snapshot.rs` 的 `serialize_rpu1`/`deserialize_rpu1`（RPU1 v1，380 B payload）与 `LegacyView`（264 B：`regs[4]`+`oam[256]`+`write_toggle`+`vram_buffer`+2 B pad），但文件头明确写着"**故意不上线（option (a)）**——只有让 RPU1 不上线，才能保证 `golden_savestate_test` 字节同一"。本 plan 必须正面处理该设计约束（D1）。
3. `fceux11_ppu_set_video_system` 存在、scheduler 支持 PAL（106392 dots），但 bridge 在 power 时**硬编码 `false`**（`ppu_rust_bridge.cpp:391`），且没有任何路径在制式变化时通知 Rust（见 §0.6 / D4）。

### Step B.1. Savestate 通道（重新设计；含 D1）

#### 问题（代码级）

#### 方案 D1（owner 必答）

| 方案 | 做法 | 代价 | 结果 |
|------|------|------|------|
| **D1-A（推荐）** | chunk-3/chunk-31 的 **chunk 号、label、size、顺序完全不变**，只把取值源换成 bridge-owned staging（值来自 Rust）；载入时把 staging 推回 Rust。**不新增 chunk**。golden 按 v2.1.1.2 流程重生并记录证据 | golden MD5 会变；新增 2 条 FFI + 1 个 staging TU | 载入真正恢复 PPU 状态；旧文件仍可被新版本读（退化为"不恢复 PPU"，与今天相同）；新文件仍可被旧版本解析 |

#### 实现细节（D1-A 路径）

**(1) Rust 侧新增 2 条 FFI**（`crates/fceux11-ppu/src/ffi.rs`）

```
fceux11_ppu_state_block_export(state, out: *mut u8, len: u32) -> i32
fceux11_ppu_state_block_apply (state, buf: *const u8, len: u32) -> i32
```

字节块约定（host little-endian；`RADD`/`TADD` 用 `uint16`，与现有 SFORMAT 的 `2|FCEUSTATE_RLSB` 语义一致——`RLSB` 只在 `FCEU_BIG_ENDIAN` 下翻转，MSVC/x86-64 恒为 no-op，见 `state.cpp:172-188`）：

| 偏移 | 字段 | 来源（Rust） |
|------|------|--------------|
| 0 | `regs[4]` | `registers.{ctrl,mask,status,oam_addr}` |
| 4 | `oam[256]` | `PpuState.oam` |
| 260 | `write_toggle` | `registers.write_toggle` |
| 261 | `vram_buffer` | `registers.vram_buffer` |
| 262 | `fine_x` | `registers.fine_x` |
| 263 | `data_bus` | `registers.data_bus` |
| 264 | `v (u16)` | `registers.v` |
| 266 | `t (u16)` | `registers.t` |
| 268 | `scanline (i16)` | `PpuState.scanline` |
| 270 | `dot (u16)` | `PpuState.dot` |

（`LegacyView` 保持 264 B 不动——它有独立测试与 RPU1 用途；上述块是**新的、bridge 专用**布局。）
