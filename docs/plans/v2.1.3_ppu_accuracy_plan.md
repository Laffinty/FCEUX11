# FCEUX11 v2.1.3 开发计划 — 模拟精度：背景渲染管线、A12/IRQ 时序与逐周期调度

- 记录时间：2026-09-13
- **状态（2026-09-13，v2.1.3 发布）**：批次 1、2 已交付并随 **v2.1.3** 发布（blargg 138→146 PASS、ctest 41/41）；**批次 3、4、5 移交 v2.1.4**（见 §11）
- 触发：owner 实测 v2.1.2 在部分游戏中仍出现**背景贴图突然出错或无法显示**；怀疑模拟精度未达理想状态
- 目标：把背景渲染从"逐扫描线批处理"升级为"逐 dot 取指流水线"，把 MMC3 族 IRQ 从"每扫描线一次的近似时钟"升级为"硬件级 A12 边沿检测"，把 CPU-PPU 交错从"逐指令"升级为"逐周期"；以 blargg 套件当前 39 项失败为主要量化验收
- 范围：`fceux11-ppu`（rendering/sprites/scheduler/frame）、`fceux11-core`（stepper）、`ppu_rust_bridge.cpp`（窗口与 A12 钩子）；C++ mapper 逻辑仅在必要时增加观察点，不改其行为
- 关联：docs/history/v2.1.2_mmc3_irq_clock_archived_2026-09-13.md（批次 2 遗留项的正式立项）

## 2. 根因

四个缺口同根：**渲染核心用"扫描线"当最小时间单位，而硬件的副作用发生在"dot"**。凡是游戏在一条扫描线*内部*制造状态变化（写寄存器、mapper 换 bank、IRQ 触发换行），本引擎只能整行延迟或整行忽略。v2.1.2 修的是"渲染关闭时 IRQ 计数器不该走"这类门控错误；v2.1.3 要修的是"渲染开启时，一条扫描线内部发生了什么"。

## 4. 批次设计（每批独立提交、独立 gate、独立可回滚）

### 批次 1 — MMC3 族硬件级 A12 watcher + 取指级 CHR 解析（背景关键路径，最小改动先行）

**动机**：MMC3 全套 12 项失败的唯一共性缺口；owner 症状中"间歇性 bank 错/卡死"的直接嫌疑。v2.1.2 归档记录明确将此列为遗留批次 2。

**改动点**：
1. **A12 只需要取指地址，不需要取指数据**——地址由 Rust 渲染器自己计算（pattern 基址 | tile<<4 | fine_y）。取指状态机在每次 BG pattern 取指（dots 1-256、321-336）与精灵 pattern 取指（dots 257-320，含空槽 tile $FF 的 dummy 取指）时把地址交给过滤型 A12 watcher；8x16 精灵由 tile 索引 bit0 逐精灵选表，同一行可产生多个 A12 边沿（Wiki：每行最多 4 次），这正是 MMC3 套件 A12_clocking 项考察的行为。
2. **渲染关闭期的上报不可省略**：blargg 测试 3 验证 $2006 第二次写、$2007 读、$2007 写造成的 A12 0→1 跳变都计数（无论渲染是否开启）；Mesen2 的模型是"每次 PPU 总线地址变化都通知 mapper"（渲染期=每次取指地址；关闭期=$2007 递增后与 $2006 写后把 v 推上总线）。本仓按同一语义在上报点补齐关闭期路径。
3. watcher 与 MMC3 计数器的接口保持在"过滤后的上升沿"粒度：只有真实边沿才穿过 FFI 调 `GameHBIRQHook` 路径（每扫描线典型 1-3 次，无逐取指 FFI 开销）。替换 `bridge_notify_a12_rising` 空函数；v2.1.2 的渲染开启门控由 A12 路径自然取代（渲染关闭时无取指、无边沿），保留其单测作为行为记录。
4. MMC3 RevA/RevB 计数语义、MMC6 变体按 `cart/mapper_irq_mechanisms.md` §2.3/§2.4 实现：RevB 判 "counter==0 且使能"，RevA 判"递减到零"（NES 2.0 芯片名 MMC3A 触发）；标准配置（BG $0000+精灵 $1000）每帧恰好 241 次计数、反配置时计数点移到上一行 dot 324 且奇帧首行可能双计——用套件逐项校准。
5. CHR **数据**改用"脏标记 + 8-dot 组刷新"：mapper 侧任何 `g_bus.vpage[]` 变化置共享原子脏标记，渲染循环每 8-dot 组检查一次（每帧约 7200 次原子读，脏时才 memcpy 1 KiB 页）。成本近零，且行内换 bank 在下一个取指组即可见；不再需要逐取指 FFI，也不再有"换 bank 后整行使用旧快照"的问题。

**Gate**：blargg mmc3_1..4 与 mmc3_v2_1..4（clocking/details/A12_clocking/scanline_timing）全部转 PASS；rev_A/rev_B 两项在真机上互斥（一张卡只能过其一，见 `cart/mapper_irq_mechanisms.md` §2.3/§6），按所选默认修订至少通过其一、另一项在 known-fail 基线记录为"修订差异"；blargg readme 明言 irq 测试 3-5 依赖未完全成文的硬件时序，1、2 通过为硬性要求。全量 ctest 41 项不回归（重点 mapper_mmc3_byte_diff、ppu_frame_diff_test）；SMB3/Crystalis 类 ROM 帧序列无冻结（复用 v2.1.2 批次 3 gate）。

> **交付记录（2026-09-13）**：已完成，commit `4ae0189`。MMC3 族 6/18 → 14/18，全量 138 → 146 PASS，ctest 41/41 无回归。gate 偏差（旧套件 4 号两项挂批 3、6 号两支为修订差异）与批次 2/3 接力说明见 **§9**。

**风险**：A12 过滤参数取值不当导致计数偏移（对照套件逐项校准）；回滚 revert 单 commit。

### 批次 2 — 逐 dot 背景取指流水线（渲染核心重写）

**动机**：A1/A2/A6 的根治；mid-scanline 滚动写、行内 $2007 写、行内换 bank 全部可表达。这是本计划的架构主升级。

**改动点**：
1. `rendering.rs` 重写为 dot 状态机：NT/AT/PT 取指落在权威 dot（1-256 每 8-dot 组、321-336 预载、337-340 garbage NT）；16-bit 移位寄存器 8-dot 重载与 fine-x 选择；v 的 coarse-X 增量在 dots 8..256、Y 增量在 256、水平复制在 257、预渲染行 280-304 垂直复制（寄存器语义已有 `registers.rs` 与 v2.1.2 dot 257 修复的成果可复用）。
2. 渲染开启时的 CPU 写（$2000/$2005/$2006/$2007）在"当前 dot"生效，按 `ppu/ppu_mid_frame_writes.md` 的硬件语义实现；参照实现的已验证取值：$2000/$2005 立即 + dot 257 open-bus 拼接竞态；$2006 第二写延迟约 3 dot 生效（Mesen2 `_updateVramAddrDelay=3`，puNES 倒计时同域）；$2007 写立即但 v 递增推迟 1 dot、6 dot 内连续读节流（三家参照一致落在 5-6 PPU 周期量级）；含 $2007 渲染期 coarse-X 污染 quirk 与渲染关闭期 backdrop=v 调色板花招（SMB3 依赖）。
3. `atlatch` quirk 处置（**已定案，2026-09-13**）：本仓存档的 Wiki《PPU rendering》属性锁存模型（NT/AT/PT 四次取指针对同一 tile、8th dot 一并装载、每个 8 像素串共享同一属性）+ Mesen2/Nintendulator/ares/puNES 四家参照实现均证明 FCEUX 的 atlatch（tile 后 4 像素用下一 tile 属性）**不符合硬件**（定案记录见 `reference/dot_ppu_designs.md` §2.6）。逐 dot 流水线按硬件模型实现均匀属性，随本批移除 quirk——**golden_frames 基线重生必须 owner 批准**（治理约束见 §7），预期像素差异仅出现在属性象限边界。
4. 快照窗口退化为渲染关闭路径（blank 时的 palette 读）使用；渲染开启路径不再依赖扫描线快照。

**Gate**：新增 Rust 单测（分屏滚动：dot N 写 $2006 后仅影响后续 tile；行内换 bank：仅影响后续取指）；blargg scroll/scanline 类保持 PASS；frame-diff 门禁按治理流程重生；KIRA 类 ROM 全帧 CRC 连续变化。

**风险**：本批输出像素与 FCEUX 遗传算法存在受控差异（属性 quirk、边界 tile），必须走基线重生流程而不是硬凑；性能回归（基准门禁 bench_tolerance_test 把关，8-dot 组内预取地址可缓存）。

> **交付记录（2026-09-13）**：已完成代码与单测落地。`rendering.rs` 逐 dot 取指流水线 + 属性移位寄存器（移除 atlatch）、精灵层 prepare/pick、A12 改由真实取指地址上报；blargg 146 PASS 与批次 1 逐项持平（零新增失败），cargo test 105/105，`ppu_frame_diff_test` 与 byte-diff 门禁保持 PASS。3 项基线/性能偏差（nestest frame 2/3、nestest 存档哈希、bench_cpu_frame +6.6%）见 **§10**，均需 owner 裁定（§7.2 基线重生 / §6 基准校准）。

### 批次 3 — 逐 CPU 周期调度（per-cycle stepper）

**动机**：A5 根治；VBL/NMI 簇 7 项 + CPU 中断簇约 15 项的唯一可行路径。scheduler 模块注释已预告此演进（"a future phase can swap the stepper for a true per-cycle state machine"）。

**改动点**：
1. `fceux11-core` stepper 提供周期粒度执行接口（每 CPU 周期返回，交出调度点）；指令完成语义与现有 FFI 兼容。
2. scheduler 交错循环改为逐周期：每 1 CPU 周期推进 3 PPU dot（PAL/Dendy 按各自比值）；NMI/VBL/IRQ 在精确 dot 采样。
3. OAM DMA / DMC DMA 以 CPU 周期为节拍注入（现有 OAM DMA 泵语义保持，挂接点细化）；假读/假写（dummy read/write）按 `reference/accuracy_test_suites.md` 中 cpu_dummy_writes_* 的要求触发真实寄存器副作用。

**Gate**：vbl_02/03/04/06/07/08/10、ppu_vbl_nmi、cpu_int_2..5、cpu_interrupts、instr_timing*、cpu_exec_space_ppuio 转 PASS；既有全量 ctest 与 byte-diff 不回归；性能基准不超过阈值（本批是性能风险最大的一批，见 §6）。

**风险**：逐周期执行的 CPU 实现复杂度高（未遂中断、页跨 dummy 周期）；回滚开关保留逐指令路径（scheduler 参数化，不出 configure 选项，仅内部策略）。

### 批次 4 — 精灵评估 per-dot 与已知限制补齐

**改动点**：secondary OAM 评估落在 dots 65-256（n/m 计数器、OAM rot、$2003 渲染期行为）；精灵取指窗口 257-320（garbage NT 取指同样上报 A12）；OAMADDR 非 0 的渲染期 quirk（评估起点=OAMADDR、渲染开始时 OAMADDR≥8 的 8 字节拷贝 bug、$2004 写只递增高 6 位——规格见 `ppu/ppu_sprite_evaluation.md`）；左 8 像素裁剪（$2001 bit1/bit2，v2.1.2 已知限制）；sprite 渲染与 sprite-0 hit 的 dot 精度复核（sprite_hit 套件已全绿，回归保护，规则见 `ppu/ppu_sprite_hit.md`）。行为要点：评估条件是 $2001 任一渲染位开启；pre-render 行不做评估（扫描线 0 永远无精灵）；评估条件与溢出判定不得依赖"帧末统一计算"（sprite_overflow 5-emulator 反作弊项）。附带：XDBuf emphasis 逐像素位平面（ChangeLog 已知限制）评估是否顺带。

**Gate**：oam_stress、cpu_dummy_writes_oam 转 PASS（**注意**：oam_stress 在真机上也只在四种 CPU-PPU 上电对齐之一通过，先核对本仓上电对齐取值与该对齐一致，再判定测试失败归因）；sprite_hit/sprite_overflow 16 项保持全绿。

### 批次 5 — $2007 读缓冲与 open bus

**改动点**：读缓冲时序（缓冲更新时机、渲染期读行为）；open bus 衰减模型（ppu_open_bus 目标）；渲染关闭时调色板读路径沿用快照（批次 2 退化路径）。

**Gate**：ppu_read_buffer、ppu_open_bus 转 PASS。

### 批次依赖与并行性

- 批次 1 独立于 2/3，可先行（改动最小、症状对应最直接）。
- 批次 2 依赖批次 1 的"取指级地址上报"接口（同一 trait 扩展，先合 1 再做 2 可避免返工）。
- 批次 3 与 1/2 完全正交（核心侧），可与批次 1 并行开发、独立合入。
- 批次 4 依赖批次 2（同一渲染状态机）；批次 5 独立。
