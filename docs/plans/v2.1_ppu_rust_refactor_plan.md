## 1. 结论摘要

v2.1 不再延续“在现有 `ppu_rendering.cpp` 上继续打 NMI 时序补丁”的路线，而是把 PPU 时序所有权迁入 Rust，并让 Rust CPU 与 Rust PPU 以 PPU dot 为主时钟协同运行。

核心判断：

1. 现有失败不是 mapper 特有问题，而是 PPU VBlank/NMI/OAM/DMA 等 sub-instruction 时序模型不完整。
2. 继续修补 C++ 新 PPU 可以短期提升几个百分点，但会让 `runppu()`、`e1_nmi_delay()`、suppression window、even/odd skip 等逻辑更加脆弱，最终仍会碰到架构天花板。
3. Rust CPU 已经是唯一 CPU 实现；把 PPU 也放进 Rust，并建立同一个 scheduler，可以消除当前热点路径中约 67k 次/帧的 `runppu(1) -> X6502_Run(1) -> fceux11_cpu_run` FFI 跨越，同时从根上解决 phase drift。
4. C++ 仍保留总线、mapper、APU、视频输出、Lua、debugger、savestate 兼容层，不要求在 v2.1 同时重写 mappers/APU。

建议采用“双引擎并行迁移”：

- 默认路径先保留 C++ PPU；
- 新增 `FCEUX11_RUST_PPU=ON` 启用 Rust PPU；
- Rust PPU 通过全部硬门槛后，v2.1 末段切换为默认 ON；
- C++ PPU 至少保留一个版本的 fallback 开关，确保可回滚。

## 2. 背景与依据

### 2.1 现有数据

来自已归档的两份报告：

- v2.0_hotfix1 批量兼容测试：`2872/3451 = 83.2% PASS`（或最终口径 83.9%），剩余主要失败是 `cpu_stuck`。
- 剩余 stuck ROM 中约 94.4% 的 PC 落在 `0x8000-0xFFFF`，跨 mapper 0/1/2/3/4/7/19 等，证明是统一时序问题。
- blargg `ppu_vbl_nmi` 9 个子测试中有 6 个失败，全部指向 sub-instruction 级 PPU 时序。

### 2.2 当前实现的问题

当前相关代码：

- `src/ppu.cpp`：PPU 寄存器访问、open bus、`$2002`/`$2004`/`$2007`/`$4014` 处理。
- `src/ppu_rendering.cpp`：new-PPU 渲染主循环、`runppu()`、VBlank/NMI 逻辑、BG/OAM 合成。
- `src/ppu_class.h`：`fceu11::Ppu` 与 legacy alias。
- `src/cpu.cpp` + `src/rust/crates/fceux11-core/src/cpu/*`：Rust 6502 CPU facade 与 FFI。

关键瓶颈：

1. `runppu(1)` 在 BG fetch 热路径中反复调用 `X6502_Run(1)`，而 `X6502_Run` 每次进入 Rust FFI，按当前新 PPU 结构约为每帧 67k 次，带来不必要的边界开销。
2. NMI 触发点仍由 `e1_nmi_delay()`、`runppu(nd)`、`X6502_Run` 组合近似，不是真正的逐 dot 采样。
3. `$2002` suppression window、`$2000` NMI enable/disable edge、even/odd skip 分散在多个函数中，缺少单一状态机。
4. PPU A12 边沿、HBlank hook、mapper IRQ 依赖渲染循环中手写的 `runppu(kFetchTime)` 位置，精度难以保证。
5. PPU 内部状态一部分在 `PPUREGS`，一部分在 `ppu_rendering.cpp` 的 static 局部/全局，架构上难以测试和保存。

## 3. 目标与非目标

### 3.1 目标

- 建立 dot 级 PPU 状态机，精确处理 VBlank flag、NMI 抑制、NMI on/off 边沿、even/odd frame skip。
- 建立 Rust CPU/PPU 统一调度器，使 CPU 内存访问与 PPU dot 对齐。
- 提高 mapper 时序基础：PPU A12 边沿、HBlank/scanline hook、MMC3/VRC 等 IRQ counter 的观测点统一。
- 用 trait 和显式 side-effect 接口替代 C++ 中的大量全局耦合。
- 保持 savestate 旧文件可加载，golden frame/savestate/mapper 测试不回归。
- 降低 PPU/CPU 热点 FFI 往返，批量兼容测试耗时应不高于当前 new PPU，目标接近或优于 legacy PPU。
- 全程可回滚，CI 硬门槛逐阶段加严。

### 3.2 非目标

- 不逐行翻译 `ppu.cpp`/`ppu_rendering.cpp` 的 C++ 实现。
- v2.1 不重写 mapper/APU 为 Rust；只把 PPU 对 mapper/APU 的时序接口显式化。
- 不追求模拟级 PPU 输出（NTSC 滤波、RGB PPU 模拟），像素输出仍复用现有 NES 调色板路径。
- 不改变 MSVC-only、Windows 11、Qt6、`/W4 /WX` 等既有工程约束。
- 不在 v2.1 同时删除全部 C++ PPU 代码；删除放在最终验收之后。

## 4. 技术路线选择

| 路线 | 说明 | 评价 |
|------|------|------|
| A. 逐行翻译 C++ PPU | 把 `ppu.cpp`/`ppu_rendering.cpp` 机械翻译为 Rust | 保留旧架构缺陷，无法根治 phase drift，工作量大但收益低 |
| B. 继续 C++ 热修 | 按旧计划 A-E 修补 NMI/VBL/even-odd | 短期风险低，但仍是补丁，无法形成可验证的统一时序模型 |
| C. Rust 原生 cycle-accurate PPU + 统一调度器 | Rust 拥有 PPU 状态与时间，C++ 仅提供 bus/mapper/APU/video 适配 | 采用 |

选择 C 的理由：

- Rust CPU 已经证明 FFI/静态库、savestate 兼容、tick bridge、KagamiQA 接入是可行的。
- 当前 PPU 失败集中在“时间归谁管”而不是“画不出来”；把时间所有权收归统一 scheduler 是根本解法。
- 可以通过 `FCEUX11_RUST_PPU` 逐步接入，避免一次性切换导致无法定位回归。

## 6. 关键设计

### 6.1 主时钟与统一调度器

`NesScheduler` 以 PPU dot 为最小主时钟单位：

```text
for each PPU dot:
    1. ppu.tick_dot(ppu_bus)
    2. if cpu_due:
         cpu.tick(cpu_bus, ppu_bus, hooks)
    3. apply DMA/DPCM stall
    4. update NMI/IRQ edge
```

CPU 与 PPU 比例由 video system 决定。NTSC 为 3 PPU dot / 1 CPU cycle；PAL/Dendy 使用调度器中的有理数分频，而不是在循环里手工散落 `X6502_Run`。

目标是把当前 `runppu(x)` 中“PPU 前进 x dot，同时给 CPU x/3 cycle budget”的隐式关系，改为调度器显式统一推进。

### 6.2 CPU sub-instruction stepping

PPU 精度要求 CPU 寄存器读写发生在正确的总线周期，不能只按整条指令推进。为此，v2.1 需要对 Rust CPU 增加“可恢复微步”能力：

```text
CpuStepper:
  - pending_read
  - pending_write
  - remaining_cycles
  - operand_state
  - instruction_phase
```

`Cpu::tick()` 每次执行一个 CPU cycle/总线访问步。PPU 在同一 tick 中可见：

- 操作码读取
- 操作数读取
- 中间写/读
- 最后写
- 页面穿越 dummy read

旧的 `run`/`run_with_tick` 保留为兼容包装，由新 stepper 驱动，避免破坏现有 CPU 单元测试、tick bridge 和 KagamiQA CPU 测试。

这一步是 v2.1 最大风险点，因此设置独立里程碑。若完整微步化风险过大，可先退化为“整条指令执行 + 每个总线访问点回调 PPU”，但该退化方案不能作为最终架构。

### 6.3 Bus 与 side-effect 接口

Rust `PpuBus` 不只是 `read`/`write`，而是显式包含硬件事件：

```rust
pub trait PpuBus {
    fn read(&mut self, addr: u16) -> u8;
    fn write(&mut self, addr: u16, value: u8);
    fn peek_chr(&mut self, addr: u16) -> u8;
    fn notify_a12_rising(&mut self);
    fn notify_hblank(&mut self);
    fn notify_hblank2(&mut self);
    fn notify_scanline(&mut self);
    fn notify_vblank(&mut self, asserted: bool);
}
```

C++ 通过一组 `extern "C"` thunk 安装到 Rust：

```c
fceux11_ppu_set_bus(
    ppu_read_fn,
    ppu_write_fn,
    ppu_peek_chr_fn,
    ppu_a12_fn,
    ppu_hblank_fn,
    ppu_hblank2_fn,
    ppu_scanline_fn,
    ppu_vblank_fn
);
```

对应关系：

- `ppu_hblank_fn` / `ppu_hblank2_fn` 映射现有 `GameHBIRQHook` / `GameHBIRQHook2`。
- `ppu_a12_fn` 为 MMC3 等 mapper 提供统一 A12 上升沿事件。
- `ppu_scanline_fn` 在调度器确认的 scanline 边界触发，避免渲染循环手写位置漂移。

### 6.4 CPU 总线与 PPU 寄存器访问

Rust scheduler 中的 CPU 总线继续调用 C++ `g_bus` 的 read/write callback。PPU 寄存器地址 `$2000-$2007`、`$4014` 需要由 C++ 桥接到 Rust PPU，而不是继续写 C++ 旧 PPU 状态。

建议：

- `FCEUX11_RUST_PPU=ON` 时，`src/ppu_rust_bridge.cpp` 将 `ARead[]/BWrite[]` 中 `$2000-$2007` 的 handler 换成 thin bridge thunk。
- thunk 调用 `fceux11_ppu_cpu_read(addr)` / `fceux11_ppu_cpu_write(addr, value)`。
- `$4014` 的 OAM DMA 由 scheduler 状态机接管，而不是 C++ 中 256 次 `X6502_DMW` 循环。

这样 mapper/bus 其余逻辑不用大改，debugger/Lua 仍通过 bridge 的同步视图观察 PPU。

### 6.5 CHR 缓存与性能

PPU 每次读取 CHR 都跨 FFI 会拖慢性能。设计两级访问：

1. C++ 在 bank 切换时调用 `fceux11_ppu_set_chr_window(slot, ptr, len, flags)`，把 CHR ROM/RAM 窗口直接暴露给 Rust。
2. Rust 使用 `unsafe` 直接读取窗口；当窗口可能是 RAM、映射需要写时，才走 `ppu_read/write` callback。
3. `setchr*`、`setntamem`、`setmirror*`、`setprg*` 等 C++ 入口统一触发窗口失效。

最终目标是热路径中 PPU tile fetch 不再逐字节跨 C ABI。

### 6.6 VBlank/NMI 状态机

目标状态机明确编码：

```text
sl 241, dot 1: assert VBL flag
sl 241, dot 1: sample NMI enable and suppression
$2002 read at sl 241 dot 0: suppress this frame's VBL flag + NMI
$2002 read at sl 241 dot 1: read flag as set, clear flag, suppress NMI
$2000 write NMI-on/off: sample at scheduler edge, not at C++ write side effect
sl 261/311 or equivalent: clear VBL flag
even/odd pre-render skip: dot 340 decision
```

所有条件集中到 `frame.rs`，不再散布在 `ppu.cpp` 与 `ppu_rendering.cpp`。

### 6.7 savestate 兼容

采用“legacy mirror + extension chunk”策略：

1. Rust `PpuState` 维护一个与当前 `PPUREGS`/`SPRITE_READ`/`fceu11::Ppu` 字段对应的 `LegacyPpuMirror`。
2. 保存时：
   - 旧 chunk 仍写 legacy mirror，保证旧字段可读；
   - 新增 `RPU1` 扩展 chunk，写入 Rust 内部 dot 级状态。
3. 加载旧 save：
   - 读取 legacy chunk，调用 `fceux11_ppu_restore_legacy()`；
   - 将内部状态重建到安全同步点，例如 scanline 边界或 VBlank 起点，并接受一次帧内归一化。
4. 加载新 save：
   - 同时读取 legacy mirror 和 `RPU1`，精确恢复。

要求：

- 旧 `.fc0` 能加载。
- `golden_savestate_test`、`savestate_regression_rust_smoke` 不回归。
- 新 save 可标记 v2.1；旧版本拒绝新 save 属于预期。

## 10. 风险与回滚

| 风险 | 影响 | 缓解 |
|------|------|------|
| CPU sub-instruction stepping 复杂度高 | 调度器/CPU 回归 | 独立 Phase 3；旧 `run`/`run_with_tick` 包装保留；先做 callback 退化方案 |
| mapper hook 时序变化 | MMC3/VRC/N106 等回归 | A12/HBlank 显式事件 + mapper byte diff + batch 扫描 |
| CHR 窗口缓存失效遗漏 | 花屏 | bank 切换统一走 `invalidate`；用 golden frame + batch 覆盖 |
| savestate 内部状态不完整 | 旧 save 加载偏差 | legacy mirror + extension chunk；保留 C++ fallback |
| APU/DMC DMA 时序 | 音频漂移 | 调度器统一 CPU cycle callback；DMC 单独状态机 |
| 性能回归 | 模拟器变慢 | 减少 FFI、CHR 缓存、SoA 热状态、benchmark gate |

回滚策略：

- 任何阶段未过 gate，不进入下一阶段。
- `FCEUX11_RUST_PPU=OFF` 始终保持 C++ PPU 可用。
- 如 Rust PPU 默认 ON 后出现严重回归，用运行时环境变量 `FCEUX11_PPU_ENGINE=Cpp` 临时回退。
