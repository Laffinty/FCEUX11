# FCEUX11 v1.x 现代化改造演进计划

> **基线版本**：v1.0.0（LTS 收官，基于 v0.3.16）
> **目标**：对核心模拟引擎进行系统性现代化改造，消除全局状态耦合、建立对象模型、完成 Rust 迁移闭环
> **工具链约束**：MSVC 2022+ / C++20 / Rust 2024 / Qt 6.8 LTS / CMake 4.0+
> **最后更新**：2026-07-11（v1.14 Anvil §14 代码交付）

---

## 0. 总纲

### 0.1 核心问题诊断

v1.0 遗留的最大架构债务是**核心模拟引擎的全局状态耦合**：

| 问题 | 量级 | 影响范围 |
|------|------|----------|
| `extern` 全局变量 | 100+ 声明（fceu.h 27+, cart.h 20+, debug.h 25+, x6502.h/ppu.h/sound.h 等） | 所有模块 |
| 零类抽象 | CPU/PPU/APU 均为裸全局结构体 + 自由函数 | 核心 + 驱动 |
| 紧耦合 | 核心含 `#ifdef __QT_DRIVER__`；fceuWrapper 定义核心所需的全局变量 | 双向依赖 |
| 裸 malloc/free | 30+ 文件 | 内存安全 |
| 单文件巨大 | ppu.cpp 2191行, TasEditorWindow.cpp 6747行 | 可维护性 |

### 0.2 改造原则

1. **渐进式**：每个子版本可独立编译、运行、回归测试，永不出现不可用中间态
2. **向后兼容**：savestate 二进制格式在 v1.x 全系列保持可互操作；FCEUI_* 别名在 v1.x 保留，v2.0 移除
3. **性能不退步**：每个子版本必须通过性能基准测试（±2% 容差），核心热路径不得引入虚函数开销
4. **Rust 优先**：新增逻辑优先用 Rust 实现；已有 C++ 逻辑按"解析/序列化/工具→状态管理→热路径"顺序迁移
5. **测试先行**：每个子版本必须先建立回归测试再动手改造

## 4. v1.4 Gateway — 内存分发总线重构

**目标**：将 ARead/BWrite/Page/VPage 等内存分发表封装为 `fceu11::Bus` 类，统一 bank-switching API。

### 4.1 Bus 类定义

- [ ] 新建 `src/bus.h` / `src/bus.cpp`
- [ ] `fceu11::Bus` 类：
  ```cpp
  namespace fceu11 {
  class Bus {
  public:
      // 64K CPU 地址空间读/写分发
      uint8_t read(uint16_t addr) noexcept;       // → ARead[addr](addr)
      void    write(uint16_t addr, uint8_t val) noexcept; // → BWrite[addr](addr,val)

      // 直接内存访问（调试/DMR/DMW）
      uint8_t direct_read(uint32_t addr) const noexcept;  // → Page[addr>>11][addr]
      void    direct_write(uint32_t addr, uint8_t val);

      // 分发表注册（替换 SetReadHandler/SetWriteHandler）
      void set_read_handler(uint32_t start, uint32_t end, read_handler fn) noexcept;
      void set_write_handler(uint32_t start, uint32_t end, write_handler fn) noexcept;

      // PPU 地址空间页表
      uint8_t* vpage(uint32_t idx) const noexcept;       // → VPage[idx]
      void set_vpage(uint32_t idx, uint8_t* ptr) noexcept;

      // CPU 地址空间页表
      uint8_t* page(uint32_t idx) const noexcept;        // → Page[idx]
      void set_page(uint32_t idx, uint8_t* ptr) noexcept;

      // Bank-switching API（从 cart.h 迁入）
      void setprg8(uint32_t addr, uint32_t bank) noexcept;
      void setprg16(uint32_t addr, uint32_t bank) noexcept;
      void setprg32(uint32_t addr, uint32_t bank) noexcept;
      void setchr1(uint32_t addr, uint32_t bank) noexcept;
      void setchr4(uint32_t addr, uint32_t bank) noexcept;
      void setchr8(uint32_t addr, uint32_t bank) noexcept;
      void setmirror(uint32_t m) noexcept;
      void setmirrorw(uint32_t a, uint32_t b, uint32_t c, uint32_t d) noexcept;
      void setntamem(uint8_t* p, bool hr, uint32_t addr) noexcept;

      // ROM 指针表
      uint8_t* prg_ptr(uint32_t idx) const noexcept;     // → PRGptr[idx]
      uint8_t* chr_ptr(uint32_t idx) const noexcept;     // → CHRptr[idx]
      void setup_prg_mapping(uint32_t count, uint8_t** ptrs, uint32_t* sizes, bool ram) noexcept;
      void setup_chr_mapping(uint32_t count, uint8_t** ptrs, uint32_t* sizes, bool ram) noexcept;

  private:
      // FCEUX11_CACHE_ALIGN 分发表
      alignas(64) read_handler  aread_[0x10000];
      alignas(64) write_handler bwrite_[0x10000];
      uint8_t* page_[32];
      uint8_t* vpage_[8];
      // PRG/CHR bank tables...
  };
  }
  ```

#### 10.6.1 Rust runtime 状态机架构模式

NSF 和 FDS 的 runtime handler 迁移采用统一模式：

1. **Rust 侧**：定义 `#[repr(C)]` 的 runtime state 结构体（`NsfRuntimeState` / `FdsRuntimeState`），持有原 C++ 全局变量（FSM 状态、IRQ 计数、寄存器数组等）。通过 `Box::into_raw` / `Box::from_raw` 管理 `create` / `destroy` / `reset` FFI。
2. **C++ 侧**：持有一个 `static FdsRuntimeState *g_fds_state` 指针。原 C++ 全局变量改为 `#define` 宏别名指向 `g_fds_state->field`，使 `AddExState` 注册的 savestate 指针直接指向 Rust 结构体字段——savestate 二进制格式无需改变。
3. **热路径**：`NSF_read` / `FDSWrite` 等改为薄 forwarder，构造一个 `FceuFdsDiskIoState` 值结构体传入 Rust FFI，Rust 返回结果结构体后回填宏字段。

#### 10.6.4 FDSClose 空指针解引用教训

**根因**：C++ 宏 `#define DiskWritten (g_fds_state->disk_written)` 在 `fceux11_rust_fds_runtime_destroy(g_fds_state)` 将 `g_fds_state` 置 `nullptr` 后被求值，触发 null deref segfault。

**修复**：在销毁 Rust 状态前，用局部变量捕获所有需要后续使用的宏字段值。

**通用规则**：当 C++ 宏别名指向 Rust 拥有的内存时，销毁 Rust 状态后不得再使用任何宏——要么在销毁前捕获，要么确保销毁是函数的最后操作。
