================================================================================
NES 模拟器内存布局与缓存对齐优化（FCEUX11 通用）
================================================================================

适用：FCEUX11 NES 内核模拟热路径（cart 读取、CPU dispatch、PPU 查表）。
所有 mapper 实现都应遵守本文档列出的对齐与预取规则。

================================================================================
1. 背景：为什么走"保守方案"
================================================================================

NES 卡带读取存在 **open-bus** 语义：CartBROB 在 Page[A>>11] 为 null 时返回
总线最后值 X.DB（外部总线的浮空记忆）。这意味着任何"派生的查找表"必须
在每次 bank switch、PRG-RAM 写、open-bus 变化时同步，否则会破坏字节级
savestate 一致性。

直接实现 32 KiB PRG 字节预取表 → 引入额外的同步路径，savestate 兼容性
会塌。

替代方案：
  1. 64 字节对齐所有热路径数组
  2. 在热读函数（CartBR / CartBROB / PPURead_Default）插入软件预取
  3. 用宏标注 mapper 寄存器组，方便后续性能调优工具识别

这个方案在不改 savestate 字节布局、不引入派生表维护路径的前提下完成了
内存布局优化。

2. 对齐的数组清单
================================================================================

src/cart.cpp / src/cart.h：
  Page[32]                          # PRG 页面基址
  VPage[8], VPageG[8]               # PPU VROM 页面基址
  MMC5SPRVPage[8], MMC5BGVPage[8]  # MMC5 专用
  PRGptr[32], CHRptr[32]            # 实际指针

  PRGmask2/4/8/16/32[32]            # 各种 PRG mask 表
  CHRmask1/2/4/8[32]                # 各种 CHR mask 表
  PRGram[32], CHRram[32], PRGIsRAM[32]

src/fceu.cpp / src/fceu.h：
  ARead[0x10000]                    # CPU 读总线表
  BWrite[0x10000]                   # CPU 写总线表

src/x6502.cpp / src/ops_table.inc：
  CycTable[256]                      # 每条指令的 cycle 数
  opsize[256], optype[256], opwrite[256]  # 指令元数据
  x6502_dispatch                    # 256 个函数指针的 std::array

3. Mapper 寄存器组标注
================================================================================

src/utils/cache.h 定义 FCEUX11_MAPPER_HOT 宏，等价于 alignas(64)：

    #define FCEUX11_MAPPER_HOT alignas(std::hardware_destructive_interference_size)

已标注文件：
  src/boards/mmc1.cpp       DRegs[4]
  src/boards/mmc3.cpp       DRegBuf[8], EXPREGS[8]
  src/boards/mmc5.cpp       PRGBanks, CHRBanksA, CHRBanksB, WRAMMaskEnable,
                            mul, MMC5ROMWrProtect, MMC5MemIn
  src/boards/vrc2and4.cpp   prgreg[2], chrreg[8], chrhi[8]
  src/boards/vrc6.cpp       prg[2], chr[8]
  src/boards/vrc7.cpp       preg[3], creg[8]
  src/boards/datalatch.cpp  latche, latcheinit, addrreg0/1
  src/boards/addrlatch.cpp latche, latcheinit, addrreg0/1

新增 mapper 时：
  - 把 mapper 寄存器组 struct 用 FCEUX11_MAPPER_HOT 标注
  - 验证 savestate 字节布局不变（FCEUX11_ALIGN 的 struct 字段顺序不能改）

================================================================================
4. 软件预取
================================================================================

CartBR / CartBROB：
  在当前 2 KiB PRG 页面内预取下一 cache line（&p[A + 64]）。
  必须做边界检查，避免跨页。

    static inline uint8 CartBR(uint32 A) {
        int np = A >> 11;
        uint8* p = Page[np];
        if (p) {
            _mm_prefetch((const char*)&p[A + 64], _MM_HINT_T0);
            return p[A];
        }
        return CartBROB(A);
    }

FFCEUX_PPURead_Default：
  在当前 1 KiB CHR 页面内预取下一 cache line
  （&VPage[tmp >> 10][tmp + 64]）。

为什么是 +64：
  - 现代 x86 L1d cache line = 64 字节
  - PRG 读通常顺序访问，A 和 A+64 大概率在同 cache line 的不同子行
  - 提前把下一行拽进 L1d，访问 A+64 时是 L1 hit

================================================================================
5. Savestate 兼容性约束
================================================================================

对齐**只**改变对象的地址对齐，**不**改变类型大小（sizeof 不变）。
SFORMAT 按字节大小序列化：
  - 已保存的 state chunk 大小不变（已发布的 .fc0 / sav 文件可读）
  - 720 帧 rom_regression_test CRC 与 golden_hashes.json 保持一致
  - 没有新增需要序列化的派生表，loadstate 后无需重建额外状态

绝对禁止：
  - 在 FCEUX11_MAPPER_HOT 标注的 struct 中插入新字段（破坏 savestate）
  - 把已有 std::array 改成 std::vector（破坏 savestate 字节布局）
  - 用 __attribute__((packed)) 覆盖对齐（破坏 L1d 性能）

6. 验证流程
================================================================================

新增 mapper / 改 cart.cpp 后必须跑：
  ctest --test-dir build --build-config Release
  tests/fceux11_rom_regression_test.exe       # 720 帧 0 mismatch
  tests/fceux11_savestate_regression_test.exe # 12 ROM 0 mismatch
  tests/fceux11_bench_ppu_render.exe          # 性能基线
  tests/fceux11_bench_x6502_exec.exe
  tests/fceux11_bench_apu_mix.exe
  cd src/rust && cargo test --workspace --release

vrc7 例外：其 OPLL 音源状态通过 FCEUSTATE_INDIRECT 保存，chunk 中包含堆指
针 sintbl，每次进程启动地址不同，导致 savestate 字节级非确定性。vrc7
仍由 rom_regression_test 帧 CRC 覆盖行为正确性，不进 savestate 哈希回归。
