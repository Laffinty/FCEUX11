## 1. Findings by severity

### 1.1 HIGH — Fixed in this errata commit

#### Q1 — `CMakeLists.txt:93-94` LSan 注释与现实矛盾

**Before**: comment claimed "LSan is bundled with MSVC ASan — no separate flag required; ASan exit reports leaks automatically." The `FCEUX11_ASAN` option description said "Enable AddressSanitizer (and LSan)".

**Reality** (per checkpoint §4.4 and `scripts/_ctest_asan.ps1`): MSVC Windows ASan does **not** implement LeakSanitizer. `ASAN_OPTIONS=detect_leaks=1` is rejected by cl's ASan runtime: `detect_leaks is not supported on this platform`. `_ctest_asan.ps1` deliberately omits `detect_leaks`.

**Fix**: rewrite the comment to state the MSVC-Windows-LSan-disabled fact, point at the script + checkpoint §4.4 as evidence, and remove "(and LSan)" from the option description.

#### Q5 — `scripts/_ctest_ubsan.ps1:33` 错误的 env var

**Before**: `$env:_NO_DEBUG_HEAP = "1"` was set with a comment "Suppress interactive RTC MessageBoxes".

**Bug**: `_NO_DEBUG_HEAP=1` **disables** the MSVC debug heap, which also **disables** the heap canary portion of `/RTC1` checks. The comment's claim that it suppresses MessageBoxes is the opposite of what the var does.

**Fix (revised after reviewer pushback)**: just **remove the line** and rely on ctest's non-zero exit-code detection. The first-draft fix proposed `MSVC_RUNTIME_CHECKS_ABORT=1` as a replacement, but that env var does not exist (verified against [Microsoft Learn /RTC](https://learn.microsoft.com/en-us/cpp/build/reference/rtc-run-time-error-checks?view=msvc-170) — the only `MSVC_RUNTIME_CHECKS` symbol in the docs is the `__MSVC_RUNTIME_CHECKS` preprocessor macro, not an env var). The honest MSVC-native fix is the "let it crash, ctest catches it" path. If a future developer needs to silence MessageBoxes on an interactive workstation, the correct mechanism is `_CrtSetReportMode` or `SetErrorMode(SEM_NOGPFAULTERRORBOX)` in the test exe — never `_NO_DEBUG_HEAP`.

#### Q12 — `CHANGELOG.md:31-32` vs `:91-94` 内部矛盾

**Before**:
- Line 31-32 said "PDB output verified: `build-asan/src/fceux11.pdb` 32 MB, per-test `build-asan/tests/*.pdb` 31 MB each."
- Line 91-94 said "the next ASan rebuild produces `build-asan/src/fceux11.pdb` and per-test PDBs".

**Reality**: the PDB *wiring* landed in the v0.3.6.5 REDO commit, but the actual rebuild that consumes it to symbolise F-1 was deferred to the v0.3.6.5-followup. The "verified" claim was forward-looking, contradicting the later "next rebuild produces" language.

**Fix**: rewrite the line 31-32 sentence to clarify the wiring-vs-verification split, and point at FOLLOWUP §4 as the source for the verification step.

#### Q14 — `.clang-format` / `.clang-tidy` 误删 — **RETRACTED, keep deleted**

**Observed**: v0.3.6.5 REDO commit (`49e14ea`) silently deleted `.clang-format` (33 lines) and `.clang-tidy` (32 lines) with no commit-message rationale, no CHANGELOG entry, no plan update, but **left 5 plan references and 1 shell-script reference behind**:

- `docs/v0.3.x_Construction_Plan_v3.md` lines 204, 309, 320, 354, 356 reference the files as part of v0.3.0 / v0.3.2 baseline

**First-draft fix (reverted 2026-06-11)**: restore both files. I implemented this in the same errata commit as the F-1 closure.

**Final resolution (per user direction 2026-06-11)**: the deletion is **intentional and final**. The project does not use clang-format or clang-tidy; restoring them is prohibited. The downstream broken references in `tools/lint/format-check.sh` and the plan are a **separate cleanup** that the user has explicitly chosen to defer — do not conflate it with the file-restoration question. A persistent memory note has been saved to prevent future sessions from re-proposing restoration.

## 3. Pattern audit — `sizeof((char*))` / `sizeof((uint8*))` across `src/`

The F-1 root cause is a `sizeof` applied to a *cast pointer expression*, which yields the pointer size (4/8) rather than the underlying buffer size. Pattern audit before this errata:

| File:Line | Severity | Notes |
|---|---|---|
| `src/state.cpp:766` | **F-1 root cause** | Heap, fired by every ROM-load via `AddExState`. **Fixed.** |
| `src/unif.cpp:158` | Latent (production) | UNIF path reachable in production. **Fixed (paired).** |
| `src/input/bworld.cpp:64,65` | Latent (stack) | `bdata[32]` backing, no actual corruption in practice but semantically wrong. **Fixed (paired).** |
| `src/drivers/Qt/input.cpp:1180` | Dead code | Commented out in an existing line. No action needed. |

`grep sizeof\\s*\\(\\s*\\(?char\\s*\\*\\)?` after this errata: 0 matches in real code (only 2 comment references and 1 commented-out call remain). The bug class is closed.
