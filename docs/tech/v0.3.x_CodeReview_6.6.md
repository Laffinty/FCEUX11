## 0. Summary

v0.3.6.6 is a small errata sub-version that closes two loose ends from the
v0.3.6.5 REDO:

1. A previous AI agent had attempted to add clang tooling (`.clang-format`,
   `.clang-tidy`, `tools/lint/clang-tidy-check.sh`, `tools/lint/format-check.sh`,
   `tools/lint/full-lint.sh`, and the `ENABLE_LINT` option in `CMakeLists.txt`)
   to a project whose plan §3.1 explicitly locks the toolchain to MSVC-only.
   The user ordered that attempt to stop, and most of those files were deleted
   in commit `a606561` (v0.3.6.5 errata). v0.3.6.6 finishes the cleanup of
   the remaining clang references that the errata commit did not touch:
   - the `option(ENABLE_LINT "Enable static analysis targets (clang-tidy, cppcheck)" OFF)`
     still named a clang-tidy target
   - the `if(ENABLE_LINT)` block still tried to find `clang-tidy` and define
     `lint-clang-tidy`
   - `compile_commands.json` was documented as "for clang-tidy / IDE integration"
   - `_build_asan.ps1`, `_build_ubsan.ps1`, and `ci.yml` still passed
     `-DENABLE_LINT=OFF`
   - `src/drivers/Qt/fceuWrapper.cpp:174-175` and `src/types.h:182` had
     `__clang__` defensive macros (per user direction 2026-06-11: remove all
     `__clang__` from first-party code, third-party headers stay)

2. The 12 code-quality items (5 MEDIUM + 7 LOW) deferred from the v0.3.6.5
   code review are closed in this commit.

**Out of scope (deliberately not changed)**:
- `src/utils/tl/expected.hpp`, `src/utils/expected.hpp`: third-party polyfill
  headers from TanLiang, contain `__clang__` defensive macros for
  portability. Touching them would diverge from upstream and risk breaking
  the polyfill.
- `src/utils/backward.hpp`, `src/utils/backward.cpp`: third-party
  `Backward-cpp` stack-tracing library. Same reason.
- `clang_rt.asan_dynamic-x86_64.dll` and similar: these are the **MSVC
  official file names** for the AddressSanitizer runtime; the `clang_rt`
  prefix is a historical naming choice from the original LLVM project but
  the files ship with every MSVC install and cannot be renamed. References
  to these in scripts, comments, and `tests/CMakeLists.txt` are correct
  and must stay.

## 2. Memory safety — v0.3.6.6 diff itself

**No new memory-safety issues introduced by the v0.3.6.6 errata diff.** The
errata touches:
- `CMakeLists.txt` and `src/CMakeLists.txt`: build configuration only.
- `scripts/_find_vcvars.bat` (new): pure bat file path-discovery helper.
- `scripts/_with_vcvars.bat`, `scripts/_probe_msvc_asan.bat`, `_build_asan.ps1`,
  `_build_ubsan.ps1`, `_verify_asan_instrumentation.ps1`: PowerShell / batch
  script changes; no C++ source touched.
- `.github/workflows/ci.yml`: CI step arg only.
- `src/drivers/Qt/fceuWrapper.cpp:174-175`: deleted two preprocessor lines
  inside a `#if defined(MSVC) / #elif defined(__GNUC__) / #elif defined(__clang__)`
  ladder. The MSVC branch is the one taken in this build; deleting the clang
  branch cannot affect the generated code.
- `src/types.h:182`: deleted `|| defined(__clang__)` from a `#elif` predicate
  under `_MSC_VER / __GNUC__ / FCEU_HAS_CPP_ATTRIBUTE(format)`. The MSVC
  branch is taken; the GCC / FCEU_HAS_CPP_ATTRIBUTE branches are unreachable
  but harmless. Removing the `__clang__` predicate cannot affect MSVC builds.
- Documentation files: no code change.

The F-1 closure (root cause `src/state.cpp:766` + paired `src/unif.cpp:158`
and `src/input/bworld.cpp:64,65`) is **not** in this errata — it was
correctly closed in the v0.3.6.5 errata commit `a606561`. v0.3.6.6 only
*normalises* the surrounding documentation (CHANGELOG F-1 framing,
Checkpoint report status table, followup file move) to reflect that
closure.
