【写在前面 / Preface】
================================================================================

  FCEUX11 的输入系统经历了 3 个阶段：
    v0.2.x  : 单 SDL 后端
    v0.3.x  : 引入 InputManager 抽象 + 多后端
    v0.3.14 : 修复键盘事件路径（A+B 双路径）
  本章把 InputManager 抽象、多后端、键盘双路径一次性讲清楚。

  本章目标：
    1. 解释 InputManager / InputBackend / InputDevice 抽象
    2. 拆解 SDL / XInput / WGI 三个后端的实现差异
    3. 解释键盘事件为什么需要"双路径"以及怎么走
    4. 解释 DeviceNum 32-slot 路由
    5. 给出常见故障的诊断方法

  阅读时间：约 25 分钟。
  前置知识：01、06 章；了解 Windows 消息机制 (WM_INPUT) 有帮助。

================================================================================
1. 整体架构：InputManager + 后端
================================================================================

  FCEUD_UpdateInput() 每帧被 120Hz QTimer 调一次，
  内部调 InputManager::pollAll()，由各个后端独立采样设备状态。

  ┌──────────────────────────────────────────────────────────┐
  │  FCEUD_UpdateInput()  (src/drivers/Qt/input.cpp)         │
  └────────────────────────┬─────────────────────────────────┘
                           │ InputManager::pollAll()
                           ▼
  ┌──────────────────────────────────────────────────────────┐
  │  InputManager  (src/drivers/Qt/input/input_manager.cpp)  │
  │  - 持有多个 InputBackend 实例                             │
  │  - 统一分配 DeviceNum (32-slot per backend)              │
  │  - 提供 testButton() 统一查询接口                        │
  └─────┬─────────────┬────────────────┬─────────────────────┘
        │ SDL         │ XInput         │ WGI (opt-in)
        ▼             ▼                ▼
  ┌──────────┐  ┌──────────┐    ┌──────────┐
  │ SDLBackend│  │XInputBackend│  │WGIBackend│
  └─────┬────┘  └─────┬────┘    └─────┬────┘
        │              │                │
        ▼              ▼                ▼
   SDLDevice       XInputDevice      WGIDevice
   (jsDev_t*)     (4 fixed slots)  (dynamic list)

  调用入口：src/drivers/Qt/input.cpp，主线程 120Hz QTimer
  （consoleWin_t::updatePeriodic）调一次 FCEUD_UpdateInput()。

================================================================================
2. DeviceNum 编号方案（32-slot 块）
================================================================================

  ButtConfig::DeviceNum 保持 int 类型（不破坏配置文件序列化）。
  后端按 32-slot 块划分：

  ┌─────────┬───────────────┬──────────────────────────────┐
  │ 后端    │ DeviceNum 范围 │ 备注                          │
  ├─────────┼───────────────┼──────────────────────────────┤
  │ SDL     │ 0 – 31        │ 与旧版 MAX_JOYSTICKS 一致     │
  │ XInput  │ 32 – 35       │ 最多 4 个 XInput 用户槽位    │
  │ WGI     │ 36 – 39       │ 枚举顺序的前 4 个 WGI 手柄   │
  └─────────┴───────────────┴──────────────────────────────┘

  InputManager::testButton() 用 kBackendFromDeviceNum() 和
  kLocalDeviceIndex() 把 DeviceNum 路由到对应后端。

  新增后端时：在 BackendId 枚举追加 + 按 32-slot 对齐分配范围。

================================================================================
3. 三种后端实现细节
================================================================================

  3.1 SDL 后端（src/drivers/Qt/input/sdl_backend.cpp）

    初始化：SDL_INIT_JOYSTICK
    复用既有 jsDev_t 数组（g_sdlJsDev[]），保留旧版映射和配置代码
    SDLDevice::button() 理解旧版按钮编码：
      - 帽子按钮：0x2000
      - 轴按钮：  0x8000
      - 普通按钮：低字节
    pollAll() 调 SDL_PumpEvents()，让 SDL 内部 joystick 状态保持新鲜

  3.2 XInput 后端（src/drivers/Qt/input/xinput_backend.cpp）

    运行时加载 xinput1_4.dll（不静态链接）
    用 GetProcAddress 拿 XInputGetState / XInputSetState
    DLL 不存在时优雅降级（旧版 Windows 或裁剪环境）
    按钮 ID 0-13 映射到：
      A/B/X/Y/LB/RB/Back/Start/LS/RS/DPadUp/DPadDown/DPadLeft/DPadRight

  3.3 WGI 后端（src/drivers/Qt/input/wgi_backend.cpp）

    仅在定义 FCEUX11_WGI_BACKEND 时编译
    用 C++/WinRT projection headers（__has_include 探测）
    headers 缺失时降级为 no-op，build 仍能成功
    用 Gamepad::SetVibration 启用高精度振动

  3.4 性能开销

  三个后端都是「同步」采样，单帧内总耗时 < 0.5 ms。
  WGI 异步路径可能导致单帧抖动，但 120 Hz timer 周期内仍可接受。

================================================================================
4. UI / 配置：GamePadConf
================================================================================

  GamePadConf 现在把已连接的 XInput 手柄列在 Device 下拉框里
  （与 SDL joystick 并列）。选 XInput 设备时分配一个固定默认 NES 映射
  （A/B/Select/Start/D-pad/TurboA/TurboB 映射到对应 XInput 面部按钮）。

  GUID 在配置中存为 XInput_N。GamePad_t::init() 在下次启动时如果该
  控制器连着，会恢复设备索引和默认映射。

  约束：
    - SDL 按钮学习（DWaitButton）只看到 SDL 事件
    - XInput 定制目前只能编辑配置或用默认映射

5. 键盘事件路径：双路径的由来
================================================================================

  键盘不走 InputManager（每个后端只懂手柄），走单独的 SDL 路径。
  键盘输入有两条互补路径，均为 v0.3.14 修复后建立，任一路径都能
  独立将按键送达 g_keyState：

  ┌─────────────────────────────────────────────────────────────────┐
  │ 路径 A — SDL_PumpEvents (raw input 层)                          │
  │                                                                 │
  │ 主线程：                                                         │
  │   1. QApplication event loop 跑（Qt pump Windows 消息）          │
  │   2. 0ms QTimer 定时调 SDL_PumpEvents()                         │
  │      把主线程消息队列里的 WM_INPUT 转成 SDL 事件                  │
  │   3. consoleWin_t::updatePeriodic() 120Hz 调 FCEUD_UpdateInput  │
  └─────────────────────────────────────────────────────────────────┘

  ┌─────────────────────────────────────────────────────────────────┐
  │ 路径 B — QOpenGLWindow keyPressEvent (Qt 事件层)                  │
  │                                                                 │
  │ QOpenGLWindow 是独立顶层 QWindow，焦点在其上时 Qt 把            │
  │ QKeyEvent 派发给它而非 QMainWindow。                              │
  │ ConsoleViewGL_t override 了 keyPressEvent / keyReleaseEvent,    │
  │ 调用 pushKeyEvent()（keyscan.cpp:1309）将 QKeyEvent 转换为       │
  │ SDL_Event 并通过 SDL_PushEvent() 推入 SDL 队列。                  │
  └─────────────────────────────────────────────────────────────────┘

  双路径总图：

    WM_INPUT ── SDL_PumpEvents ──┐
    (0ms QTimer, 路径 A)         │
                                ▼
    QKeyEvent ── pushKeyEvent ──► SDL 事件队列 ──► SDL_PollEvent()
    (QOpenGLWindow, 路径 B)               │      (UpdatePhysicalInput)
                                         ▼
                                  g_keyState[scancode]
                                         │
                                         ▼
                                  DTestButton → JSreturn

  两条路径不冲突：SDL_PushEvent 是线程安全的，两个路径可同时推事件
  入队。UpdatePhysicalInput 用 SDL_PollEvent 统一消费。

  SDL_KEYDOWN / KEYUP 事件（两条路径最终都汇入此队列）：
    - 在 UpdatePhysicalInput 里被 SDL_PollEvent 取出
    - 更新 g_keyState[scancode]
    - 调 KeyboardCommands（处理热键）

  FCEUD_UpdateInput 链路：
    InputManager::pollAll()    → SDL_PumpEvents（再 pump 一次）
    UpdatePhysicalInput       → SDL_PollEvent → g_keyState
    KeyboardCommands
    UpdateGamepad             → DTestButton（查 g_keyState）→ JS bit

================================================================================
6. 路径 B 的详细实现
================================================================================

  ConsoleViewGL_t 必须 override 两个 Qt 事件处理函数：

    void ConsoleViewGL_t::keyPressEvent(QKeyEvent* event) {
        pushKeyEvent(event, true);
        event->accept();
    }
    void ConsoleViewGL_t::keyReleaseEvent(QKeyEvent* event) {
        pushKeyEvent(event, false);
        event->accept();
    }

  pushKeyEvent 在 keyscan.cpp:1309：

    void pushKeyEvent(QKeyEvent* qe, bool pressDown) {
        SDL_Keycode sym = mapQtKeyToSDL(qe);
        SDL_Scancode sc = SDL_GetScancodeFromKey(sym);
        SDL_Event ev;
        ev.type = pressDown ? SDL_KEYDOWN : SDL_KEYUP;
        ev.key.keysym.sym = sym;
        ev.key.keysym.scancode = sc;
        SDL_PushEvent(&ev);
    }

  关键：event->accept() 让 Qt 不要再向上传播，避免被 QMainWindow
  重复处理成"快捷键"。

7. 迁移注意
================================================================================

  - 现有输入预设和保存的配置文件能无修改加载，因为 ButtConfig 布局没变
  - 新代码应通过 InputManager::testButton() 查询输入，
    不要直接读 SDL joystick 状态
  - DTestButtonJoy() 保留为兼容 wrapper，新代码优先用 testButton()

8. 常见故障诊断
================================================================================

  症状 1：手柄/键盘都不响应
    - 检查 SDL_PumpEvents 是否在主线程（详见 08 §3）
    - 检查 FCEUD_UpdateInput 是否被调用（120Hz QTimer 是不是被 disarm）
    - 打印 JSreturn 看是否有 bit 被置位

  症状 2：键盘 OK 手柄不响应
    - 检查 DTestButtonJoy / testButton 路径
    - 检查 InputManager::backends_ 是否非空
    - 用 fceu11::input::InputManager::instance().printState() 看后端列表

  症状 3：手柄 OK 键盘不响应
    - 这是 08 章 §3 案例 B —— 0ms QTimer 没装
    - g_keyState 永远 0，JS 永远 0

  症状 4：XInput 手柄默认映射错位
    - 检查 xinputMap[] 数组（sdl-joystick.cpp:384）
    - 改完后必须更新 fceux11_input_regression_test

  症状 5：FCEUD_UpdateInput 死锁
    - 看 fceuWrapper.cpp line 1377 注释掉的 FCEUD_UpdateInput
    - 确认 updatePeriodic / emuFrameFinish 路径都通
    - 排查 fceuWrapperTryLock 互斥锁

  症状 6：QOpenGLWindow 焦点时键盘丢失
    （MID 面板 / ROM 列表区键盘正常）
    - 检查 ConsoleViewGL_t 是否 override 了 keyPressEvent / keyReleaseEvent
    - 检查是否调用 pushKeyEvent(event, pressDown) + event->accept()
    - 这是 08 §3 方案 C —— QOpenGLWindow 独立 HWND 导致 Qt 事件路由断裂
