## 1. 范围 (Scope)

将 v0.2.30 沿用的 C 风格手工内存管理 (raw malloc / FCEU_gmalloc / FCEU_dmalloc)
替换为 C++ RAII 包装 (`std::unique_ptr` + 自定义删除器),在不改变 savestate 字节级
一致性的前提下,确保 mapper PRG-RAM 等热路径在异常/提前返回时的自动释放。

**基线依赖**:
- v0.3.5 (缓冲区安全) — 已完成 `sprintf/strcpy/strcat` 全面清理,所有 hot-path
  字符串拼接改用 `safe_format` / `FCEU_strlcpy`。
- v0.3.4 (死代码清理) — 已删除 `types-des.h` 残留、DeSmuME/NDS 死段,`types.h`
  254 行已缩减,本版本继续拆分。
- v0.3.3 (C++20 完备化) — `std::span` / `tl::expected` 已就绪,本版本在
  `utils/memory.h` 中继续落实 `[[deprecated]]` 警告。

## 2. 实施内容 (Changes)

### 2.1 弃用 (Deprecation)

- `FCEU_malloc / FCEU_free / FCEU_dmalloc / FCEU_dfree` 标记为
  `[[deprecated]]` (C++14) / `__declspec(deprecated)` (MSVC) / 空 (抑制时)。
  抑制宏 `FCEUX11_NO_DEPRECATION_WARNINGS` 在 v0.4.0 前可用。
- 弃用消息明确指向替代方案: `std::make_unique_for_overwrite<uint8_t[]>(n)` 或
  `std::pmr::get_default_resource()->allocate(n)`。
- `utils/memory.cpp` 自身实现这些函数,故顶部 `#define FCEUX11_NO_DEPRECATION_WARNINGS`
  抑制自身警告 — 外部调用方仍能看到。

### 2.2 RAII 删除器与助手 (utils/memory.h)

新增:

```cpp
struct FceuMallocDeleter {
    void operator()(uint8_t* p) const noexcept { if (p) FCEU_gfree(p); }
};
using FceuMallocPtr = std::unique_ptr<uint8_t[], FceuMallocDeleter>;

inline FceuMallocPtr FCEU_gmalloc_unique(size_t size) {
    return FceuMallocPtr(static_cast<uint8_t*>(FCEU_gmalloc(size)));
}
```

`FceuMallocDeleter` 严格匹配 `FCEU_gmalloc` 的 `malloc` 后端 (→ `FCEU_gfree` →
`free`)。**禁止**替换为 `delete/delete[]` (UB)。

### 2.3 fceuScopedPtr 迁移 (types.h, state.cpp)

`fceuScopedPtr<T>` 整段类定义替换为 `using` 别名:

```cpp
template <typename T>
using fceuScopedPtr [[deprecated("...")]] = std::unique_ptr<T>;
```

`fceuAllocType` 枚举保留 (向后兼容),但所有内部实现删除。

迁移点: `state.cpp:586` 仅一处使用 `fceuScopedPtr<EMUFILE> st`,已替换为
`std::unique_ptr<EMUFILE> st;` (reset() 替代 operator=)。

### 2.4 Mapper PRG-RAM RAII 化 (src/boards/*.cpp)

`FCEU_gmalloc` / `FCEU_dmalloc` 在 69 个文件中出现 95 次,全部迁移为
`FCEU_gmalloc_unique(N)` + `static FceuMallocPtr NAME_owner;` 的 RAII 模式。

模式:

```cpp
// Before
static uint8 *WRAM = NULL;
...
WRAM = (uint8*)FCEU_gmalloc(WRAMSIZE);
...
static void M103Close(void) {
    if (WRAM) FCEU_gfree(WRAM);
    WRAM = NULL;
}

// After
static uint8 *WRAM = NULL;
static FceuMallocPtr WRAM_owner;  // v0.3.6: RAII owner; FCEU_gfree on destruction
...
WRAM_owner = FCEU_gmalloc_unique(WRAMSIZE);
WRAM = WRAM_owner.get();
...
static void M103Close(void) {
    WRAM_owner.reset();  // v0.3.6: RAII owner frees via FCEU_gfree
    WRAM = nullptr;
}
```

自动化: `tools/transform_v036.py` Python 脚本负责一致性迁移,处理:
- 嵌套括号 size 表达式 (如 `sizeof(cfi_data) * 2`)
- `extern` / bare / `static` 三种 `uint8*` (或任意指针类型) 声明
- 跨文件 `extern` 指针的 `FCEU_gfree` 保留 (不转换为 reset())
- 转换 `FCEU_dmalloc` (merged with `FCEU_malloc` in v0.3.6) 与 `FCEU_free` 调用
- 对 `extern` 指针(由其他 TU 分配/释放)保留原 `FCEU_gfree` 调用,
  避免跨 TU 双重释放
- 对用户自定义类型(如 `nes_ntsc_t*`)保留原 `(TYPE*)` cast 语义

幂等性: 脚本对已迁移文件 / 已迁移 call site 是 no-op,可重复运行。

### 2.5 CFG (Control Flow Guard) 验证 (fceu.h)

`/guard:cf` 已在 `CMakeLists.txt:31` 全局启用,`/GUARD:CF` 在链接器启用。
v0.3.6 验证 mapper 写函数 (`DECLFW(x) void x(uint32, uint8)`) 通过
`SetWriteHandler()` 间接调用时,MSVC 自动插入 CFG 守卫检查,**无需** 逐函数
添加 `__declspec(guard_overwrite)`(该属性用于 C++ vtable,非函数指针表)。

`fceu.h` 顶部添加注释,记录这一验证结论(并提供 v0.4.x 时如需重新评估的入口)。

### 2.6 其他

- `src/fceu.cpp`: `RAM = (uint8*)FCEU_gmalloc(0x800);` 迁移为 `RAM_owner` 模式,
  `FreeBuffers()` 中的 `FCEU_free(RAM)` 迁移为 `RAM_owner.reset()` (避免双重释放)。
- `src/ines.cpp`: `ROM / VROM` 是 `extern`(在 `ines.cpp` 之外被定义),保留原
  `FCEU_free` 调用(避免误转)。
- `src/drivers/common/vidblit.cpp`: 处理 11 个 `FCEU_dmalloc` (含 `nes_ntsc_t*` /
  `uint32*` / `uint16*` / `float*` 多种类型) + 5 个 `FCEU_free`。
- `src/nsf.cpp` / `src/fds.cpp`: 处理 `ExWRAM` / `FDSBIOS` / `CHRRAM` / `FDSRAM`
  的 PRG-RAM 分配。
- `src/state.cpp`: `FCEUSS_Load` 中的 `fceuScopedPtr<EMUFILE>` 替换为
  `std::unique_ptr<EMUFILE>`。
