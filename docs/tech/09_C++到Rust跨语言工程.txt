================================================================================

  FCEUX11 自 v0.2.1 起把 C++ 模块逐步迁移到 Rust。这是模拟器生态中
  比较罕见的尝试：CPU / PPU / APU 等"必须 cycle-accurate"的核心
  仍是 C++；工具、格式、媒体、Lua 绑定等"无状态"模块优先 Rust。

  本章把这套跨语言工程一次讲清楚：
    - 为什么选 Rust？迁移优先级与原则
    - FFI 5 种稳定模式
    - cbindgen 自动头文件生成
    - EMUFILE std::span / std::byte 现代化
    - Cargo feature 与 FFI 边界
    - 双侧测试与回归门控

  阅读时间：约 35 分钟。
  前置知识：懂 C++ 虚函数、模板；懂 Rust 基础语法与 Cargo workspace。

================================================================================
1. 为什么把 C++ 迁到 Rust？
================================================================================

  1.1 内存安全

  Rust 的所有权 + borrow checker 编译期阻止 use-after-free、
  double-free、data race。这对 savestate 序列化、parser 类的代码
  价值巨大。

  1.2 工具链现代化

  - Cargo workspace 替代手写 Make / CMake 子目录
  - 自动生成 C 头文件 (cbindgen)
  - 单一 cargo test --workspace 覆盖所有 crate

  1.3 不可逆迁移原则

  从 v0.2.12 起：模块 Rust 化后立即删除 C++ 回退代码。
  目的：避免"双份代码"导致的 bug 漂移（同一逻辑两套实现，
  行为会缓慢分歧）。

  1.4 行为等价性约束

  Rust 化的模块必须与原 C++ 实现：
    - 输出逐字节一致
    - 性能退化不超过 110%

  这是 CI 强制门控（详见 12 章）。

3. Workspace 结构
================================================================================

  src/rust/
  ├── Cargo.toml           # Workspace 根
  ├── cbindgen.toml        # 头生成配置
  ├── build.rs             # 调 cbindgen，合并多个 crate 头
  ├── fceux11_rust.h       # 合并后的最终头（自动生成）
  └── crates/
      ├── fceux11-utils/
      ├── fceux11-formats/
      ├── fceux11-media/
      ├── fceux11-debug/
      ├── fceux11-lua/
      └── fceux11-core/

  Crate 依赖规则：
    - 必须构成 DAG，禁止循环依赖
    - 每个 sub-crate 为 rlib
    - root crate 统一 re-export 为 staticlib
    - C++ 链接到 fceux11_rust.lib

  fceux11_rust.h 冻结：
    从 v0.2.30 起，这个头由 cbindgen 自动生成，签名为 FFI 契约。
    修改签名需走 RFC 流程（14 章 §FFI 冻结期）。

4. FFI 5 种稳定模式
================================================================================

  FCEUX11 沉淀出 5 种 FFI 模式，可作为"任何 C++ → Rust 项目"的参考：

  4.1 模式 1：纯函数

  无状态计算（CRC32, MD5）：

    #[unsafe(no_mangle)]
    pub extern "C" fn fceux11_md5(data: *const u8, len: usize,
                                  out: *mut u8) {
        if data.is_null() { return; }
        let slice = unsafe { std::slice::from_raw_parts(data, len) };
        let digest = md5::compute(slice);
        unsafe { std::ptr::copy_nonoverlapping(digest.as_ptr(), out, 16); }
    }

  指针检查 is_null()，用 from_raw_parts 构造 slice。
  永远是「指针入 + 指针出」，无所有权转移。

  4.2 模式 2：Thread-Local 返回缓冲区

  变长字符串返回（GUID, 错误信息）：

    thread_local! {
        static RETURN_BUF: RefCell<[u8; 512]> = RefCell::new([0; 512]);
    }

    #[unsafe(no_mangle)]
    pub extern "C" fn fceux11_gen_guid() -> *const u8 {
        let guid = gen_guid_internal();
        RETURN_BUF.with(|b| {
            let mut b = b.borrow_mut();
            b[..guid.len()].copy_from_slice(&guid);
            b.as_ptr()
        })
    }

  固定 512 字节，调用方必须立即 memcpy。
  thread_local 避免多线程同时写同一缓冲。

  4.3 模式 3：Opaque Pointer + Handle

  有状态组件（Profiler, Filter）：

    pub struct Profiler { /* ... */ }

    #[unsafe(no_mangle)]
    pub extern "C" fn fceux11_profiler_create() -> *mut Profiler {
        Box::into_raw(Box::new(Profiler::new()))
    }

    #[unsafe(no_mangle)]
    pub extern "C" fn fceux11_profiler_destroy(p: *mut Profiler) {
        if !p.is_null() {
            unsafe { drop(Box::from_raw(p)); }
        }
    }

  create 用 Box::into_raw，destroy 用 Box::from_raw。
  关键：调用方必须配对 create/destroy。

  4.4 模式 4：Slice 结构体

  传递大块缓冲区（像素, 音频, ROM）：

    #[repr(C)]
    pub struct FceuSlice {
        pub ptr: *const u8,
        pub len: usize,
    }

  双向都有对应的 FceuSliceMut（*mut u8）。
  视图不拥有数据，由调用方负责生命周期。

  4.5 模式 5：批量回调 / Chunk 编排

  复杂序列化（Savestate）：

    #[unsafe(no_mangle)]
    pub extern "C" fn fceux11_state_save_chunk(
        user: *mut c_void,            // 回调 user data
        write_cb: unsafe extern "C" fn(*mut c_void, FceuSlice) -> i32,
    ) -> i32 {
        // Rust 负责外壳（version, total size, header chunk）
        write_cb(user, slice_of("FCS"));
        // C++ 负责每个 chunk 的 payload（通过回调写入）
        for chunk in chunks {
            let payload = chunk.to_bytes();
            if write_cb(user, slice_of(&payload)) != 0 { return -1; }
        }
        0
    }

  Rust 负责压缩 / 版本 / 头，C++ 负责每个 mapper 的实际字段序列化。

5. cbindgen 工具链
================================================================================

  cbindgen = 读 Rust 源码，自动生成对应的 C/C++ 头文件。

  src/rust/cbindgen.toml:

    language = "C"
    cpp_compat = false
    include_version = true
    header = "/* Auto-generated by cbindgen. Do not edit. */"

    [parse]
    parse_deps = false

    [export]
    prefix = ""
    [export.rename]
    "Md5Context" = "md5_context"

  src/rust/build.rs:

    fn main() {
        // 1. 对每个 crate 调 cbindgen 生成子头
        for crate_name in ["fceux11-utils", "fceux11-media", ...] {
            Command::new(cbindgen)
                .args(&["--crate", crate_name, "--output", sub_header])
                .status().unwrap();
        }
        // 2. 合并所有子头为 fceux11_rust.h
        merge_headers(...);
    }

  5.1 自动化触发

  build.rs 的 println!("cargo:rerun-if-changed=...") 告诉 Cargo 何时
  重新调 cbindgen。任何 Rust 源文件改动都会自动重生成头。

  5.2 头文件内容示例（节选）

    /* Auto-generated by cbindgen. Do not edit. */
    #ifndef FCEUX11_RUST_H
    #define FCEUX11_RUST_H
    #include <stdbool.h>
    #include <stdint.h>
    #ifdef __cplusplus
    extern "C" {
    #endif

    typedef struct FceuSlice {
      const uint8_t *ptr;
      size_t len;
    } FceuSlice;

    typedef struct FceuSliceMut {
      uint8_t *ptr;
      size_t len;
    } FceuSliceMut;

    void fceux11_md5(const uint8_t *data, size_t len, uint8_t *out);
    /* ... */

    #ifdef __cplusplus
    }
    #endif
    #endif

6. EMUFILE std::span / std::byte 现代化
================================================================================

  v0.3.10 完成的最大一次 FFI 边界改造。

  6.1 旧接口

    virtual size_t fread(void* ptr, size_t size) = 0;
    virtual size_t fwrite(const void* ptr, size_t size) = 0;

  6.2 新接口

    virtual size_t fread(std::span<std::byte> dst) = 0;
    virtual size_t fwrite(std::span<const std::byte> src) = 0;

  6.3 兼容 shim

    [[deprecated("use std::span overload (v0.3.10)")]]
    size_t fread(void* ptr, size_t bytes) {
        return fread(std::span<std::byte>(
            static_cast<std::byte*>(ptr), bytes));
    }
    [[deprecated("use std::span overload (v0.3.10)")]]
    size_t fwrite(const void* ptr, size_t bytes) {
        return fwrite(std::span<const std::byte>(
            static_cast<const std::byte*>(ptr), bytes));
    }

  保留 [[deprecated]] 标记到 v0.4.0，让 30+ 旧调用方继续工作。

  6.4 转换规则

    // uint8_t → std::byte
    auto b = std::byte{val};

    // std::byte → uint8_t
    auto u = std::to_integer<uint8_t>(b);

    // 写入外部 API
    some_c_api(reinterpret_cast<const uint8_t*>(span.data()),
               span.size());

  完整规则见 13 章 / src/utils/fceu11_expected.cpp。

7. Cargo feature 与 FFI 边界
================================================================================

  fceux11-lua 有个特殊 feature：

    [features]
    ffi-stubs = []    # 允许 cargo test --workspace 链接时去重

  不加 feature：cargo test 需要链接 src/lua-engine.cpp 的真实 FFI
                实现（CMake 已链接），与 CMake Release 双重符号冲突
  加 feature：crate 内部 stub 这些函数符号，让 Rust 侧单测能跑

  这种"feature 切换"是 C++ ↔ Rust 跨语言工程的常见解法。

8. 测试策略：三层金字塔
================================================================================

  层 1：Rust 单元测试（cargo test）
    - 每次 commit，失败阻止合并
    - 纯逻辑覆盖

  层 2：C++ 集成测试（ctest）
    - CI / 本地构建，失败阻止合并

  层 3：ROM 回归测试
    - CI nightly / 发布前，失败阻止发布
    - 字节级 / 帧级 行为等价性

  新模块测试 Checklist：
    - #[test] 覆盖正常路径、边界、错误输入
    - 纯计算模块 ≥5 个测试
    - 缓冲区模块：null 安全、零长度、越界测试
    - 文件格式模块：round-trip 测试（serialize→deserialize→逐字节比对）

9. 性能调优
================================================================================

  对比 1000 次调用平均耗时 vs C++ 基线，阈值 ≤ 110%。

  Release Profile：

    [profile.release]
    panic = "abort"
    lto = true
    codegen-units = 1
    debug = false

  进一步优化：
    - lto = "fat"（更慢链接但更激进优化）
    - #[inline(always)] 用于热函数
    - match 表达式被 LLVM 优化为跳转表

  Bus 解码典型对比：

    // C++：函数指针数组
    return ARead[A](A);   // 1 次间接调用

    // Rust：match + #[inline]
    match A {
        0x0000..=0x1FFF => ram_read(A),
        0x8000..=0xFFFF => rom_read(A),
        _ => default_read(A),
    }

    // 编译后两者都是跳转表，Rust 略快（无函数指针间接）

11. FFI 冻结期与 RFC
================================================================================

  从 v0.2.30 起，fceux11_rust.h 签名为 FFI 契约。

  改签名需走 RFC 流程：
    1. 在 docs/tech/ 提交 RFC（md 格式）
    2. 说明理由、影响范围、回退方案
    3. 至少一次代码审查
    4. 同步更新所有 C++ 调用方

  这是为了保证「外部用户（C++ 代码）不会因为 Rust 内部重构而崩溃」。
