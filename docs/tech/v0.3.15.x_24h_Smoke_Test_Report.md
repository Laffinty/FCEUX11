## 1. Test Objective

Run fceux11 v0.3.15.x continuously for 24 hours across 6 NES ROMs to detect:
- Memory leaks (steady-state RSS growth over 24h)
- GPU driver faults (Win11 DWM / OpenGL context loss under sustained rendering)
- Audio buffer underruns (SDL2 + WinMM backend starvation)
- Save-state integrity (write → load → hash identical to Gate 3 reference)
- Crash-on-sleep / wake-up behavior (laptop cover close)
- Crash-on-language-switch (zh_CN ↔ en ↔ zh_TW rotation)

The PHASE-5 build (commit `252caac`) is the candidate binary.

## 3. Test Protocol

### 3.1 Per-ROM loop (1 hour each × 6 ROMs = 6 hours × 4 cycles)

```
For each ROM in roster:
    Launch:    fceux11.exe --no-console <rom>
    Wait 5s    (boot + rom init)
    Record:    RAM working set (Get-Process fceux11)
               GPU engine utilization (RenderDoc / GPUView)
    Loop for 60 minutes:
        Every 60s:
            Save-state to C:\smoke\<rom>-<cycle>-<minute>.fc0
            Take window screenshot (PowerShell + System.Drawing)
            Record RSS / CPU% / GPU%
        Every 5 minutes:
            Rotate input A/B button 100 times (game pad stress)
        Every 15 minutes:
            Switch language: en → zh_CN → zh_TW → en
            Open ConsoleDebugger → close
            Open HexEditor → search for "FF FF" → close
            Open TasEditor → close
    At 60-minute mark:
        Stop the process
        Hash all saved states (sha256sum *.fc0 > <rom>-<cycle>.sha256)
        Verify hashes match the v0.3.14 reference hashes (see Gate 3)
        Restart and proceed to next ROM
```

### 4.5 Save-state integrity

For each `*.fc0` written during the run, load it in a fresh `fceux11.exe --no-console` invocation and verify:
- Frame counter equals the recorded value
- PPU framebuffer hash matches Gate 3 reference at the same frame
- No "Save-state version mismatch" error message

Any mismatch is a savestate regression → release blocker.
