# FCEUX11 v0.3.13 Input System Refactor

## Scope

This document records the v0.3.13 input-system refactor described in
`docs/v0.3.x_Construction_Plan_v3.md` §5 v0.3.13.

Goals:

- Introduce a backend-agnostic input abstraction.
- Support SDL, XInput, and optional Windows.Gaming.Input (WGI) backends.
- Keep existing zapper / powerpad / Famicom keyboard / arkanoid devices
  regression-free.
- Preserve byte-level savestate compatibility.

## Architecture

```text
┌─────────────────────────────────────────────────────────────┐
│                    FCEUD_UpdateInput()                      │
│                       (input.cpp)                           │
└───────────────────────┬─────────────────────────────────────┘
                        │ InputManager::pollAll()
                        ▼
┌─────────────────────────────────────────────────────────────┐
│                     InputManager                            │
│  owns one InputBackend per underlying API                   │
└───────┬───────────────┬───────────────────┬─────────────────┘
        │ SDL           │ XInput            │ WGI (optional)
        ▼               ▼                   ▼
   SDLBackend      XInputBackend     WindowsGamingInputBackend
        │               │                   │
        ▼               ▼                   ▼
    SDLDevice      XInputDevice        WGIDevice
   (jsDev_t*)     (4 fixed slots)    (dynamic list)
```

## Device Numbering

`ButtConfig::DeviceNum` is kept as an `int` to avoid breaking configuration
serialization.  Backends are partitioned by fixed 32-slot blocks:

| Backend | DeviceNum range | Notes |
|---------|-----------------|-------|
| SDL     | 0 – 31          | Same range as before (`MAX_JOYSTICKS`). |
| XInput  | 32 – 35         | Up to 4 XInput user slots. |
| WGI     | 36 – 39         | First 4 enumerated WGI gamepads. |

`InputManager::testButton()` uses `kBackendFromDeviceNum()` and
`kLocalDeviceIndex()` to route queries.

## Backend Details

### SDL (`sdl_backend.cpp`)

- Initializes `SDL_INIT_JOYSTICK`.
- Re-uses the existing `jsDev_t` array (`g_sdlJsDev[]`) so legacy mapping
  and configuration code continue to work.
- `SDLDevice::button()` understands the legacy button encodings:
  - hat buttons: `0x2000`
  - axis buttons: `0x8000`
  - plain buttons: lower bits

### XInput (`xinput_backend.cpp`)

- Loads `xinput1_4.dll` at runtime.
- Acquires `XInputGetState` and `XInputSetState` via `GetProcAddress`.
- Falls back cleanly when the DLL is absent (common on older Windows or
  stripped environments).
- Button ids 0-13 map to A/B/X/Y/LB/RB/Back/Start/LS/RS/DPadUp/DPadDown/
  DPadLeft/DPadRight.

### WGI (`wgi_backend.cpp`)

- Only compiled when `FCEUX11_WGI_BACKEND` is defined.
- Uses C++/WinRT projection headers when available (`__has_include`).
- If the headers are absent the backend initializes to a no-op state so the
  build still succeeds.
- Enables high-precision vibration via `Gamepad::SetVibration`.

## UI / Configuration

- `GamePadConf` now lists connected XInput gamepads in the **Device**
  drop-down alongside SDL joysticks.
- Selecting an XInput device assigns it a fixed default NES mapping
  (A/B/Select/Start/D-pad/TurboA/TurboB mapped to the matching XInput
  face buttons).
- The GUID is stored as `XInput_N` in the config; `GamePad_t::init()`
  restores both the device index and the default mapping on the next
  startup if the controller is connected.
- SDL button-learning (`DWaitButton`) still only sees SDL events; XInput
  customization must currently be done by editing the config or by using
  the default mapping.

## Migration Notes

- Existing input presets and saved configurations load unchanged because
  `ButtConfig` layout was not modified.
- New code should query input through `InputManager::testButton()` rather
  than reading SDL joystick state directly.
- `DTestButtonJoy()` remains as a compatibility wrapper.
