  FCEUX11 用 Qt 6 写 GUI。Qt 是事件驱动的框架，理解 Qt 事件循环
  是理解 FCEUX11 GUI 代码的前提。本章聚焦：

    - Qt 事件循环与 QApplication 的关系
    - 120Hz QTimer 怎么驱动模拟器
    - QOpenGLWindow 怎么贴 PPU 渲染结果
    - 跨线程问题：模拟器线程 vs UI 线程
    - 常见的"启动崩溃 / 键盘失效"问题

  本章目标：
    1. 解释 FCEUX11 的双线程模型（模拟器线程 + UI 线程）
    2. 拆解 QOpenGLWindow + OpenGL 3.3 Core 渲染管线
    3. 解释 updatePeriodic / emuFrameFinish 协作
    4. 解释 WM_INPUT 跨线程的解决思路
    5. 解释为什么 Qt event loop 是「主线程边界」

  阅读时间：约 30 分钟。
  前置知识：了解 Windows 消息机制；懂一点 OpenGL。

1. 双线程模型：UI 线程 + 模拟器线程
================================================================================

  FCEUX11 GUI 启动后有两个并发运行的线程：

  ┌──────────────────────────────────────────────────────────────┐
  │ UI 线程 (Qt main thread)                                      │
  │ - QApplication event loop 跑                                  │
  │ - 处理所有 QWidget / QWindow 事件                            │
  │ - 0ms QTimer 触发 SDL_PumpEvents()                           │
  │ - 120Hz QTimer (updatePeriodic) 触发 FCEUD_UpdateInput       │
  │ - 渲染：QOpenGLWindow::paintGL → 上传纹理 → 画 quad          │
  └──────────────────────────────────────────────────────────────┘
                            ▲           │
                            │ signals   │ emuFrameFinish
                            │ slots     ▼
  ┌──────────────────────────────────────────────────────────────┐
  │ 模拟器线程 (EmuThread)                                        │
  │ - 跑 FCEUI_FrameBoundary() 死循环                            │
  │ - 跑完一帧后发 emuFrameFinish signal 回 UI 线程              │
  │ - 期间更新 PPU 的 XBuf 共享缓冲（emufile 锁保护）           │
  └──────────────────────────────────────────────────────────────┘

  1.1 为什么需要双线程？

  模拟器主循环会"霸占"CPU。如果在 UI 线程跑，按钮点击会卡 16ms
  （一帧时间），用户感觉就是"卡顿"。把模拟器放后台线程后，UI 线程
  仍然能及时响应用户。

  1.2 数据共享

  - XBuf (PPU 渲染缓冲)  共享，但用 mutex 保护
  - savestate 字段       仅模拟器线程访问
  - 录像 / 输入         通过 Qt signal-slot 跨线程（自动 queued）
  - 调试器 hook         在模拟器线程触发，UI 线程只读

2. QApplication 与 Qt 事件循环
================================================================================

  src/drivers/Qt/main.cpp:

    int main(int argc, char** argv) {
        QApplication app(argc, argv);
        // ... 初始化 fceuWrapper, consoleWin_t
        consoleWin.show();
        return app.exec();   // 启动 Qt 事件循环
    }

  app.exec() 启动一个事件循环：
    1. 从 Windows 消息队列取 WM_PAINT / WM_KEYDOWN / WM_MOVE 等
    2. 分发到对应 QObject 的 event() 虚函数
    3. QWidget 子类 override event() 处理特定事件
    4. 未处理事件转给 QApplication::notify() 兜底

  关键事实：Qt 事件循环在 UI 线程。QObject 子类的事件默认在创建它的
  线程处理。这是"线程亲和性"。

  2.1 0ms QTimer 与 120Hz QTimer

    QTimer* zeroTimer = new QTimer(this);
    zeroTimer->setInterval(0);   // 0ms = "尽快"
    connect(zeroTimer, &QTimer::timeout, this, []() {
        SDL_PumpEvents();          // 把 WM_INPUT 转 SDL 事件
    });
    zeroTimer->start();

    QTimer* frameTimer = new QTimer(this);
    frameTimer->setInterval(1000 / 120);   // ~8.33ms
    connect(frameTimer, &QTimer::timeout, this, [this]() {
        this->updatePeriodic();   // 触发 FCEUD_UpdateInput 等
    });
    frameTimer->start();

  0ms timer 是 Qt 提供"尽快处理 Windows 消息但不阻塞事件循环"的惯用法。
  120Hz 是模拟器输入采样率（与 NES 60Hz 帧率匹配但额外采样）。

3. QOpenGLWindow 与 OpenGL 3.3 Core Profile
================================================================================

  FCEUX11 用 QOpenGLWindow（独立 QWindow 子类）而非 QWidget + QPainter
  来画 PPU 输出。原因：
    - QOpenGLWindow 拿到"独立顶层窗口"的 HWND，OpenGL 上下文创建
      更稳定（与 QWidget 共享的兼容性模式 QPainter 容易出 bug）
    - Qt 6 强制 OpenGL 3.3 Core Profile（v0.3.14 修复过崩溃）
    - 可直接调 glTexSubImage2D 上传 PPU XBuf

  3.1 渲染流程

    void ConsoleViewGL_t::paintGL() {
        QOpenGLFunctions_3_3_Core* f = QOpenGLContext::currentContext()
                                          ->versionFunctions<QOpenGLFunctions_3_3_Core>();
        f->glClear(GL_COLOR_BUFFER_BIT);

        // 上传 PPU 缓冲
        f->glBindTexture(GL_TEXTURE_2D, tex_);
        f->glTexSubImage2D(GL_TEXTURE_2D, 0, 0, 0, 256, 240,
                           GL_RGBA, GL_UNSIGNED_BYTE, xbuf_.data());

        // 画全屏 quad
        f->glBindVertexArray(vao_);
        f->glDrawArrays(GL_TRIANGLES, 0, 6);
    }

  3.2 启动崩溃的常见原因（v0.3.14 修复过）

  QOpenGLWindow 第一次 paintGL() 时如果 OpenGL 上下文还没"makeCurrent"
  就调 GL 函数，会 segfault。修复方式：

    void ConsoleViewGL_t::initializeGL() {
        QOpenGLFunctions_3_3_Core::initializeOpenGLFunctions();
        // 在这里初始化纹理、VAO、VBO —— 此时上下文已激活
    }

  initializeGL() 在第一次 paintGL() 之前由 Qt 自动调，OpenGL 上下文
  已 makeCurrent。绝不能把 GL 初始化放进 paintGL() 里。

  详见 15 章 §案例 A。

4. updatePeriodic：120Hz 钩子
================================================================================

  src/drivers/Qt/consoleWindow.cpp:

    void consoleWin_t::updatePeriodic() {
        if (fceuWrapperTryLock()) {
            FCEUD_UpdateInput();   // 采样输入
            // ...
            fceuWrapperUnLock();
        }
    }

  fceuWrapperTryLock 是非阻塞互斥锁：
    - 若模拟器线程没在跑（不持锁）→ 立刻返回 true，本帧继续
    - 若模拟器线程正在跑（持锁）→ 返回 false，本帧跳过

  这是为了避免 UI 线程"挤"模拟器线程造成卡顿。代价是：少数帧会
  错过输入采样，但 120Hz vs 60Hz NTSC 的过采样足够弥补。

5. emuFrameFinish：模拟器线程回 UI 线程的钩子
================================================================================

  src/drivers/Qt/fceuWrapper.cpp:

    void FCEUD_BlitScreen(uint8* XBuf) {
        // 拷贝 PPU 输出到 UI 线程可见的缓冲
        // 触发 ConsoleViewGL_t 重新 paint
        QMetaObject::invokeMethod(this, [this, XBuf]() {
            this->xbuf_ = XBuf;   // 拷贝
            this->update();        // 触发 paintGL
        }, Qt::QueuedConnection);
    }

  QueuedConnection 让 lambda 推到 UI 线程的事件队列。
  模拟器线程不直接调 QOpenGLWindow::update()（线程不安全）。

6. WM_INPUT 跨线程的解决
================================================================================

  Windows 的 WM_INPUT raw input 默认只发到"有焦点的 HWND 所在线程"。
  Qt 6 把焦点 HWND 放在 UI 线程，所以 SDL_PumpEvents() 也必须在
  UI 线程调。

  但 SDL 自己的事件队列是线程安全的，所以模拟器线程可以 SDL_PollEvent
  取事件（v0.3.14 之前 SDL_PollEvent 在模拟器线程，导致 SDL 内部状态
  与 UI 线程不同步，键盘失效）。

  修复：把 SDL_PumpEvents 移回 UI 线程（0ms QTimer），SDL_PollEvent
  仍可在模拟器线程或 UI 线程（路径 B 的 pushKeyEvent 在 UI 线程），
  但所有"喂事件给 SDL"的动作都必须在 UI 线程。

  详见 15 章 §案例 B。

7. 模拟器线程的启动与关闭
================================================================================

  src/drivers/Qt/fceuWrapper.cpp:

    void fceuWrapper::runEmuThread() {
        emuThread_ = std::thread([this]() {
            while (running_) {
                FCEUI_FrameBoundary(...);   // 跑一帧
                // ... 处理录像
            }
        });
    }

  关闭时：
    1. 设 running_ = false
    2. join 模拟器线程
    3. 释放所有资源

  死锁风险：互斥锁顺序不一致。FCEUX11 用一个全局 tryLock
  (fceuWrapperTryLock) 简化所有跨线程访问。

8. QOpenGLWindow 焦点导致键盘丢失
================================================================================

  QOpenGLWindow 是独立 QWindow。当它获得焦点时，Qt 把 QKeyEvent
  派发给它而非 QMainWindow。QMainWindow 上的快捷键（如 F5=开始）
  不再响应。

  修复：override keyPressEvent/keyReleaseEvent 并转发到 keyscan.cpp。
  详见 07 章 §5 路径 B。

9. 跨语言 FFI：Qt → C++ → Rust
================================================================================

  启动流程：
    1. QApplication 创建
    2. fceuWrapperInit() 调 FCEUI_Initialize()（C++ 内核）
    3. 若 -DFCEUX11_RUST_ENABLED=ON，初始化 fceux11_rust FFI 库
    4. consoleWin_t 创建
    5. 启动模拟器线程

  详见 09 章。

10. 性能：UI 线程开销
================================================================================

  - paintGL 1 帧：约 0.3 ms（256x240 RGBA 上传 + 1 quad draw）
  - 0ms QTimer：~0.01 ms 每次，Windows 消息多时 < 0.1 ms
  - 120Hz QTimer：~0.02 ms 每次
  - 总 UI 线程开销：< 5 ms / 秒
  - 模拟器线程：~10 ms / 帧（NTSC 60 Hz）
