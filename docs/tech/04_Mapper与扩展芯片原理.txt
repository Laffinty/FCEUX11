【写在前面 / Preface】
================================================================================

  Mapper 是 NES 模拟器最「脏」的部分——它们是 1985-1995 年间各家卡带
  厂商用 TTL 芯片搭出来的「私有内存切换协议」。FCEUX11 支持 200+ 个
  mapper，每个 mapper 是一对 .h/.cpp 文件（在 src/boards/ 下）。

  本章目标：
    1. 解释「什么是 mapper」与「为什么需要 mapper」
    2. 拆解 FCEUX11 mapper 实现的统一框架（SetReadHandler、setprg、setchr）
    3. 详解最常用的 5 个 mapper：NROM / MMC1 / MMC3 / UxROM / MMC5
    4. 介绍扩展音频芯片：MMC5 / VRC6 / VRC7
    5. 解释 mapper 的 savestate 序列化与回归测试

  阅读时间：约 40 分钟。
  前置知识：01、02、03 章；懂 C 语言结构体；懂 C++ 虚函数。

1. 什么是 mapper？为什么要分这么多？
================================================================================

  6502 CPU 只有 16 位地址线 = 64 KiB 可寻址空间。NES 自身占用
  16 KiB RAM + 8 KiB PPU 寄存器，留给卡带只有 48 KiB（$4020-$FFFF）。
  但超级玛丽的卡带是 320 KiB，塞尔达更大。

  解决方案：mapper 芯片把卡带 ROM「分页」到 CPU 的 $8000-$FFFF 窗口。
  CPU 写入 mapper 的 bank 寄存器决定「这次 $8000 看到的是 ROM 的哪 16 KiB」。

  不同游戏用不同 mapper 协议（不同寄存器地址、不同 page 大小），
  所以 iNES 头里有个 mapper ID 字段。FCEUX11 的 src/boards/ 目录
  共有 175+ 个 mapper.cpp，映射了主流 iNES mapper ID。

2. FCEUX11 mapper 实现的统一框架
================================================================================

  所有 mapper都遵循同一组 API（src/boards/mapinc.h 声明）：

  ┌────────────────────┬────────────────────────────────────────────────┐
  │ API                │ 用途                                           │
  ├────────────────────┼────────────────────────────────────────────────┤
  │ SetReadHandler     │ 注册 CPU 读某地址范围时调用的回调              │
  │ SetWriteHandler    │ 注册 CPU 写某地址范围时调用的回调              │
  │ setprg             │ 把某个 PRG 页映射到 $8000-$FFFF 某个窗口       │
  │ setchr             │ 把某个 CHR 页映射到 PPU 某个 1K/2K/4K/8K 窗口 │
  │ setmirror          │ 设置 name table 镜像方式                       │
  │ AddExState         │ 注册要序列化的状态字段（savestate 关键）       │
  │ SFORMAT            │ 状态字段描述数组                               │
  └────────────────────┴────────────────────────────────────────────────┘

  mapper 的「写寄存器」callback 一般是 DECLFW 宏：

    void DECLFW(MMC3_write) (uint32 A, uint8 V) {
        switch (A & 0xE001) {   // 屏蔽 A0 与 A13
        case 0x8000: MMC3_cmd = V; break;
        case 0x8001: DRegBuf[MMC3_cmd & 7] = V; /* ... */ break;
        // ...
        }
    }

  模拟器主代码在 src/cart.cpp 维护 ARead[0x10000] 与 BWrite[0x10000]
  两个 64K 字节的函数指针表，CPU 读/写地址时通过表 dispatch 到 mapper
  提供的 callback。

3. 一个具体例子：Mapper 0（NROM，最简单）
================================================================================

  NROM 没有 bank 切换：

    PRG：32 KiB 固定在 $8000-$FFFF（4 个 16 KiB bank，
                                  但 NROM 只支持 1 个 16K 或 2 个 16K）
    CHR：8 KiB 固定（ROM）或 8 KiB RAM

  FCEUX11 的实现（src/boards/00-099.cpp 中的 NROM_Init）：

    void NROM_Init(CartInfo *info) {
        if (info->PRGsize == 0x4000) {    // 16 KiB 镜像
            Page[2] = PRGptr[0] - 0x8000;
            Page[3] = PRGptr[0] - 0x8000;
        } else {                          // 32 KiB
            Page[2] = PRGptr[0] - 0x8000;
            Page[3] = PRGptr[1] - 0x8000;
        }
        if (info->CHRsize == 0) {
            // 8K CHR-RAM
        } else {
            // 8K CHR-ROM
        }
    }

  Page[2] / Page[3] 是 cart.cpp 维护的 32 项「PRG 页面基址」表。
  Page[2] = ptr - 0x8000 是个 trick：访问 Page[A>>11][A] 时得到 ptr[A]。

4. Mapper 4（MMC3，最重要）
================================================================================

  MMC3 是 1990 年代最流行的 mapper，几乎所有「佳作」级游戏都用了它：
  超级玛丽 3、魂斗罗 6、口袋妖怪、最终幻想 4/5/6（汉化版）等等。

  4.1 内存布局

  ┌──────────────┬──────────────────────────────────────────┐
  │ CPU 地址     │ 映射                                      │
  ├──────────────┼──────────────────────────────────────────┤
  │ $6000-$7FFF  │ WRAM（电池供电，可选）                    │
  │ $8000-$9FFF  │ 4 个可切换 PRG bank 之一（$8000 选择）    │
  │ $A000-$BFFF  │ 2 个可切换 PRG bank 之一                 │
  │ $C000-$DFFF  │ 固定为 PRG 倒数第二页                     │
  │ $E000-$FFFF  │ 固定为 PRG 最后一页（中断向量表）          │
  └──────────────┴──────────────────────────────────────────┘

  CHR bank 选择通过 PPU $0000-$1FFF 窗口（8 个 1 KiB 窗口 × 2 种模式）。

  4.2 寄存器协议

  CPU 写 $8000-$9FFF：

    A & 0xE001 == 0x8000 : 设置「bank select」（bit 0-2 = bank index, bit 6 = PRG mode, bit 7 = CHR mode）
    A & 0xE001 == 0x8001 : 设置「bank data」（写入 bank index 选中的寄存器）

  CPU 写 $A000-$BFFF：

    0xA000: PRG bank 0
    0xA001: PRG bank 1 (mirroring control)

  CPU 写 $C000-$DFFF：

    0xC000: IRQ latch
    0xC001: IRQ reload
    0xE000: IRQ disable
    0xE001: IRQ enable

  4.3 扫描线 IRQ（让 mapper 知道 PPU 在哪里）

  MMC3 的 IRQ 计数器靠 PPU CHR bank A13 翻转次数：
    每次 A13 0→1，IRQCount--。
    当 IRQCount == 0 时拉低 /IRQ。
    IRQCount = 0xFF 时从 IRQLatch 重新装载。
    游戏中常用 IRQ 实现"分屏"（不同区域用不同调色板或 bank）。

  4.4 FCEUX11 实现

  src/boards/mmc3.cpp：约 700 行
    FixMMC3PRG(int V)        - 根据 V 重新映射 PRG 窗口
    FixMMC3CHR(int V)        - 根据 V 重新映射 CHR 窗口
    MMC3_hb(IRQSource)       - PPU A13 翻转钩子
    MMC3_StateRegs[]         - 9 个状态字段的 SFORMAT 数组

5. Mapper 1（MMC1，塞尔达 / 银河战士 / 银河帝国）
================================================================================

  MMC1 用「串行移位寄存器」写入 5 位数据：
    每次 CPU 写 $8000-$FFFF，bit 7 进入 shift register，bit 0 = 1
    触发「apply」（5 位都收到）。
    bit 0 = 0 时只是 shift。
    第 5 次写时若 bit 0=1，shadow 寄存器值生效。

  MMC1 寄存器（5 位）：
    bit 0-3 : register data
    bit 4   : register select (0=control, 1=CHR bank 0, 2=CHR bank 1, 3=PRG bank)

  特点：
    - 镜像方式在「control」寄存器里设置
    - PRG 模式 bit (control.2) 决定 16K 还是 32K
    - CHR 模式 bit (control.4) 决定 4K+4K 还是 8K

================================================================================
6. Mapper 2（UxROM，魂斗罗 / 恶魔城）
================================================================================

  只有一个 bank 选择寄存器（$8000-$FFFF，写入低 4 位选 bank 16K）。
  $C000-$FFFF 固定为最后一页。
  $8000-$BFFF 切换 bank。

================================================================================
7. Mapper 3（CNROM，俄罗斯方块）
================================================================================

  没有 PRG bank。
  $8000-$FFFF 固定 32K PRG。
  $0000-$1FFF（PPU 视角）切换 8K CHR bank。
  写入 $8000-$FFFF 的低 4 位选 CHR bank 编号。

8. 扩展音频芯片：MMC5
================================================================================

  MMC5 是最强扩展芯片，自带 2 个扩展方波通道 + 1 个 PCM 通道 +
  8×8 硬件乘法器 + 扩展 VRAM。

  8.1 音频寄存器

  ┌──────────┬──────────────────────────────────────────┐
  │ $5000    │ Square 1 控制（占空比 4 级 + 包络 2 种）  │
  │ $5001    │ Square 1 扫频                              │
  │ $5002    │ Square 1 频率低 8 位                       │
  │ $5003    │ Square 1 频率高 3 位 + 长度 5 位           │
  │ $5004-$5007 │ 同上 for Square 2                      │
  │ $5010    │ 启用 PCM 通道                              │
  │ $5011    │ PCM 写 8-bit 样本                          │
  │ $5015    │ 通道使能                                  │
  └──────────┴──────────────────────────────────────────┘

  8.2 内存映射寄存器（强大但复杂）

  ┌──────────┬──────────────────────────────────────────┐
  │ $5100    │ PRG 模式 (0=32K, 1=16K, 2/3=8K)           │
  │ $5101    │ CHR 模式 (0=8K, 1=4K, 2=2K, 3=1K)         │
  │ $5102/$5103│ BBR-RAM 写保护（必须写 2/1 允许）       │
  │ $5104    │ 图形模式 (Split/ExGrafix/ExRAM)            │
  │ $5105    │ NameTable 来源（每 2 bit 选 1K 区域）     │
  │ $5113-$5117│ PRG bank 切换                            │
  │ $5120-$512B│ CHR bank 切换（Mode A/B）                │
  │ $5200    │ Split Mode 控制                           │
  │ $5203    │ Split 扫描线 IRQ 触发点                   │
  │ $5205/$5206│ 8×8 硬件乘法器（写入立即算 16-bit 结果）│
  └──────────┴──────────────────────────────────────────┘

  8.3 扩展 VRAM ($5C00-$5FBF)

    - ExGrafix 模式：每 tile 指定调色板（2 bit）+ 背景 CHR 页（6 bit）
    - Split 模式：作为扩展 name table
    - ExRAM 模式：作为普通扩展 RAM

  MMC5 是少数能"超过 NES 原始能力"的卡带之一，铸就了《Castlevania 3》
  《EarthBound》等高画质游戏。

================================================================================
9. 扩展音频：VRC6（Konami 早期 Famicom 专用）
================================================================================

  VRC6 = Konami 的扩展芯片，给《Gradius 2》《Salamander》等游戏用。
  比 MMC5 弱但更常见。

  音频部分：
    - 2 个 8-bit 占空比可调 Pulse 通道（$9000, $A000）
    - 1 个 5-bit 锯齿波通道（$B000）
    - 输出经 6-bit R2R DAC

  频率公式：
    Pulse：Fout = 1789772.7272 / ((freq+1) × 16)
    Sawtooth：Fout = 1789772.7272 / ((freq+1) × 14)

  注意：部分 VRC6 卡带 A0/A1 线接反，若音乐异常可尝试交换寄存器对
  （$9001 ↔ $9002）。FCEUX11 在 cart.cpp 检测这种接反并自动修正。

================================================================================
10. 扩展音频：VRC7（FM 合成）
================================================================================

  VRC7 = Konami 1987 年的 FM 合成芯片（YAMAHA OPL 风格）。

  6 个 FM 通道（每通道 4 算子，2 调制 + 1 载波 + 1 反馈）。

  寄存器：
    $9010  索引寄存器
    $9030  数据寄存器

  内部寄存器：
    $00-$07 : 自定义乐器参数（OPL2 风格）
    $10-$15 : 频率低 8 位
    $20-$25 : 频率高 2 位 + 触发 + 八度
    $30-$35 : 乐器号 + 音量

  频率公式：
          49722 × freqval
    F = ---------------------
        2^(19 - octave)

  VRC7 唯一的"商业发行"游戏是《Lagrange Point》（Famicom only）。

================================================================================
11. 怪卡带：SMB2j Mapper #50
================================================================================

  《超级玛丽 2 日本版》用了一个独特 mapper（ID 50）。
  硬件：6 个 TTL 芯片 + 8K VRAM + 128K PRG ROM。
  寄存器地址译码非常古怪（地址模式 010x xxxQ x01x xxxx）。

  FCEUX11 通过 smb2j.cpp 模拟。IRQ 计数器由 4020 纹波计数器实现，
  4096 个 M2 周期后拉低 /IRQ（约 36 扫描线）。用于顶部分数栏的屏幕分割。

12. mapper 怎么与 savestate 协作？
================================================================================

  每个 mapper 维护一个 SFORMAT 数组：

    static SFORMAT MMC3_StateRegs[] = {
        { DRegBuf,  8, "REGS" },
        { &MMC3_cmd, 1, "CMD" },
        { &A000B,   1, "A000" },
        { &A001B,   1, "A001" },
        { &IRQReload, 1, "IRQR" },
        { &IRQCount, 1, "IRQC" },
        { &IRQLatch, 1, "IRQL" },
        { &IRQa,     1, "IRQA" },
        { 0 }
    };

  序列化的关键：
    - 字段类型大小（uint8/uint16/uint32）
    - 字段名（4 字符短名，用于向后兼容）
    - 加新字段只能在末尾加，且不能改已有字段的大小

  详见 05 §Savestate 与 14 §FFI 冻结期。

14. 给 mapper 开发者的实践建议
================================================================================

  1. 先读 src/boards/mapinc.h 了解 SetReadHandler / SetWriteHandler / setprg
     / setchr / AddExState 的所有变体
  2. 找 2-3 个简单 mapper（NROM/UNROM/CNROM）作为参考
  3. 写 mapper 前先在 nesdev wiki 查寄存器协议（切记核对真机）
  4. 写完后必须写 SFORMAT 数组（即便字段看起来"已存在"）
  5. 加测试 ROM 到 src/tests/fixtures/ 并更新 golden_hashes.json
  6. 跑 ctest 全套确保没破坏 savestate 字节级一致性
