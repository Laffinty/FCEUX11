## 3. Design decisions

### 3.1 `SI_*` / `SIFC_*` / `FCEUIOD_*` kept as `inline constexpr int`

The pre-v0.3.8 codebase stores input-device IDs in `int` arrays
(`static int CurInputType[3] = {SI_GAMEPAD, …};` and 50+
`odirs[FCEUIOD_STATES]`-style array-index sites). Strongly typing the
legacy `SI_*` / `FCEUIOD_*` constants as `ESI` / `IoDir` (per the most
literal reading of plan §5) would have required either:
- ~30 per-site `(int)` casts at array-index / int-storage sites, or
- a wholesale rewrite of the int-storage layer to use the typed form.

The int-alias path used here keeps the legacy patterns compiling
verbatim. Type safety is preserved at the API boundary: the parameter
of `FCEUI_SetInput(int, ESI, …)` is the typed form, and `FCEUGI::input[2]`
/ `inputfc` storage keeps the typed form too, so the assignments from
ROM-detection code (`src/fceu.cpp`, `src/unif.cpp`, etc.) require
explicit `static_cast<ESI>(…)` — exactly where the type-check belongs.

### 3.2 `MapIRQHook` typedef without changing global linkage

The 35 mapper `.cpp` files in `src/boards/` assign to `MapIRQHook` as a
global symbol (`MapIRQHook = MxxIRQHook;`). Moving the symbol into
`fceu11::MapIRQHook` would have broken all 42 assignment sites. The
implemented design adds the type alias only — the symbol itself stays
at `::MapIRQHook` (global C linkage). A `static_assert` in `x6502.cpp`
guards against future drift between the definition's bare
`void(*)(int)` and the extern declaration's `fceu11::MapIRQHook` form.

### 3.3 `FCEU_ENUM_CLASS_BITFLAGS` is infrastructure, not consumed

None of the v0.3.8 conversion targets has OR-combination semantics:
- `InputDevice` / `InputDeviceFC` — single-selector enums
- `AllocKind` — single-value tag
- `IoDir` — array index
- `MapIRQHook` — function pointer

The bitflags macro is provided ahead of expected v0.3.13 / v0.3.14 /
v0.4.x consumers (input plugins, OpenGL render flags, mapper concepts).
`CpuFlag` ships as the macro's correctness witness and is unit-tested,
but it does NOT replace the `_P|=Z_FLAG` patterns in `src/x6502.cpp`
(~600 sites in the CPU dispatch macros) — mirroring plan §5 v0.3.8's
explicit PPU[0..2] exclusion.

### 3.4 `OldFceuApi = fceu11::v0_2_compat` deferred

Plan §6.1 phase-1: "only NEW symbols enter `fceu11::`; OLD symbols stay
global". In v0.3.8, every legacy alias is already at file scope (in the
header that defines the corresponding new enum class). The
`fceu11::v0_2_compat` sub-namespace becomes meaningful only when the
mass `FCEUI_*` rename starts in v0.3.10 — that is when global aliases
get phased out and the sub-namespace becomes the migration path.
Landing the empty sub-namespace in v0.3.8 would be speculative
scaffolding.

## 4. Five-gate verification plan

Gate execution is the responsibility of the v0.3.8 commit author and CI;
the design intent is captured here.

| Gate | Method | Expected outcome |
|------|--------|------------------|
| 1 — compile | `cmake --build build --config Release` (MSVC 19.36) | 0 errors; warning count ≤ v0.3.7 baseline |
| 2 — unit | `ctest --output-on-failure` incl. `enum_class_bitflags_test` + `cargo test --manifest-path src/rust/Cargo.toml` | All pass |
| 3 — byte-level | `tests/rom_regression_test` 5 ROMs (NROM/MMC1/MMC3/AxROM/UxROM) 60 frames | SHA-256 matches `tests/fixtures/golden_hashes.json` v0.3.0 baseline |
| 4 — smoke | Launch + load `nestest.nes` + run 60 frames | No crash; $C66E status register matches v0.2.30 |
| 5 — perf regression | `tests/benchmark/{ppu_render,x6502_exec,apu_mix}_bench` | PPU render < 1.1× baseline; CPU exec < 0.95× baseline |

Additional sanity check: `grep -rE "\b(ESI|ESIFC|SI_|SIFC_|FCEUIOD_|FCEU_ALLOC_TYPE_|fceuAllocType)\b" src/ tests/ | wc -l` should be ≥ 200 — confirms zero legacy-name deletions.

## 5. Risk register (final)

| Risk | Mitigation outcome |
|------|--------------------|
| `FCEUGI` shrinks ~5 bytes (`int8_t` underlying) | Not in any SFORMAT serialization; no Lua reflection assumes `sizeof(FCEUGI)`; verified by absence of relevant in-tree references. |
| Qt 6 `QVariant` rejects `enum class` | 17 `addItem` sites in `InputConf.cpp` gain `(int)` casts; verified no further `QVariant::fromValue<ESI>()` sites exist. |
| `ESI_Name` / `ESIFC_Name` lose implicit `names[esi]` | Replaced with explicit `static_cast<int>(esi)` and a `>= 0` guard against the `Unset` sentinel. |
| `MapIRQHook` type drift across 35 mapper files | `static_assert(std::is_same_v<…>)` in `x6502.cpp:38` enforces compile-time identity. |
| Plan `: u8` vs `-1` sentinel | Resolved with `: int8_t`; documented in commit message + CHANGELOG. |
| `OldFceuApi` shim absent in v0.3.8 | Deferred to v0.3.10 with commit-message annotation; v0.3.8 uses file-scope `using` / `inline constexpr` aliases instead. |
| Rust FFI drift | Zero — `ines_data.rs` continues to expose IDs as `int32_t` and the cast site in `ines.cpp` remains valid. |

## 6. Next-version starting conditions

- v0.3.9 (driver.h physical split) inherits: `fceu11::` namespace
  established for `InputDevice` / `InputDeviceFC` / `AllocKind` / `IoDir`
  / `MapIRQHook` / `CpuFlag`. The `core_api.h` / `io_api.h` / `net_api.h`
  / `diag_api.h` split can now reference these typed forms without
  touching the legacy `ESI` / `SI_*` token stream.
- v0.3.10 (`FCEUI_*` mass rename) will materialise the
  `fceu11::v0_2_compat::` sub-namespace and start phasing the global
  aliases through `[[deprecated]]` markers — same pattern as the
  `fceuScopedPtr` deprecation from v0.3.6.
