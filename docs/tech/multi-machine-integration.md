# 把第二台模拟机接进既有前端

> 面向的读者：要在 FCEUX11 里加一种**新机器**（GBA 是第一个，也不会是最后一个），
> 或者接手 GBA 模块的人。写的不是「我们做了什么」，是**下次接第二台时应该怎么做才
> 不会重蹈这四个覆辙**。
> 证据出处：v2.0 计划 §十四 r41（解耦裁决）、r44（三个驱动）、r49/r50（两个 P0）。

---

## 一、问题形态

一个模拟器前端假设了很多关于「机器」的事：画面从哪来、声音往哪送、手柄状态在
哪、存档文件怎么命名。NES 与 GBA 在这五处**全部不同**。

 naïve 的接法是在每个差异点插一个 `if (is_gba)`。三个月后，前端里会有 40 个这样的
分支，每一个都要在「NES 行为不能变」的前提下单独推理，而没有任何机制保证它们
是对的 —— 这正是 GBAEUX11 走过的路。

## 二、允许耦合的清单，以及为什么它必须是清单

FCEUX11 把耦合收敛到**五个穷举位置**（计划 §十 不变式 9）：

1. 同一进程 / 模拟线程 / 窗口 / 声卡
2. 每帧循环里的**那一个**分支
3. `WriteSound` 写入接口（环按**设备**尺寸配，不按机器配）
4. 限速的基准帧率取值
5. 打开 ROM 对话框的过滤器条目

**这份清单的价值不在「允许了什么」，而在「没列的地方一律不许碰」。**
清单是封闭的：新增触碰点要先进清单，与代码同一个提交。没有清单的话，
「尽量少耦合」是句口号，评审时无从判断。

代价是清单会漏。GBA 就漏了两次，两次都是致命的：

| 漏掉的位置 | 后果 |
|---|---|
| 三个视频驱动里只改了一个 | OpenGL 驱动下 GBA 永久黑屏（r50） |
| `GamePad[0].bmap` 绑定的**形态**（键盘键 vs 摇杆轴） | 方向键永远是「未按下」（S4） |

## 三、守卫的两种形态，以及为什么必须都有

守住耦合边界需要两类检查，缺一不可：

### 3.1 白名单：抓「已存在」

> 任何提到 GBA 的 C/C++ 文件都必须在显式清单内登记。

它防的是**蔓延**：新文件引用 GBA 符号时被迫做一次显式决策。

**它对「缺失」完全无效。** 没有 GBA 分支的文件不提到 GBA，于是白名单根本不会
看它一眼。r50 就是这样通过的 —— 所有守卫全绿，而有两个驱动根本没画 GBA。

### 3.2 固定清单：抓「缺失」

> 这些文件**必须**引用 GBA。

对着写死的文件列表断言，而不是从代码里推导。r50 补上这条时，第一次实现是错的：
只检查「文件里有没有 gba 字样」，于是 `if (false && fceu11_gba_active())` 照样通过
（函数还在文件里）。改成检查**绘制函数体内**，仍因函数边界判定有 bug 而漏判
（扫描到文件末尾，把后面函数里的字样算了进来）。最终用括号配对界定函数体才转红。

**教训：一个只能抓「已存在」的守卫，和没有守卫的区别只在于它给了你安全感。**
接第二台机器时，先问「这个守卫抓不到什么」，再决定要不要加。

### 3.3 守卫的已知边界

`every_viewer_draws_the_gba` 抓得住「分支被删」，抓不住「分支在但不可达」
（文本匹配看不到可达性）。判可达性需要真解析器。**把边界写进注释，不要假装
守卫覆盖了它没有覆盖的东西。**

## 四、三个驱动的教训：同一个决定只能有一份

r50 之前，GBA 的画面逻辑只在 `ConsoleViewerSDL` 里，另外两个驱动完全没有。
r50 补齐时又发现，缩放上限 `if (scale > 1.0f)` 在三个文件里各写了一份。

**同一份决策写三遍，等于承诺三处永远一致，且没有任何机制保证。** 于是把
「GBA 帧在视口里画多大」收成一个函数（`fceu11_gba_draw_size`），三个驱动都调它。
这不是 DRY 洁癖，是 r50 教训的直接应用。

判断标准：**当第三个副本出现时，抽函数；不要等第四次。**

## 五、输入：一个共享状态不等于一个可读的状态

GBA 读手柄时踩了三层坑，每层都只有实测能发现：

1. `joy[]` 是 NES 侧的值，由 NES 核心写。GBA 会话下 NES 不跑 ⇒ 恒 0。
2. 改成直接读绑定表仍全 0 —— **方向键默认绑在摇杆轴上**，
   `ButtonNum` 存的是 `0x8000 | axisSign<<14 | axisIdx`，不是 SDL 键码。
   把轴标志当键码传给 `getKeyState()`，越界返回 0。
3. NES 与 GBA 的方向键**顺序不同**（NES: 上/下/左/右；GBA: 右/左/上/下）。
   按位置硬映射会做出一个「每个键都有反应、但方向是错的」摇杆。

**通用规则：接新机器时，跨系统的状态一律经由该系统自己的查询接口读，不要直接
读对方的内部变量。** NES 侧读手柄走的是 `DTestButton()`（它认得轴绑定），
GBA 侧现在走同一个函数。

**位序不同的两张表要显式写出来，不要靠位置对应。** 「按索引顺序映射」在两边
顺序恰好相同时是安全的 —— 而「恰好」是最危险的状态，因为它不会报错。

## 六、跨线程纪律

模拟线程读、GUI 线程写的值，和 `joy[]`、`g_keyState` 是同一档纪律：读一个
被别处写的表。**新增这样的读取时，把它和既有的同类读取放在一起说明**，
不要让它看起来像是个安全的局部状态。

跨 FFI 的例外：`gba` 模块在**核心库**里，`Qt/input.h` 不能被它包含
（该头在 `FAMILYKEYBOARD_NUM_BUTTONS` 被定义之前就使用它）。所以键盘相关的读取
必须留在 Qt 层，由它把状态推入。**这条约束会反复出现，任何时候想「就加一行
include」都会撞到。**
