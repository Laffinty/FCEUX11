2. v0.3.10 API 收敛深度解读
================================================================================

  v0.3.10 是 C-track 的"闭幕"工作，集中处理三件事：
    1. FCEUI_* 公共 API 符号从 1,118 → < 600
    2. EMUFILE::fread/fwrite 改用 std::span<std::byte>
    3. EMUFILE_MEMORY 内部 std::vector<u8> → std::vector<std::byte>

  2.1 目标（Goals）

    1. 减少 in-tree FCEUI_* 公共 API 符号从 ~1,118 到 < 600
    2. 现代化 EMUFILE::fread/fwrite 到 std::span<std::byte>
    3. 迁移 EMUFILE_MEMORY 内部存储到 std::vector<std::byte>
    4. 保持 Rust fceux11-formats::EmuFile FFI 边界同步
    5. 100% 字节级 savestate 兼容

  2.2 非目标（Non-Goals）

    - 不删兼容 shim（legacy using aliases 留到 v0.4.0）
    - 不加新 FFI 函数（Rust crate 保持 0.2.x）
    - 不动 emulator 热路径算法
    - 不改 mapper 行为、PPU/CPU/APU 时序、savestate 格式

  2.3 硬约束

  | # | 约束                          | 验证方法                              |
  |---|-------------------------------|---------------------------------------|
  | 1 | 字节级 savestate 一致         | 5-ROM 60-frame SHA-256 vs golden       |
  | 2 | MSVC-only 工具链              | CMakeLists.txt FATAL_ERROR            |
  | 3 | C++20, 无 C++23               | CMAKE_CXX_STANDARD 20                  |
  | 4 | 兼容 shim 保留                | global using/inline constexpr aliases |
  | 5 | Rust crate 源不动             | cargo test --workspace + fceux11_rust.h|

  2.4 阶段划分（P0-P7）

    P0  基线冻结（topic 分支、5 gates 全过）
    P1  度量与脚本基础设施
    P2  EMUFILE 核心现代化（高风险）
    P3  EMUFILE 调用方迁移（6 个拓扑批）
    P4  FCEUI_* namespace 收敛（4 波）
    P5  Rust 侧同步 + FFI 边界检查
    P6  全量回归
    P7  文档与合并

  2.5 实际成果

  FCEUI_* raw  : 1118 → 594  （命中 < 600 目标）
  FCEUI_* text : 993  → 452
  EMUFILE 调用方文件：30+ 已迁移
  新 EMUFILE 虚函数：2（fread span, fwrite span）
  兼容 shim 保留：2（带 [[deprecated]]）
  新 fceu11:: 符号：~250 跨多个新头

3. v0.3.14 GUI 启动崩溃 + 键盘双路径
================================================================================

  v0.3.14 修复两个 GUI 启动问题：

  3.1 启动崩溃

  QOpenGLWindow::paintGL() 第一次进入时 OpenGL 上下文没 makeCurrent，
  直接调 glTexSubImage2D → segfault。修复：把 GL 初始化移到
  initializeGL()（Qt 保证上下文已激活）。

  3.2 键盘失效

  WM_INPUT 事件被 Qt 消息循环吞掉。修复：
    - 0ms QTimer 在 UI 线程调 SDL_PumpEvents()
    - QOpenGLWindow override keyPressEvent/keyReleaseEvent → pushKeyEvent

  详见 15 章 §案例 A / B。

4. FFI 冻结期与 RFC 流程
================================================================================

  从 v0.2.30 起，fceux11_rust.h 签名为 FFI 契约。

  4.1 修改签名需走 RFC

    1. 在 docs/tech/ 提交 RFC（txt 格式）
    2. 说明理由、影响范围、回退方案
    3. 至少一次代码审查
    4. 同步更新所有 C++ 调用方

  4.2 哪些改动需要 RFC

    - 改 #[repr(C)] struct 字段顺序
    - 改 #[unsafe(no_mangle)] extern "C" 函数签名
    - 改 enum class 的值编号（破坏 ABI）
    - 改 FFI 头里 const/指针的属性

  4.3 哪些改动不需要 RFC

    - 加新函数（追加不破坏现有）
    - 加新 enum 值（追加不破坏现有，前提是旧值不变）
    - 加新 struct（独立 #[repr(C)] 不影响现有）

5. Plan v3 的 5 道门控
================================================================================

  Plan v3 §7 规定任何 release 前必过 5 道门：

  1. 编译门控     cmake --build build，0 errors，无新增 warnings
  2. 单元门控     ctest + cargo test --workspace 全绿
  3. 字节级门控   5-ROM savestate SHA-256 与 golden_hashes.json 一致
  4. 冒烟门控     fceux11.exe --help 退 0；nestest.nes 60 帧 OK
  5. 性能门控     PPU/x6502/APU benchmark 在阈值内

  任何一道失败 → 拒绝合并或拒绝发布。

  详见 12 / 13 章。

6. RFC 模板
================================================================================

  写 RFC 时使用以下结构（docs/tech/ 目录下）：

    ====================================================================
    RFC: <简短标题>
    Author: <作者>
    Date: <日期>
    Status: Draft / Accepted / Rejected / Implemented
    Target version: v0.X.Y
    ====================================================================

    1. 摘要
    2. 动机（为什么改）
    3. 提案（改什么）
    4. 影响范围（哪些调用方/crate/测试要同步）
    5. 回退方案（如何撤销）
    6. 替代方案
    7. 待决问题
    8. 实施时间表
    9. 风险评估

  完成后 merge 到 main，PR 链接附在 RFC 文件头。

7. v0.3.7 enum class 化深度
================================================================================

  v0.3.7 启动类型系统重构。v0.3.8 落地：

  | 旧名          | 新名                       | 备注                           |
  |---------------|----------------------------|--------------------------------|
  | ESI / ESIFC   | fceu11::InputDevice / FC   | (:int8_t, -1 sentinel)         |
  | fceuAllocType | fceu11::AllocKind         |                                |
  | FCEUIOD_*     | fceu11::IoDir             |                                |
  | MapIRQHook    | typedef in fceu11_core_types.h | static_assert 防止 drift  |

  SI_*/SIFC_*/FCEUIOD_* 旧名作为 inline constexpr int 保留兼容。
  FCEU_ENUM_CLASS_BITFLAGS 宏让 enum class 也能做位运算。

  详见 14 章附录 / 09 章。

9. v0.4.x 计划
================================================================================

  9.1 B-track 目标

    1. emulator 核心循环重构（Cpu/Ppu/Apu/Mapper trait 抽象）
    2. APU 音质提升（重写混音器、用更精确的 envelope/linear counter）
    3. OpenGL 后端重写（VBO 优化、shader 升级、10-bit 输出）
    4. 完整 clang-style UBSan + LSan（v0.4.x 工具链 workstream）
    5. 多线程 mapper 调度（实验）

  9.2 风险

    - 重构 emulator loop 风险极高，需要 720 帧 ROM 回归 + savestate 字节级
    - APU 音质改动可能让老 .fm2 录像不兼容
    - OpenGL 升级到 4.x 可能影响老显卡兼容
