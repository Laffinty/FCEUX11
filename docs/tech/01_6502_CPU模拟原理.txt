【写在前面 / Preface】
================================================================================

  NES 的 CPU 是 Ricoh 2A03，本质是 MOS 6502 加一个内置 APU。所以搞懂
  6502 等于搞懂 NES CPU 的一半。FCEUX11 的 6502 实现位于
  src/x6502.cpp + src/ops_table.inc，是「教学级」质量：cycle accurate、
  56 个官方指令全部覆盖、B 标志完整模拟、BCD 模式正确。

  本章目标：
    1. 让你理解 6502 寄存器、寻址方式、状态标志
    2. 解释 FCEUX11 的「主循环」x6502_run / FCEUI_FrameBoundary 怎么走
    3. 给出真实指令的 cycle 表来源与如何查表
    4. 帮你写一个最简单的指令解释器作为练习

  阅读时间：约 30 分钟。
  前置知识：了解任何一种汇编（x86 / ARM 均可）；懂 C。

================================================================================
1. 6502 寄存器：6 个寄存器 + 状态字 P
================================================================================

  6502 寄存器极少，模拟器用一个 struct 就能装下：

    struct X6502 {
        uint16_t PC;       // Program Counter（16 位）
        uint8_t  A;        // Accumulator
        uint8_t  X;        // Index X
        uint8_t  Y;        // Index Y
        uint8_t  S;        // Stack Pointer（页 1，相对地址 $0100+$S）
        uint8_t  P;        // Processor Status：NV-BDIZC 8 位
        int32_t  count;    // 剩余 cycle 数（CPU 调度用）
        union {
            uint16_t quick;
            struct { uint8_t l, h; } byte;  // PCL/PCH
        } PC; // 注意：FCEUX11 实际是分开的 PCL/PCH，但合并读更高效
        // ...
    };

  全局只有一个 X6502 X 变量（FCEUX11 故意保留单实例；想多实例见 09 §v0.3.x 计划）。
  注意 alignas(64) 保证它不与 mapper 寄存器组共占 cache line，避免 false sharing。

================================================================================
2. 状态字 P：8 位，每一位都有名字
================================================================================

   bit 7   6   5   4   3   2   1   0
       N   V       B   D   I   Z   C
       │   │       │   │   │   │   └─ Carry
       │   │       │   │   │   └───── Zero
       │   │       │   │   └───────── IRQ Disable (1 = 关中断)
       │   │       │   └───────────── Decimal (BCD 模式)
       │   │       └───────────────── Break (BRK 指令压栈时设 1)
       │   └───────────────────────── Overflow
       └───────────────────────────── Negative

  关键陷阱：
    - B 标志只有 BRK 指令执行时设 1；中断进入时设 0。软件靠这个判断
      「我是被 BRK 进来的还是被 IRQ 进来的」。
    - I 标志是 1 时 NMI 仍能进，但 IRQ 屏蔽。复位后 I=1。
    - D 标志位 ADC/SBC 走 BCD，但 NES 的 2A03 已禁用 BCD（DEC 行为错误），
      FCEUX11 模拟这一行为：默认 D 写入无效。

================================================================================
3. 13 种寻址方式（6502 寻址的精华）
================================================================================

  6502 只有 13 种寻址，比 x86 简单得多：

  ┌──────────┬────────────────────────────────┬────────────────────────────┐
  │ 模式      │ 语法示例                       │ 寻址过程                    │
  ├──────────┼────────────────────────────────┼────────────────────────────┤
  │ Implicit │ CLC, RTS, NOP                  │ 无需操作数                  │
  │ Accum    │ ASL A                           │ 操作数是 A                  │
  │ Immediate│ LDA #\$10                       │ 紧跟 opcode 的字节          │
  │ ZeroPage │ LDA \$10                        │ 1 字节地址 $0000-$00FF     │
  │ ZeroPage,X│ LDA \$10,X                      │ ($10 + X) & $FF           │
  │ Absolute │ LDA \$1234                      │ 2 字节地址                 │
  │ Absolute,X│ LDA \$1234,X                    │ $1234 + X                  │
  │ Absolute,Y│ LDA \$1234,Y                    │ $1234 + Y                  │
  │ (Indirect,X)│ LDA (\$10,X)                  │ ($10+X) & $FF → ptr        │
  │ (Indirect),Y│ LDA (\$10),Y                  │ ($10) → ptr, ptr+Y        │
  │ Relative │ BEQ \$10                        │ 相对 PC 的有符号偏移        │
  │ Indirect │ JMP (\$1234)                    │ $1234 读出 16 位地址跳转     │
  │ (Indirect)│ JMP (\$1234) bug: 跨页高字节  │ 6502 JMP 间接 bug：若 ptr 在 │
  │          │                                │ $xxFF，下一字节从 $xx00 取   │
  └──────────┴────────────────────────────────┴────────────────────────────┘

  最容易出错的是 (Indirect,X) 与 (Indirect),Y：
    LDA ($10,X)  寻址路径：先取 ($10 + X) & $FF 这 1 字节为 zp 地址 z；
                        再读 z, z+1 拼成 16 位地址
    LDA ($10),Y  寻址路径：先取 ($10), ($10+1) 拼成 16 位基址；
                        再加 Y

4. 调度循环：cycle-accurate 是怎么做到的？
================================================================================

  FCEUX11 的 CPU 主循环逻辑大致是：

    void FCEUI_FrameBoundary(...) {
        timestamp = 0;
        while (timestamp < total) {        // total = 每帧 PPU 周期数
            X6502_Run();                    // 跑 1 条指令
            // 期间会更新 timestamp；超过 PPU 边界就停
        }
        // 跑 APU、PPU 一帧
    }

  X6502_Run 内部：

    void X6502_Run() {
        while (X.count > 0) {
            uint8 op = RdMem(X.PC++);
            // 取指
            int extra_cycle = ops_table[op](&X);  // 派发指令
            // 指令返回额外 cycle（跨页 / 分支成功）
            ADDCYC(extra_cycle);
            // 把指令消耗的周期加到 timestamp、子系统等
        }
    }

  ops_table[op] 是 256 项的函数指针表（std::array<void(*)(X6502*)>）。
  FCEUX11 在 src/ops_table.inc 用宏展开的方式声明这 256 个 stub：

    static void op_LDA_IMM(X6502 *X) { X->A = RdMem(X->PC++); /* ... */ }
    // ...
    ops_table[0xA9] = op_LDA_IMM;

  编译期 MSVC 优化后会变成跳转表，每条指令的派发 < 5ns。

================================================================================
5. Cycle 表 CycTable[256]
================================================================================

  任何指令都消耗「基本 cycle + 跨页额外 + 分支成功额外」。
  CycTable[op] 存的是基本 cycle。例如：

    LDA #imm      : 2 cycles
    LDA zp        : 3 cycles
    LDA abs       : 4 cycles
    LDA abs,X     : 4 + (跨页?1:0)
    STA abs,X     : 5 cycles
    JMP abs       : 3 cycles
    JSR abs       : 6 cycles
    RTS           : 6 cycles
    BEQ rel (taken)  : 2 + 1（分支成功）+ 1（跨页?）
    BEQ rel (not taken) : 2 cycles

  FCEUX11 用 4 张表（CycTable、opsize、optype、opwrite）来描述指令：
    CycTable[op]  - 基本 cycle
    opsize[op]    - 指令长度（1/2/3 字节）
    optype[op]    - 寻址方式分类（用于调试器显示）
    opwrite[op]   - 是否会写内存（影响 read-only 工具的判定）

6. 中断：NMI / IRQ / BRK
================================================================================

  NES 中有 3 种「软/硬」进入 CPU 的路径：

  ┌────────┬────────────────────────────────┬────────────────────┐
  │ 类型    │ 触发源                          │ 行为               │
  ├────────┼────────────────────────────────┼────────────────────┤
  │ RESET  │ 电源 / 复位按钮                 │ 读 $FFFC/$FFFD → PC│
  │ NMI    │ PPU 每帧开始（VBlank）          │ 读 $FFFA/$FFFB → PC│
  │ IRQ    │ mapper 拉低 /IRQ（如 MMC3）     │ 若 I=0 则读 $FFFE  │
  │ BRK    │ 软件触发（BRK 指令）            │ 同 IRQ 但 B=1     │
  └────────┴────────────────────────────────┴────────────────────┘

  中断压栈的内容：PCH, PCL, P (B=1 for BRK, B=0 for IRQ) 然后 JMP 到向量。
  FCEUX11 的 MapIRQHook 是 mapper 调用 CPU 触发 IRQ 的入口（v0.3.8 用
  enum-class 的 fceu11::MapIRQHook 类型防止 typedef 漂移）。

================================================================================
7. NES 特定行为：2A03 vs 标准 6502 的差异
================================================================================

  Ricoh 2A03 是 6502 的「减配版」：
    - BCD 模式（ADC/SBC 的 D 标志）禁用 → FCEUX11 模拟这一行为
    - 没有官方 6502 的 STP / WAI（无所谓，FCEUX11 也不实现）
    - 把 5 个声音寄存器嵌入到 CPU 地址空间 $4000-$4017
    - 增加了 $4015（通道状态）和 $4017（帧计数器）

  这意味着 FCEUX11 模拟 CPU 时，对 $4000-$401F 范围的读/写会「旁路」到
  APU 代码——而 APU 寄存器写往往还会触发 IRQ 清零等副作用。

8. 一段示例：写一个最简单的「LDA #imm」模拟
================================================================================

  假设你想给 x6502.cpp 加一个新指令（教学用），至少要做四件事：

  // 1. 在 ops_table.inc 注册
  static void op_MYINS_IMM(X6502 *X) {
      uint8 v = RdMem(X->PC++);
      X->A = v;
      ZF = (v == 0);
      NF = (v & 0x80) != 0;
  }
  // 在表里： ops_table[0xXX] = op_MYINS_IMM;

  // 2. 在 CycTable 加周期
  CycTable[0xXX] = 2;

  // 3. 在 opsize 加长度
  opsize[0xXX] = 2;

  // 4. 在 optype / opwrite 标注属性
  optype[0xXX] = IMM;
  opwrite[0xXX] = 0;  // 不写内存

  5. 写单测
  void test_lda_imm() {
      X6502 X = {};
      X.PC = 0x1000;
      WRAM[0x1001] = 0x42;
      op_LDA_IMM(&X);
      assert(X.A == 0x42);
      assert((X.P & ZF) == 0);   // ZF=0
      assert((X.P & NF) == 0);   // NF=0
  }
