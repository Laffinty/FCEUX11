FCEUX11 v0.3.10 API Convergence Reference
==========================================

Sub-version : v0.3.10
Track       : C-track (API modernisation)
Positioning : Closing sub-version of the C-track. Builds on the
type-system refactors of v0.3.7/8/9 and opens the door to the
performance workstream starting at v0.3.11.
Plan source : docs/v0.3.x_Construction_Plan_v3.md §5 v0.3.10
Status      : Completed (P0-P7)

This document archives the systematic engineering knowledge from the
v0.3.10 construction cycle. The day-to-day change log is in
CHANGELOG.md [0.3.10]; this file preserves the plan structure,
constraints, risk register, conversion templates, and verification
gates so future agents can reproduce or extend the work.


1. Goals
--------

1. Reduce in-tree `FCEUI_*` public-API symbol occurrences from
   ~1,118 to < 600.
2. Modernise `EMUFILE::fread` / `EMUFILE::fwrite` from raw pointer
   interfaces to `std::span<std::byte>` / `std::span<const std::byte>`.
3. Migrate `EMUFILE_MEMORY` internal storage from `std::vector<u8>`
   to `std::vector<std::byte>`.
4. Keep the Rust `fceux11-formats::EmuFile` FFI boundary in sync by
   changing only the C++ wrapper layer, not the Rust crate source.
5. Preserve 100% byte-level savestate compatibility: the 5-ROM
   savestate SHA-256 hashes must remain identical to the v0.3.0
   baseline.


2. Non-goals
------------

- No compatibility shim is removed; legacy global `using` aliases
  stay until v0.4.0.
- No new FFI functions are added; Rust crate versions stay at 0.2.x.
- No emulator hot-path algorithm is changed (v0.3.10 is API-shape
  modernisation, not performance optimisation).
- No mapper behaviour, PPU/CPU/APU timing, or savestate file format
  is changed.

9. EMUFILE caller conversion templates
--------------------------------------

Before:
    uint8_t buf[16];
    size_t n = emuf->fread(buf, 16);
After:
    std::array<std::byte, 16> buf{};
    size_t n = emuf->fread(buf);

Before:
    std::vector<u8> data;
    data.resize(len);
    emuf->fread(data.data(), data.size());
After:
    std::vector<std::byte> data;
    data.resize(len);
    emuf->fread(data);

Before:
    emuf->fwrite(ptr, size);
After:
    emuf->fwrite(std::span<const std::byte>(
        reinterpret_cast<const std::byte*>(ptr), size));


10. std::byte <-> uint8_t boundary rules
----------------------------------------

uint8_t -> std::byte:
    auto b = std::byte{val};

std::byte -> uint8_t:
    auto u = std::to_integer<uint8_t>(b);

C API interaction:
    some_c_api(reinterpret_cast<const uint8_t*>(span.data()),
               span.size());

Compatibility shim (retained, marked deprecated):
    class EMUFILE {
    public:
        virtual size_t fread(std::span<std::byte> dst) = 0;
        virtual size_t fwrite(std::span<const std::byte> src) = 0;

        [[deprecated("use std::span overload")]]
        size_t fread(void* ptr, size_t size) {
            return fread(std::span<std::byte>(
                static_cast<std::byte*>(ptr), size));
        }
        [[deprecated("use std::span overload")]]
        size_t fwrite(const void* ptr, size_t size) {
            return fwrite(std::span<const std::byte>(
                static_cast<const std::byte*>(ptr), size));
        }
    };

The canonical boundary rules are the single source of truth in
docs/tech/v0.3.10_byte_conversion_rules.md.

14. Key deviations from the literal plan text
---------------------------------------------

- Phase shape: P0 -> P1 -> P2 -> P3.1-P3.6 -> P4 -> P5 -> P6 -> P7.
  This document (and the v0.3.10 sub-plan it archives) is the
  authoritative fine-grained breakdown.

- The mechanical-rename helpers scripts/_p4_migrate_*.py were kept in
  scripts/ as repeatable tools rather than deleted. They can be re-run
  for later convergence passes (e.g. v0.4.0 shim removal).

- `_check_byte_usage.py` reported 11 HIGH findings at P6. These are
  the documented boundary conversions in
  v0.3.10_byte_conversion_rules.md §7.2 and are required, not
  regressions.

- Performance gate 5: the benchmark scripts print `RESULT: PASSED`
  unconditionally. v0.3.10 measured PPU 0.735 ms/frame, x6502
  0.842 ms/frame, APU 0.704 ms/frame on a 60-frame run, within the
  plan budget window. A hard budget assertion is a future
  integration-checkpoint item if needed.

- ASan on Windows has no LeakSanitizer; only UAF / bounds / stack-
  buffer-overflow checks are active. This is the documented
  v0.3.6.5 behaviour, not a v0.3.10 regression.

- fceux11-lua gained a new `ffi-stubs` Cargo feature to let
  `cargo test --workspace` link without duplicate symbols in the
  CMake Release build. No new C-exported symbols were added to
  fceux11_rust.h.
