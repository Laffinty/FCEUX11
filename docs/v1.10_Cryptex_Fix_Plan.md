## 0. 背景与事故定性

前一 AGENT 的 v1.10 构建质量不合格，代码混乱；维护者已执行回滚至 `b1077dd`，并删除其引入的 `.mimocode/plans/1782900353759-clever-engine.md` 噪声文件（现 HEAD `a19c4f6`）。回滚未重写文档，故 CHANGELOG / Roadmap 与代码不同步。

回滚后的真实状态：`version.h` 已是 `1.10.0`（由 `b16d6a4` bump，回滚点 `b1077dd` 在其后故保留），但**仅完成 iNES 头部解析 / hash / 修正 / MasterInfo 查询的 Rust 迁移**（`ines.cpp` 中约 12 处 `fceux11_rust_ines_*` 调用）；UNIF/NSF/FDS/VSUni 全为 v1.9 原貌。

被废弃的 `fc8f7e8` 是单 squash commit，整体迁移但存在可量化缺陷（见 §3）。本计划按维护者决策**整体采纳 `fc8f7e8` 后逐项修补**，目标是达到可发布质量。

### 0.1 关键事实核对

- `git log --graph` 证实 `fc8f7e8` 与 HEAD 在 `b1077dd` 处分叉：HEAD 是 `b1077dd` 的子（删除噪声 md），`fc8f7e8` 也是 `b1077dd` 的子（迁移 squash）。两者为兄弟。
- `fc8f7e8` 的 delta（vs 其父 `b1077dd`）**不触碰** `.mimocode` 噪声 md（已核对 `git show fc8f7e8 --stat`）。故 cherry-pick 不会重新引入噪声。
- `v1.10` tag 未推送到 origin（`git ls-remote --tags origin` 无 v1.10）。
- Build Plan §0.1 的行数（913/613/528/789）已过时失真；以 §1 实测为准。

### Task 1 — unif.cpp 收敛至 <100 行

**现状**：`unif.cpp` 150 行，loader 已走 `fceux11_rust_unif_load`，残留约 50 行 board 表/PRG-CHR 映射胶水。

**做法**：
- 将 board 名称→mapper 查找表与 PRG/CHR 映射 setup 胶水移入 `src/unif_bmap.h`（header-only inline）或下沉到 Rust `unif.rs`
- C++ 仅保留：`UNIFLoad`（调 Rust FFI）+ `UNIFGI` 生命周期 + `AddExState` 注册

**门禁**：`(Get-Content src/unif.cpp).Count` < 100；UNIF ROM 加载不退化；`ctest` 不低于 N₀。

---

### Task 2 — nsf.cpp runtime handlers 迁移至 Rust（≤150 行）

**现状**：`nsf.cpp` 548 行，仅 `NSFLoad` 迁移；`NSF_read`/`NSF_write`/`NSFROMRead`/`NSFVectorRead` 仍在 C++。

**做法**：
- 在 `fceux11-formats::nsf` 新增 runtime 状态机：`NsfRuntimeState` + `nsf_read(addr)` / `nsf_write(addr,val)` / `nsf_init()` / `nsf_frame()`（bank 切换、NSFROM patch 应用、向量读取）
- 新增 FFI：`fceux11_rust_nsf_read` / `fceux11_rust_nsf_write` / `fceux11_rust_nsf_init` / `fceux11_rust_nsf_frame`
- C++ `NSF_read` 等改为薄 forwarder → Rust
- C++ 仅保留：`NSFLoad`（FFI）+ `DrawNSF`（UI）+ `AddExState` + 生命周期

**门禁**：
- `(Get-Content src/nsf.cpp).Count` ≤ 150
- 新增 `cargo test` 单元测试覆盖 bank 切换 / NSFROM patch 字节级对比
- NSF ROM 加载 + 播放 N 帧 WAV 输出与 v1.9 采样级一致（复用 `apu_wav_diff_test` 模式）
- `ctest` 不低于 N₀

---

### Task 3 — fds.cpp disk/BIOS/side 迁移至 Rust（≤320 行）

**现状**：`fds.cpp` 905 行，仅 `disk_read`/`disk_write`/`switch_side` FFI 存在；`FDSRead4031`/`FDSWrite` 函数体仍在 C++；BIOS 映射、侧切换逻辑未迁移。这是 D12（声明与实现不符）的核心。

**做法**：
- `fceux11-formats::fds` 扩展：完整 disk 数据读写路径、BIOS ROM（$E000-$FFFF）映射、侧切换 FSM
- `FDSRead4031`（磁盘数据读取）与 `FDSWrite`（磁盘数据写入）的核心字节路径下沉 Rust；C++ 仅保留寄存器实时分发
- BIOS 映射、`FCEU_FDSInsert` 侧切换逻辑下沉 Rust（C++ UI 钩子转发）
- C++ 仅保留：`FDSLoad`/`FDSInit`/`FDSClose` 生命周期（调 FFI）+ `FCEU_FDSInsert`/`FCEU_FDSSelect` UI + `FDSSound`（v1.6 已处理）+ `AddExState` + 薄寄存器分发

**门禁**：
- `(Get-Content src/fds.cpp).Count` ≤ 320
- FDS IRQ/block FSM 行为与 v1.9 字节级一致（扩展 Rust 已有单元测试）
- 见 Task 4 的运行测试

### Task 4 — FDS 运行测试 + disksys.rom 处理（D4/D14）

**约束**：`disksys.rom` 为 Nintendo 版权 BIOS，**严禁提交入仓库**。

**做法**：
- 维护者将合法获取的 `disksys.rom` 放置于仓库根的 **`.dr/`** 文件夹（一级目录）
- 在 `.gitignore` 追加（匹配现有 `/discard/` 锚定风格，见 `.gitignore` 行 110-111）：
  ```
  # Copyrighted FDS BIOS for local FDS testing (never commit)
  /.dr/
  ```
- 新增 `tests/core/fds_load_test.cpp`：检测 `.dr/disksys.rom` 存在则跑 FDS ROM 加载 + N 帧 + golden savestate 往返；不存在则 `SKIP`（但记入发布门禁为 BLOCKED）
- 新增 bad ROM 检测对比测试（D14）：用一组已知 bad ROM 头，断言 Rust 路径检测率 ≥ C++ v1.9 路径

**门禁**（严格全量 → 硬门禁）：
- `git check-ignore .dr/disksys.rom` 命中该路径（确认被忽略）
- `git ls-files .dr/` 无输出（disksys.rom 未被追踪）
- `.dr/disksys.rom` 存在时 `fds_load_test` PASS；不存在则**发布 BLOCKED**（不得打 v1.10 tag）
- bad ROM 检测率 ≥ C++ v1.9

## 6. 风险与回滚
