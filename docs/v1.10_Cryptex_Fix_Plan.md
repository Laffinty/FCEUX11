### Task 0.5 — 修补 fc8f7e8 继承的 5 个 ctest 失败

**现状**：Step 0 采纳 fc8f7e8 后 `ctest -LE perf` 有 5 个测试 FAIL（76% 通过率）：

| # | 测试 | 症状 | 类型 |
|---|------|------|------|
| 1 | `savestate_regression_test` | mmc1/mmc3/mmc5/vrc2and4 四组 golden MD5 不匹配 | hash 过期 |
| 2 | `mapper_byte_diff_test` | mapper 逐字节对比偏离基线 | hash 过期 |
| 3 | `golden_savestate_test` | mmc3_smb3_map/level/sprite 等 4/9 失败 | hash 过期 |
| 4 | `mapper_core_test` | 所有断言 PASS 后在 `test_mapper_savegame` 的 `currCartInfo->SaveGame.size()` 访问时 **SEGFAULT** | 内存错误 |
| 5 | `cart_class_test` | `test_nrom_on_power_called` 中 `cart_obj->mapper_number()` 虚函数调用时 **SEGFAULT** | 内存错误 |

#### Task 0.5a — 修复 2 个 SEGFAULT（D15, D16）

**根因分析**：

两个 segfault 的共同特征是崩溃发生在 ROM 加载上建立的 CartInfo / cart_obj 指针链访问时。fc8f7e8 将 iNES 头解析和 ROM 布局计算迁入 Rust（`fceux11_rust_ines_load` / `_parse_header` / `_compute_layout`），改变了 CartInfo 的初始化路径：

- `mapper_core_test` 崩溃于 `currCartInfo->SaveGame.size()`。`SaveGame` 是 `std::vector`——若 `currCartInfo` 在上一轮 `CloseGame` → `LoadGame` 周期中被部分释放或 Rust 侧清零了 C++ 期望的字段，vector 的 `size()` 读取即触发 segfault。
- `cart_class_test` 崩溃于 `currCartInfo->cart_obj->mapper_number()`。`cart_obj` 是 `fceu11::Cart*` 虚基类指针——若 iNES Rust 加载路径中 cart_obj 的构造时机或 vtable 初始化顺序与 C++ 侧不一致，虚函数调用即崩溃。

**做法**：
1. 在 `src/ines_load.cpp` 中审计 `fceux11_rust_ines_load` 返回后到 `currCartInfo` 完成初始化的全链路，定位 Rust FFI 返回值和 C++ 侧 `CartInfo` 字段之间的所有权/生命周期不一致
2. 在 `src/ines.cpp` 中审计 `fceux11_rust_ines_parse_header` / `_compute_layout` 的返回值检查——若 Rust 返回失败（`false`），C++ 是否仍然继续使用未初始化的 `FceuInesParseResult` / `FceuInesLayout`
3. 在 `tests/core/test_helpers.h` 的 `core_shutdown()` / `load_rom()` 中增加 `currCartInfo` 完整性断言（非空 + `cart_obj` 非空校验），缩小崩溃定位范围
4. 修复后重新运行 `mapper_core_test` 和 `cart_class_test` 至 PASS

**门禁**：
- `mapper_core_test` 和 `cart_class_test` 单独 PASS（不再是 SEGFAULT）
- 修复后的 `ctest -LE perf` 全量回归，通过数记为 N₀.₅

#### Task 0.5b — 更新 3 个 golden hash（D17, D18, D19）

**根因分析**：

fc8f7e8 的 Rust iNES 迁移改变了 savestate 格式，因为：
