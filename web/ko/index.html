소개

개요

FCEUX11 은 FCEUX NES/Famicom 에뮬레이터에서 파생된 프로젝트로, Windows 용으로 깊이 최적화되었습니다.

FCEUX 의 뛰어난 에뮬레이션 정확도를 계승하면서 Qt 6 GUI 로 현대적인 Windows 네이티브 경험을 새롭게 다듬으며, 12 개 언어 다국어 지원과 함께 개발자와 스피드러너를 위한 디버깅·TAS 도구 세트를 기본 탑재합니다.

내부 코어 리팩터링과 성능 최적화를 지속적으로 추진하여, 높은 부하 상황에서도 효율적이고 부드러우며 안정적인 동작을 유지합니다.

실험적 Game Boy Advance (GBA) 에뮬레이션이 추가되었으며, 기존 UI·저장 시스템·단축키·디버깅 인프라를 그대로 활용합니다. GBA 기능은 Beta 단계로 화면에 워터마크가 있으며, 일부 하드웨어 기능은 아직 완전히 구현되지 않았습니다.

새 기능

v2.0.5

2026-11-18 배포 · 호환성 대수술: 더 많은 카트리지가 제대로 동작하고, 로딩과 녹화 복구가 정상화
01

mapper 번호 75개에서 보드 레벨 초기화가 복구되고, MMC3 계열 18개 변종도 함께 연결

이 번호들은 전원 투입 시 초기화가 범용 포워더에 무조건 덮여, 보드 고유의 Power 루틴이 한 번도 실행되지 않았습니다(카트리지가 빈 하드웨어로 초기화된 상태였습니다). 이제 "레지스트리에 맞을 때만 포워더를 거치고, 맞지 않으면 보드 초기화를 그대로 두는" 방식(UNIF 경로와 동일)으로 바꾸고 75개 전부를 개별 고정했습니다. MMC3 계열은 별도로 18개 변종이 각자의 전원 투입 함수에 다시 연결되었습니다.

02

mapper 471(Impact Soft IM1) 추가

업스트림 2.8.0에서 추가된 보드로, mapper 201에 스캔라인 IRQ를 더한 것과 같고 쓰기 주소가 곧 전환값입니다. 보정 표와 레지스트리 두 경로에 등록하고 동작 고정 테스트 4개를 붙였습니다. iNES mapper 451과 413은 이번 버전에 포함되지 않았습니다.

03

보드 레벨 의미 수정: Namco 340 미러링, bandai의 I2C, mapper 72 쓰기 윈도

mapper 210의 N340 미러링 표에는 다른 항목과 값이 겹치는 자리(사실상 깨진 표)가 있어 NESdev 표대로 고쳤고, 저장 상태를 읽은 뒤에도 미러링이 상태를 따라 복원되도록 했습니다. bandai의 x24c02는 이 보드가 아닌 장치 주소에 올바로 NAK를 돌려주어, 뒤따르는 데이터 비트를 잘못 ACK로 삼키지 않습니다. mapper 72의 쓰기 윈도는 $8000으로 좁혀 $6000-$7FFF로 새어 들어온 쓰기가 뱅크를 다시 바꾸지 않게 했고, mapper 4의 WRAM은 항상 8 KB(칩의 실제 용량 기준, NES 2.0 헤더 선언에 따라 조정하지 않음)로 두었습니다.

04

ROM 보정 표에 22건 추가, 잘못 분류된 카트리지는 mapper를 직접 고칠 필요가 없어짐

업스트림 보정 표에는 mapper 필드가 C 표현식으로 적힌 행이 22줄 있었는데, 예전 추출기가 해석하지 못해 행 전체가 버려졌습니다. 그 결과 이 카트리지들은 보정을 받지 못하고 헤더의 잘못된 mapper로 로딩되었습니다. 평가 가능한 표현식을 지원하는 추출기로 표 전체를 다시 생성하고(유효 행 256 → 278), 오래된 항목 2건도 바로잡았습니다.

05

사용성 결함 일괄 수정: 정상 카트리지 오판, 명령행 로딩, 멈춤, 빈 녹화

정상이지만 CHR 수가 2의 거듭제곱이 아닌 iNES 카트리지가 더 이상 알 수 없는 형식으로 판정되지 않습니다. 명령행에서 한글 이름 ROM을 불러오는 문제와 --no-console과 함께 쓸 때 조용히 무시되던 문제도 고쳤습니다. ROM을 닫은 직후 다시 열어도 창이 멈추지 않고, 사운드 장치가 없을 때 매 프레임 약 1초씩 도는 현상도 사라졌습니다. 로딩 시간은 8~10초에서 0.3초로 줄었고, 이전에는 전부 0이던 .fm2 녹화도 이제 정상 재생됩니다.
