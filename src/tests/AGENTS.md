# FCEUX11 Test Suite — Agent Guide

## Overview

This directory contains the **headless regression test suite** for FCEUX11 core emulation behavior. It runs **without Qt GUI initialization**, enabling fast CI validation of mapper loading, NES power-on/reset sequences, and core symbol integrity.

### Test Targets

| Target | Source | What it validates |
|--------|--------|-------------------|
| `fceux11_smoke_test` | `smoke_test.cpp` | 24 core symbols resolve; `FCEUI_Initialize()` / `FCEUI_Kill()` succeed |
| `fceux11_mapper_load_test` | `boards/mapper_load_test.cpp` | 8 representative mappers load without crash; `gi->mappernum` matches expected value |
| `fceux11_mapper_reset_test` | `boards/mapper_reset_test.cpp` | Same 8 mappers survive `FCEUI_ResetNES()` after load |

All targets are registered with CTest and runnable via:

```powershell
# From Developer PowerShell for VS 2022
cd build
ctest --output-on-failure
```

> **Platform note**: Tests are statically linked and do not require DLLs in PATH. Run via `ctest` from the build directory.

## Architecture

### Library Linking Strategy

Test executables link against the same static libraries used by the main emulator:

```
fceux11_drivers_qt
fceux11_drivers_common
fceux11_core
fceux11_boards
fceux11_utils
```

Because `main.cpp` is compiled into the main executable (not the static libraries), test targets provide their own `main()` without conflicts.

### `git_info_stub.cpp`

The Qt driver library expects `fceu_get_git_url()` and `fceu_get_git_rev()`. These are normally generated by `genGitHdr.bat` for the main executable only. Every test target must include `git_info_stub.cpp` to satisfy this dependency.

## Headless Mode — Known Traps

The Qt driver contains many globals that are initialized only when the full GUI starts (`consoleWindow`, `g_config`, `msgLog`, etc.). When running headless, these globals are `NULL` or uninitialized. **The following crashes have already been encountered and fixed:**

### Trap 1: `g_config` NULL dereference in `FCEUD_VideoChanged()`

**Location**: `src/drivers/Qt/sdl-video.cpp`  
**Trigger**: Loading any iNES ROM → `iNESLoad()` → `FCEUI_SetVidSystem()` → `FCEUD_VideoChanged()`  
**Root cause**: `g_config` is `NULL` because `InitConfig()` was never called (no QApplication).  
**Fix**: Add null guard:

```cpp
void FCEUD_VideoChanged(void) {
    int buf;
    if (g_config)
        g_config->getOption("SDL.PAL", &buf);
    else
        buf = 0;
    // ...
}
```

### What to watch for when adding new tests

Any code path that calls into the Qt driver layer (`FCEUD_*` functions) is suspect. Common danger zones:

- `FCEUD_Message` / `FCEUD_PrintError` — may write to NULL GUI handles
- `FCEUD_SetPalette` — currently safe (`s_psdl` is a static array)
- Any function accessing `g_config`, `consoleWindow`, `msgLog`, `videoDriver`
- Debugger hooks guarded by `#ifdef __WIN_DRIVER__` — these are skipped in Qt builds, but Qt-specific hooks may still fire

**Rule of thumb**: If a test crashes after ROM load but before your assertion, instrument the code with `printf + fflush(stdout)` to locate the exact `FCEUD_*` call, then add a null guard in the Qt driver.

## Test Fixtures

### Minimal ROM Generation

Test ROMs are **synthetic iNES files** (16-byte header + minimal PRG/CHR data). They are not real games; they exist only to exercise mapper initialization code paths.

**Generator**: `fixtures/generate_test_roms.py`

To regenerate or extend fixtures:

```powershell
cd src/tests
python fixtures/generate_test_roms.py
```

### Adding a New Mapper Test

1. **Add fixture generation** in `generate_test_roms.py`:
   ```python
   make_nes("mapper_newmapper.nes", mapper=123, prg_banks=1, chr_banks=0)
   ```
2. **Regenerate fixtures**: `python fixtures/generate_test_roms.py`
3. **Add test case** in `boards/mapper_load_test.cpp`:
   ```cpp
   { "fixtures/mapper_newmapper.nes", 123 },
   ```
4. **Add matching case** in `boards/mapper_reset_test.cpp`
5. **Rebuild & run**:
   ```powershell
   cd build
   cmake --build . --target fceux11_mapper_load_test fceux11_mapper_reset_test
   ctest --output-on-failure
   ```

## Adding a New Test Executable

When creating a brand-new test target (e.g., `ppu_render_test`), copy the pattern from `src/tests/CMakeLists.txt`:

```cmake
add_executable(fceux11_ppu_render_test
    ppu/render_test.cpp
    git_info_stub.cpp          # REQUIRED
)

target_link_libraries(fceux11_ppu_render_test PRIVATE
    fceux11_drivers_qt
    fceux11_drivers_common
    fceux11_core
    fceux11_boards
    fceux11_utils
)
# ... Rust logic same as existing targets ...

add_test(NAME ppu_render_test COMMAND fceux11_ppu_render_test)
```

> Always include `git_info_stub.cpp`. Without it, linking will fail with unresolved `fceu_get_git_url` / `fceu_get_git_rev`.

## Working Directory

`mapper_load_test` and `mapper_reset_test` expect to find the `fixtures/` subdirectory **relative to the current working directory**.

- **Correct**: Run via `ctest` from `build/` (CMake sets CWD automatically)
- **Correct**: Run `.exe` directly from `build/src/tests/`
- **Incorrect**: Run `.exe` from project root or elsewhere — it will fail to find fixtures

## Troubleshooting

| Symptom | Likely Cause | Fix |
|---------|-------------|-----|
| `EXIT CODE: -1073741819` (0xC0000005) after ROM load | NULL `g_config` or similar Qt global in headless mode | Add null guard in Qt driver; see "Known Traps" above |
| `Cannot find fixtures/mapper_*.nes` | Wrong working directory | Run from `build/src/tests/` or use `ctest` |
| Link error: undefined `fceu_get_git_rev` | Missing `git_info_stub.cpp` | Add to test source list |
| Link error: multiple definition of `main` | `main.cpp` linked into static lib | Ensure `main.cpp` is only in the executable target, not in `fceux11_drivers_qt` |
